# Hardware run 2026-11-18: Mac ↔ PC over the Thunderbolt 4 cable

Manual run of the T-123 checks without ssh to the Mac (ssh to the Mac is disabled by the company's SOC2 policy). Each side ran its half from a local Claude Code session, with test agents provisioned by `tandem-hw provision` in temporary folders, all at commit `d0489cc`. Both sides were cleaned up afterwards.

- PC: Windows 11, "USB4(TM) P2P Network Adapter" up, link-local 169.254.252.182.
- Mac: MacBook Pro (Apple Silicon), Thunderbolt Bridge `bridge0`, link-local 169.254.93.252. Firewall on, stealth mode on.
- Peers configured with each other's cable link-local IPv4 address, port 47871.

## Findings

1. **The cable is never recognized as USB4** (T-196). The configured peer address is labelled `Wifi`, so the Wi-Fi QoS cap applies. On Windows, the USB4 P2P adapter is detected as `Ethernet`. The IPv6 link-local candidate on the cable fails on every attempt with `InvalidRemoteAddress([fe80::…%13]:47871)`: the scope id appears to be the peer's interface index instead of the local one.
2. **Workspace tunnels fail with a relative data directory** (T-197). Git runs with `scratch/repo` as its working directory but gets `agent/data/workspaces/…` as a relative path (`git bundle create` on the Mac, `git fetch` on the PC).
3. **Input needs the Mac's Accessibility and Input Monitoring permissions.** Not a code bug; to be repeated in person.
4. **The hardware suite needs ssh to the Mac** (T-198). With ssh disabled, the Mac half had to be run by hand.

## Follow-up: one-way reachability (T-237)

With the Mac's firewall in stealth mode, only the Mac could dial. Every check the Mac ran passed, but the PC agent never considered the Mac connected: it only used connections its own link manager dialed, and the Mac did not serve streams opened over its own connection. T-237 makes each side adopt the connection the other agent opened when it cannot dial, and stops rebuilding the link manager on mDNS changes that leave the same links, the likely source of the repeated `closed by peer: 0` in the PC log.
