# Windows installer

Tandem is installed on the PC with an NSIS installer built by Tauri's bundler
(`Tandem_<version>_x64-setup.exe`). It carries the app, the `tandemd.exe` agent and
its console-less launcher `tandemw.exe`, and leaves the agent starting with the user's session.

## Install

1. Download the `tandem-windows-installer` artifact from CI (job `installer (windows)`) or
   build it (see below).
2. Run `Tandem_<version>_x64-setup.exe`. It does not ask for administrator: it installs for the
   current user in `%LOCALAPPDATA%\Tandem`. **For Claude to be able to run things as
   administrator on this PC** (D8, A7), run it with *Run as administrator* (or from
   an elevated terminal): the agent is then registered with the highest privileges (see
   "Tunnel privileges").
3. When it finishes, `tandemd` is already running; there is no need to sign out.

Unattended install: `Tandem_<version>_x64-setup.exe /S`.

What the installer leaves:

| What | Where |
|---|---|
| Program (the app, `tandemd.exe`, `tandemw.exe`, `uninstall.exe`) | `%LOCALAPPDATA%\Tandem` |
| Configuration (`tandem.toml`, generated by the agent at startup) | `%APPDATA%\Tandem\tandem.toml` |
| Agent state and logs | `%APPDATA%\Tandem` (`state.json`, `logs\`) |
| Start with the session | With administrator, the scheduled task `Tandem\tandemd` (highest privileges); without it, `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, value `tandemd` |
| Shortcuts | Start menu (and desktop in the unattended install) |

### Automatic configuration

The installer carries no configuration. The first time it starts, `tandemd` creates
`%APPDATA%\Tandem\tandem.toml` with what it sees (`tandemd::autoconfig`, T-082), just like on the
Mac:

- `machine = "pc"`;
- the empty desk: no `[[screens]]`, the input engine uses the monitors of Windows's
  virtual desktop to move the cursor and the Mac goes to the left (DESIGN §7);
- network, input and power with their default values, with no sample data.

Tandem does not control monitors (DESIGN §8). Reinstalling or updating **never** touches an existing
`tandem.toml`. It can be edited (format in `docs/examples/tandem.pc.toml`): screens
are declared with `[[screens]]` and the Mac's side with `[arrangement]`. A v0.1
`[[monitors]]` section is ignored with a warning in the log. To validate one edited by hand:

```
"%LOCALAPPDATA%\Tandem\tandemd.exe" --check-config "%APPDATA%\Tandem\tandem.toml"
```

### Port

The default port is UDP **52000**. On PCs with WSL or Hyper-V, Windows reserves port ranges
(on the real desk, 47000–48999: the earlier 47770 failed with `os error 10048`). If
the configured port cannot be opened, the agent tries others (52000, 52100, 53100, 54200,
55300, 56400, 45500, 44600) and announces the real one over mDNS, so the Mac finds it anyway; the pairing one
is the one after whichever was chosen. If none opens, the log error says which ones it
tried and how to fix it. The reserved ranges can be seen with:

```
netsh interface ipv4 show excludedportrange protocol=udp
```

## Automatic start

When it finishes copying, the installer runs `tandemd --install`, which registers the start
with the session and starts the agent (which generates the configuration if there is none). What it registers
depends on whether the installer has administrator:

- **With administrator and the program at an administrators-only path** (for example
  `%ProgramFiles%\Tandem`): the scheduled task `Tandem\tandemd`, with a trigger "at user
  logon" and `RunLevel = HighestAvailable` (the highest privileges, with no UAC
  prompt on each start). It is defined with an XML, not with the options of
  `schtasks /Create`, and registered through the Task Scheduler COM API, with no
  intermediate files, so as not to inherit Task Scheduler's default values
  (stop the task after 3 days and not start on battery); the task has no time
  limit. With the task registered, the `Run` value is removed, so as not to start two copies.
  Before registering it, the ACL of the executable and its folder is read: if `Users`,
  `Authenticated Users`, `Everyone` or the user can write there, it is not registered (otherwise
  any user process would change the `.exe` and run it elevated without UAC).
- **Without administrator, or with the program at a user-writable path** (the
  per-user install in `%LOCALAPPDATA%\Tandem`): the `HKCU` `Run` key, value
  `tandemd` = `"…\Tandem\tandemw.exe"`, and a warning in the log and on the console. The agent runs
  unelevated and so does whatever is launched in a tunnel.

To go from one to the other, run `tandemd --install` (or the installer) again as
administrator. Uninstalling removes both; removing the task also requires administrator (if the
uninstaller does not have it, it warns and leaves the task: delete it with `schtasks /Delete /F /TN
Tandem\tandemd` from an elevated terminal).

`tandemw.exe` is a graphical-subsystem launcher that starts `tandemd.exe` with
`CREATE_NO_WINDOW`: `tandemd` is a console application (its CLI writes to the terminal) and
launched directly from `Run` it would open a black window at every sign-in. Arguments
pass through as they are and the exit code is `tandemd`'s; errors go to the log in
`%APPDATA%\Tandem\logs`.

The `Run` key stays as an alternative because it does not ask for administrator, only affects the user
who installs and is what Windows shows in *Task Manager → Startup apps*,
where it can be disabled.

The SYSTEM service for the secure desktop (UAC prompts, lock screen, Ctrl+Alt+Del; T-027) is
installed by the app's setup with one UAC prompt (`tandemd --install --with-service`) or by
hand with `tandemd --install-service`; see `docs/dev/secure-desktop.md`. An elevated
`tandemd --install` (the installer run as administrator) also refreshes an installed service,
and an elevated `tandemd --uninstall` removes it.

### Tunnel privileges

What is launched in a tunnel (`exec`, T-104) runs with the agent's privileges (A7): nothing
in Tandem raises or lowers them. If the agent started from the task above, the processes
are administrator ones (`net session` answers without an access error); if it started from `Run`,
they are the user's. An elevated process is an assumed risk (D8): it only gets in through the user's
local IPC and the authenticated link (DESIGN §11).

When updating with an elevated agent, the installer (without administrator) may fail to
stop it and the `.exe` files stay locked: run the update as
administrator too.

To register or remove it by hand:

```
tandemd --install     # idempotent; accepts --config / --data-dir and passes them to the Run command
tandemd --uninstall   # removes the Run value; leaves the configuration
```

On macOS these commands do not exist: there the start is a LaunchAgent installed by the app (T-070).

## Uninstall

From *Settings → Apps → Tandem → Uninstall* (or `uninstall.exe`, `/S` for
unattended). The uninstaller:

1. stops the user's `tandemw.exe` and `tandemd.exe`;
2. runs `tandemd --uninstall` (removes the `tandemd` value from `Run`);
3. deletes the binaries, the shortcuts and the *Apps* entry.

Configuration, state and logs (`%APPDATA%\Tandem`) are kept, unless you tick the
*Delete application data* box in the uninstaller. Careful: the agent's
identity and its trust file (`trust.toml`, the pairing) also live there. Keeping them
keeps the pairing, which is why the box says "leave unticked to keep the pairing"
(`windows/English.nsh` and `windows/Spanish.nsh` override Tauri's `deleteAppData` string; they are copies of the
bundler's language files for the version `@tauri-apps/cli` pins, so refresh them when it is upgraded). If you
reinstall with the data kept and the other machine was reset, Tandem offers to forget the old pair
(T-345). Deleting them forces pairing again.

On an update (installing one version over another) the installer stops the agent
before copying, replaces the binaries, registers the start again and starts it again.

## Building the installer

On Windows, with Rust (MSVC), Node 22 and pnpm:

```
cd apps\tandem-ui
pnpm install --frozen-lockfile
cd ..\..
pwsh tools\windows\installer\build-installer.ps1
```

The script compiles `tandemd` and `tandemw` in release, copies them as sidecars to
`apps/tandem-ui/src-tauri/binaries/` (with the target triple in the name, as Tauri asks)
and runs `pnpm tauri build --features app --config src-tauri/windows/installer.conf.json`. The
installer is left in `target\release\bundle\nsis\`. Tauri downloads NSIS the first time.

Pieces:

- `apps/tandem-ui/src-tauri/windows/installer.conf.json`: NSIS target, sidecars, `currentUser`
  mode, installer language. It is kept apart from `tauri.conf.json` so that the UI's normal `cargo build`
  does not require the sidecars.
- `apps/tandem-ui/src-tauri/windows/hooks.nsh`: the install and uninstall hooks.
- `crates/tandemd/src/install/`: `--install` / `--uninstall` (the logic is tested with a registry
  double; the real registry, in the Windows CI).
- `tools/windows/installer/test-installer.ps1`: end-to-end test that CI runs.

### CI test

The `installer (windows)` job builds the installer, uploads it as the artifact
`tandem-windows-installer` and runs `test-installer.ps1`: it installs silently, checks the
files, the `Run` value, that `tandemd` is running and that it generated a valid PC
config (the installer carries none);
reinstalls over it and checks that the user's config did not change; uninstalls and checks that
the agent stopped, that the `Run` value and the binaries disappeared and that the config was
kept. **Do not run it on the daily-use PC**: it really installs and uninstalls.

## Authenticode signing

By default the installer is **not signed** and Windows SmartScreen warns about an unknown
publisher the first time ("More info → Run anyway"). Signing is the user's
decision (it costs a code-signing certificate); the script enables it with environment
variables, and Tauri then signs the binaries, the sidecars and the installer:

| Variable | Use |
|---|---|
| `TANDEM_WINDOWS_CERT_THUMBPRINT` | SHA-1 thumbprint of a certificate installed in the user's store (`Cert:\CurrentUser\My`). Signs with `signtool`, SHA-256. |
| `TANDEM_WINDOWS_TIMESTAMP_URL` | Timestamp server. By default `http://timestamp.digicert.com`. |
| `TANDEM_WINDOWS_SIGN_COMMAND` | Own signing command, with `%1` in place of the file (for example, Azure Trusted Signing or an HSM token). If present, it wins over the thumbprint. |

Examples:

```
$env:TANDEM_WINDOWS_CERT_THUMBPRINT = 'A1B2…'
pwsh tools\windows\installer\build-installer.ps1

$env:TANDEM_WINDOWS_SIGN_COMMAND = 'trusted-signing-cli -e https://eus.codesigning.azure.net -a account -c profile %1'
pwsh tools\windows\installer\build-installer.ps1
```

In CI it would be signed by storing the certificate in a repository secret, importing it into the
runner's store before the build and passing the thumbprint; it is not enabled because there is no
certificate. What signing means for T-027's SYSTEM service (which binaries, why antivirus and
WDAC care, when UIAccess would make it mandatory) is in `docs/dev/secure-desktop.md`.
