# T-352 — One UI per machine

## Context

From the review of T-350 (#212): `tandemd` now launches `tandem-ui` when Tandem is opened while
only the agent runs, and it remembers a launch in flight. But a freshly restarted agent does not
know about a UI that is still running and has not reconnected yet, so an open request in those
seconds launches a second UI (a second tray icon and window, each running its own LaunchAgent
install). `apps/tandem-ui/src-tauri` has no single-instance guard; `open -n` (the workaround
used on 2026-11-20) can also start duplicates.

## Goal

A second `tandem-ui` on the same machine and user hands over to the running one (which shows its
main window) and exits, on macOS and Windows.

## Approach

- A single-instance guard in the UI (Tauri's single-instance plugin or an equivalent lock on the
  agent's data dir), with the second instance asking the first to show its window.
- Portable decision tested on Linux; platform code behind a trait with a test double.

## Acceptance criteria

- [ ] Starting a second UI shows the first one's window and the second exits; tests.
- [ ] Quality gate and CI green on the three platforms.
