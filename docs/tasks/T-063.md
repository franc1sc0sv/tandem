# T-063 — Reconcile pc_on with the links (power cut)

## Scope

Today, if the PC loses power, the Mac agent stays with `pc_on = true` and no plan includes `PowerOnPc` again; the 34" on DisplayPort stays black until the PC is turned on by hand (QA round 2 observation, PR #31).
Reconcile `pc_on` with the link manager's state: if all links to the PC are down for longer than a configurable threshold and no `PowerOffPc` was in progress, mark the PC as off, return the monitors to the Mac by the safe path (those the Mac can recover) and notify the UI.

## Acceptance criteria

- [x] Scenario in tandem-sim: power cut in Shared → after the threshold the Mac recovers what it can, `pc_on = false` and the next switch to Shared includes `PowerOnPc`.
- [x] A brief link drop (shorter than the threshold) does not change `pc_on`.
- [x] UI event with the reason.

## Notes

- `tandemd::pc_watch::watch(agent, reachable)`: Mac only. `reachable` is whether any link sees the PC agent (in `tandem-sim`, the link manager's active link). If it does not see it for `power.pc_lost_after_secs` (15 s by default, configurable in `[power]`, 0 is rejected) and `pc_on` is still `true`, it takes the orchestrator like any other change (`try_begin`; if busy it retries every 1 s), sets `pc_on = false`, saves and publishes it, notifies the UI with `AgentToUi::Power(PowerEvent::PcLost { reason, stranded })` and recalculates the keyboard and mouse geometry on the Mac only (`Orchestrator::run_here`).
- "What the Mac can recover": today only that. The inputs are switched by the PC (DESIGN §8), so the monitors that were on its input stay on it, black; the state says so (they still belong to the PC with `pc_on = false`) and `stranded` names them for the UI. The built-in screen already follows `builtin_effective`. If a `ddc-macos` ever exists, this is where the Mac would bring them back.
- A power off in progress is not mistaken for a cut: it holds the orchestrator, and when it finishes it leaves `pc_on = false`, so there is nothing to reconcile. If the Mac is lent to a PC transaction, it waits for the loan to expire.
- The other way round: if the PC is seen again (rising edge of the link) with `pc_on = false`, it is assumed to be on (it was turned on by hand, or the Mac started without knowing). A hung power off with the links up has no edge and changes nothing.
- `Plan::to_mode`: with the PC off it is also powered on if any input has to be switched (the PC switches it), not only if it is going to show something; otherwise going back to Mac only after a cut failed with "the other agent is not connected". `Plan::shutdown_pc` powers it off again if it had to power it on for that. The core's property test generates states after a cut and its physical model rejects switching an input with the PC off.
- `tandem-sim`: the Mac runs the watcher; `World::check` accepts a black PC monitor if the state says `pc_on = false`; `Desk::press_pc_power_button` turns the PC on without Wake-on-LAN. Scenarios in `tests/power_cut.rs`.
- Pending for whoever wires the link manager into `main` (out of scope): launch `pc_watch::watch` with the active link's `watch`, as `tandem-sim` does.
