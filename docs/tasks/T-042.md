# T-042 — UI: menu bar, tray and global shortcuts

## Scope

Icon in the menu bar (macOS) and tray (Windows) with a mini scene and the three modes; configurable global shortcuts.

## Acceptance criteria

- [x] Compiles on macos and windows CI; screenshot in the PR.

## Notes

- **Icon** (`tandem_ui::app`, `tauri` with `tray-icon`): monochrome template in the macOS menu bar (the system paints it according to the theme) and the color logo in the Windows tray (`icons/tray-template.png`, `icons/tray.png`). Left click: opens the mini scene next to the icon (below if the bar is at the top, above if it is at the bottom, always inside the usable area: `tray::popover_origin`). Right click: menu with the status («Shared · PC on»), the three modes (the current one checked, disabled without an agent), «Open Tandem» and «Quit Tandem». The tooltip says the mode.
- **Mini scene** (`tray.html`, borderless `tray` window, always on top, out of the taskbar): the two machines with their monitors (click = move it to the other), whether the PC is on, the three modes with their shortcut, the step in progress of the change and «Open Tandem». It closes on losing focus or with Esc.
- **The app lives in the menu bar**: closing the main window hides it; you quit from the icon's menu. On macOS, a click on the Dock shows it again.
- **Global shortcuts** (`tauri-plugin-global-shortcut`): ⌃⌥0 to show or hide the window (the mode ones went away with them: each scene carries its own, `Scene.shortcut`, and the lock its own, `[shortcuts] lock`; all are edited in Settings → Shortcuts, T-129). It is changed from Settings → Shortcuts (the combination is pressed; duplicates and those without Ctrl, Alt or ⌘/Win are rejected) and saved in `ui.toml`, next to `tandem.toml`. Canonical form by physical key code (`Ctrl+Alt+Digit1`), the same in Rust (`tandem_ui::shortcuts`) and in TypeScript, with tests on both sides. A damaged `ui.toml` does not leave you without shortcuts: the usual ones are used and the dialog says why.
- A mode requested by shortcut or by the menu uses the same rule as the cards (`tray::mode_request` = `modeRequest`); if the agent rejects it, the windows show it (event `ui-message`).
- If the system does not let a shortcut be registered (another app uses it, Wayland), the dialog says so and the window handles it itself while it has focus; the registered ones are not handled twice. «Show or hide» handled this way hides the window (`ui_hide_main`): if it receives the key, it is in front.
- When the shortcuts change, `shortcuts_set` notifies the windows (event `ui-shortcuts`): the mini scene, which hides but is not destroyed, shows the new ones without restarting the app.
- The CI `ui` job builds the Tauri app on ubuntu, windows and macos.
- Screenshots (frontend in Chrome with the simulated agent, `pnpm dev` and `/tray.html?demo`; `&keys=busy` simulates a busy shortcut): removed later because they showed the retired Spanish UI; see git history. The real icon in the menu bar and in the tray can only be seen on each machine.
