# T-171 — Editable Wake-on-LAN in the demo

## Context

Finding of the acceptance agent (part A, round 2), rule G6 (each element does something verifiable). In `?demo#/machine/b` the "Wake-on-LAN" field shows `aa:bb:cc:dd:ee:ff`. Another valid MAC is typed (`aa:bb:cc:dd:ee:01`) and "Save" is pressed: the DOM does not change, there is no notice, "Save" stays enabled and on reload `aa:bb:cc:dd:ee:ff` comes back. The "Delete MAC" button (trash icon) does not change anything either. Cause: `DemoSource.setWol` (`apps/tandem-ui/src/lib/store/demo.ts`) validates the MAC and returns `{ ok: true }` without saving it; the rest of the demo's actions (`setDeskName`, `editMachine`) do update the desk.

App screenshot: `docs/reports/acceptance/2026-11-18-a2/machine-wol-no-effect/app.png`. The real effect on the agent belongs to part B; what is missing here is the effect in the demo, which is what the UI and the screenshots test.

## Scope

1. `DemoSource.setWol` saves the MAC (or deletes it with `null`) in the machine's `wake` and publishes the new desk, like `editMachine`.
2. With a saved MAC, "Power on" is enabled and the "MAC missing" notice (`WOL_MISSING`) disappears; without a MAC, the opposite. "Save" goes back to being disabled when it matches what is saved.
3. Tests (vitest): save, delete, invalid MAC (visible error message) and that "Power on" follows the MAC.

## Acceptance criteria

- [x] In the demo, saving a valid MAC changes the saved field and the state of "Power on"; deleting removes it; an invalid one shows the reason.
- [x] `machine-a` and `machine-b` stay at ≥ 0.99 / ≥ 0.97.
- [x] Quality gate and CI green.
