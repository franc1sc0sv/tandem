# T-359 — The PC's right Shift reaches the Mac

## Context

Reported on 2026-11-26: typing on the Mac with the PC's keyboard, "one Shift does not work, some things do and others do not". Both machines use the U.S. layout (Windows `0409`, macOS "U.S." on an ANSI keyboard), so characters map one to one; the missing key was the right Shift.

`WH_KEYBOARD_LL` reports the real right Shift as scancode `0x36` with `LLKHF_EXTENDED` set (also seen by AutoHotkey and Wine). The Windows capture treated every `E0 36` as the fake Shift Windows adds around the navigation keys with NumLock on, so it dropped every press and release of the real key.

## Scope

- `key_event`: scancode `0x36` is right Shift with or without the extended flag. `E0 2A` (fake left Shift; the real one is never extended) is still dropped.
- `FakeShiftFilter`, before `AltGrFilter` in the `Translator`: an extended right Shift within the window (10 ms, the AltGr one) of a navigation key's `time` (Insert, Delete, Home, End, Page Up, Page Down, the arrows, keypad `/`) is the fake pair and is dropped; any other one passes. A right Shift is held until the next event or the window passes, so the leading fake one (`E0 B6` before the arrow) is caught too.

## Acceptance criteria

- [x] Test: an extended right Shift maps to HID `0xE5`.
- [x] Test: a right Shift held across an arrow with NumLock reaches the other machine once down and once up; the fake pair around the arrow is dropped.
- [x] Test: a held right Shift goes out when the window expires.
- [x] Property test: with no navigation keys, nothing is dropped or reordered.
- [x] Pipeline test: the `Translator` passes an extended right Shift.
- [x] Quality gate and CI green.

## Pending hardware verification

- [ ] With the PC's keyboard on the Mac: right Shift + letters gives capitals; right Shift + arrow selects text with NumLock on and off.
- [ ] Left Shift and both Shifts at once still work; Shift + arrow on the PC itself is unchanged.
