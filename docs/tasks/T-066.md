# T-066 — Roles with the hub on a powered-off PC

## Scope

If the PC powers off with the hub connected and then the hub moves to the Mac, the arbiter stays with the PC as server until the PC comes back; the keyboard works on the Mac but the UI chip shows it wrong (QA round 2 observation).
When the PC is considered off (`pc_on = false`, see T-063), the arbiter decides only with what the Mac sees.

## Acceptance criteria

- [x] Scenario in tandem-sim: the PC powers off with the hub, the hub moves to the Mac → the Mac is the server and the UI reflects it.
- [x] When the PC comes back, the roles converge as they do today.

## Notes

- `RoleArbiter::set_peer_off()` (`tandem-peripherals`): the other agent is taken as off and counts as not having the hub (a powered-off machine sees no USB). With that the Mac decides alone: if the hub is on it, it is the server. It is removed by the other agent's next report or by `set_peer(None)`. The Mac calls it when its `State` says `pc_on = false` (T-063); since the watcher only runs on the Mac, the PC never uses it.
- Convergence on return: while it was off, the PC did not find out and starts with the server it had saved. If on return the hub decides (it is on a single machine), they converge as usual. For the tie (hub on neither or on both), the report to the other agent now also carries its server (`PeerReport { hub, server }`, `RoleArbiter::report()` / `set_peer`): on the PC the Mac's server wins, since it is the one that stayed on; the Mac keeps its own. `set_peer_hub` (hub only, no server) keeps its previous behavior.
- The same covers a false power off (links down for longer than `pc_lost_after_secs` with the PC on): the Mac only stays as server if the hub is on it, and when the link returns they converge.
- Tests: arbiter unit tests and the property test `roles_converge_after_the_pc_is_off` (power offs, false power offs, link drops and the PC starting with any saved server: when connected they always agree; with the PC taken as off and the hub on the Mac, the Mac is the server). Without the tie going to the Mac the property fails. In `tandem-sim` (`tests/hub.rs`): `the_pc_shuts_down_with_the_hub` (power cut with the hub on the PC, the hub moves to the Mac, past the threshold the Mac is the server; when the PC returns it becomes a client and moving the hub swaps the roles as before) and the end of `move_the_hub_with_the_whole_desk`, which used to document the old behavior (the Mac stayed with the PC as server until the PC returned).
- "The UI reflects it": the UI chip does not yet receive the agent's role (`main.ts` shows it as "no data"; the arbiter is wired into `tandemd` with T-074). The scenario checks the value that each machine's chip would show (`Roles::chip`, its arbiter's `role()`). Whoever wires it in T-074 must call `set_peer_off()` with `pc_on = false` on the Mac and send `report()` over the control plane.
