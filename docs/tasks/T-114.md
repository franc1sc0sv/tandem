# T-114 — Tunnels screen (read-only)

## Context

DESIGN §12. Reference mockups (visual and interactive source of truth): `V3-Compute`, `F-ClaudeMCP`. The screen must look and behave the same as the mockup: same structure, sizes, colors, icons, texts, animations and transitions; everything interactive in the mockup really works against the agent.

## Scope

1. Grouped, collapsible projects (header with folder icon and the proportion of active tunnels "1/2").
2. Tunnel: Claude session title, branch chip, mini origin→destination path; detail with the animated tube, statistics and process panel: on the left only those that are **running** (list with scroll and fixed header, handles many processes), on the right the live output of the selected one.
3. Empty states "Nothing running now" / "Tunnel closed". No stop buttons (D9).
4. Tunnel counter in the sidebar.

## Acceptance criteria

- [x] Similarity ≥ 0.99 against each listed mockup and state, in the screenshot harness (T-112/T-125), with the screenshots saved in `docs/screenshots/v03/`.
- [x] Everything that is interactive in the mockup works connected to the agent (real IPC) and in demo mode; vitest tests of the logic and of the interactions.
- [x] Mockup animations and transitions present; with `prefers-reduced-motion` they are turned off (test).
- [x] No filler texts or elements without a function (DESIGN §3.8).
- [x] `pnpm test`, `pnpm build`, `pnpm check` and CI green.

## Notes

- Data: `GetTunnels`/`AgentToUi::Tunnels` arrive through the `agent-tunnels` event (on connect and on every change), `GetProcesses` and `Output` through the `processes`/`output` actions (the screen polls every 1.5 s, and every 1 s while the tunnel is selected) and `Transfer` through `agent-transfer`. Tunnel ids travel as text (16 hex): they do not fit in a JavaScript number.
- Tunnel branch (T-107, PR #100): `TunnelView.branch` is ready and the UI does not draw the chip while it is `null`; once the event exists, only filling it in `tunnelsFromWire` is left.
- Figures the agent does not give yet: "Ports" is not shown (there is no list of forwarded ports in the IPC) and "Commands" counts the processes the screen sees. The tube arrows add up the bytes of the file copies seen since the window was opened.
- Closed tunnels do not come from the agent (`view()` only brings the open ones): the window remembers the last 10 it saw and marks them "closed".
- "How Claude opens them" (the mockup links it to `F-ClaudeMCP`, which is not an app screen) copies the `tandem mcp` command.
- On the Tunnels screen the sidebar counter becomes a live dot, as in `V3-Compute`.
- `shots.ts` moves the pointer to (0, 0) after clicks, like the mockup renderer, so the `:hover` of the last button does not change the screenshot.
- Similarity (screen / worst tile, `docs/screenshots/v03/similitud.json`): the seven mockup states give 100 % / 100 %. Empty and 12 processes have no mockup: they are captured without a threshold.
