# T-333 — The agent does not terminate on a Quit Apple event

## Context

Found on a real Mac with v0.3.0 (unified log). Changing Accessibility or Input Monitoring in System Settings and choosing "Quit & Reopen" killed the agent:

```
22:18:03.364 tccd Publishing TCCDEvent type=Modify service=kTCCServiceListenEvent identifier=com.franc1sc0sv.tandem
22:18:04.207 tandemd[90776] [com.apple.AppKit:Application] Handling Quit AppleEvent
22:18:04.207 tandemd[90776] Asking app delegate whether applicationShouldTerminate: / replyToApplicationShouldTerminate:YES / App termination approved / terminate:
22:18:04.208 tandemd[90776] Termination complete. Exiting without sudden termination.
launchd: termination reported (0, 0, 0)
```

The same happened at 22:11:29 (pid 77897).

## Failure

`tandem-files::drag_macos::run_app_loop` (T-121) runs `NSApplication.run` with the `Accessory` policy on the agent's main thread (`crates/tandemd/src/main.rs`, `run_hosted`). Because `tandemd` lives in `Tandem.app/Contents/MacOS`, LaunchServices registers it as part of the app `com.franc1sc0sv.tandem`, and "Quit & Reopen" sends the Quit Apple event to every process of the app. With no delegate, AppKit approves and calls `exit(0)`:

- `daemon.serve` / `shutdown_signal` are skipped: no "shutting down" line, the state is not saved;
- the exit code is 0, and the LaunchAgent (`KeepAlive` with `SuccessfulExit = false`) does not restart it.

## Expected fix

- The agent is supervised by launchd and stops with SIGTERM / `bootout`. An `NSApplication` delegate answers `applicationShouldTerminate:` with `NSTerminateCancel` and logs a warning ("ignoring Quit AppleEvent (tandemd is stopped by launchd)").
- The decision is portable and tested; the AppKit part is minimal.

## Acceptance criteria

- [x] Portable decision `tandem_files::app_quit::decide` with unit and property tests, written to fail first.
- [x] `run_app_loop` installs a delegate (`TandemAgentAppDelegate`) that ignores a plain Quit Apple event with a `warn`, and lets the end of the session through so a logout, restart or shutdown is never blocked.
- [x] A `docs/DECISIONS.md` line.
- [x] Quality gate and CI green.

## Notes

- Failing first: with `decide` returning AppKit's old answer (always terminate), 5 of the 7 `app_quit` tests failed (`a_plain_quit_apple_event_is_ignored`, `terminate_without_an_apple_event_is_ignored`, `the_end_of_the_session_is_allowed`, `a_session_reason_on_another_event_is_ignored`, `only_session_reasons_let_the_agent_quit`).
- Why the end of the session is let through: loginwindow sends the same Quit Apple event with a `kAEQuitReason` (`'logo'`, `'rlgo'`, `'rrst'`, `'rest'`, `'rsdn'`, `'shut'`). Cancelling it would make the agent block the logout, restart or shutdown. In that case AppKit still ends the process with `exit(0)` without the orderly shutdown (as before this task); launchd does not restart anything at the end of the session, so only the state save is lost there. Routing the session end through the agent's shutdown (`NSTerminateLater` and `replyToApplicationShouldTerminate:` once the state is saved) is left out: it needs a channel from the main thread to the agent's runtime, and the session ends anyway.
- Why a delegate and not a `kAEQuitApplication` handler in `NSAppleEventManager`: replacing AppKit's handler would also have to reply to the event and reimplement the logout handshake; the delegate keeps AppKit's handling and only answers yes or no, and it is where AppKit expects the answer (`Asking app delegate whether applicationShouldTerminate:` in the log). The quit reason is read from `NSAppleEventManager.currentAppleEvent` inside the delegate, as Apple documents.
- Sudden and automatic termination: neither is turned on. The bundle's `Info.plist` (shared with the UI) has no `NSSupportsSuddenTermination` / `NSSupportsAutomaticTermination`, AppKit's default is off, and the log above already says "Exiting without sudden termination". Turning them on would let the system kill the agent silently, which is the opposite of what is wanted, so nothing is changed there.
- `paramDescriptorForKeyword:`, `eventClass` and `eventID` are called with `msg_send!` because the typed methods need the `objc2-core-services` crate for three `u32`s.
- Checked on the development Mac (Apple Silicon) with an unbundled debug `tandemd --sim-backends` and a small Swift sender (Quit Apple event by pid): a plain quit was answered `errn -128` (user canceled), the process kept running and logged the warning; a quit with reason `'rlgo'` was answered `errn 0`, logged `Quit AppleEvent for log out: AppKit terminates tandemd` and the process exited. The bundled case (LaunchServices, System Settings) stays in the hardware list.
