# T-082 — Automatic configuration on first launch (zero config)

## Context

First real test (2026-10-16): on the Mac `tandem.toml` had to be written by hand, and the
user does not want to do that. On Windows the default port 47770 could not be opened
(`os error 10048`) because that PC reserves 47000–48999 (WSL/Hyper-V), and the installer
template (`crates/tandemd/templates/tandem.pc.toml`) was out of date (34" with DP 0x0F
instead of 0x09, 32" without `edid_model` or `ddc`).

## Scope

1. If there is no `tandem.toml`, `tandemd` generates it on startup on macOS and Windows: `machine` from
   the operating system; monitors detected by EDID (on the PC through DDC/dxva2 and topology; on
   the Mac through Quartz) with stable ids and a label by size/model, DDC profile from the profile
   database (`profiles/ddc`) when it exists; default wiring DP→PC and HDMI→Mac; network,
   input and power sections with sensible default values and no fake data (no example
   MAC/VID:PID). If the Mac cannot see the EDID of a monitor that is only on the
   PC, the Mac starts with what it sees and is completed on sync (T-083).
2. Port with reservation: if the configured or default port cannot be opened, try
   a list of alternative ports outside 47000–48999 (starting with 52000) and announce the
   real port over mDNS; the final error, if none opens, explains the cause and how to fix it.
   Default port: 52000.
3. Remove the template from the Windows installer and the macOS bundle: both use the same
   generation as (1); the macOS app no longer requires writing the file and the first-launch
   guide says so.
4. The UI shows the generated config (machine, monitors, wiring) and lets the user change a
   monitor's wiring with one click (saved in `tandem.toml`).

## Acceptance criteria

- [x] Tests of the generation with simulated monitors that reproduce the real desk (34"
  SAM711A and 32" SAM7489) giving the correct config.
- [x] Test of the fallback port with the port occupied.
- [x] The installers no longer ship a template and start without a config.
- [x] `docs/dev/install-macos.md` and `install-windows.md` without steps for writing a config.

## Notes

- **Generation** (`tandemd::autoconfig`): `load_or_generate` loads `tandem.toml` or, if it
  does not exist (and only then), detects with `platform_scan` and writes it with `create_new` (never
  overwrites an existing one, not even an invalid one: that remains an error). `machine_of_os` gives `mac` on
  macOS and `pc` on Windows; on Linux it is not generated and the error asks for `--config`. If detection
  fails, it starts anyway without monitors.
  - PC: Windows topology (all connected monitors, active or not, with their place) plus
    the DDC bus (dxva2) for those missing (`merge`, by manufacturer + product + serial).
    Mac: Quartz. The built-in one and monitors without EDID are left out.
  - Each monitor: `id` = PnP id in lowercase (`sam711a`, the same on both machines because the
    monitor provides it; with two identical ones, `-<serial>` or `-2`), `edid_model` = PnP id, `label` = the
    EDID diagonal (`34"`, new `Edid::size_cm` / `diagonal_inches`; on the Mac,
    `CGDisplayScreenSize`) or the model, `ddc` from `ProfileDb` (repo + user), wiring
    `{ pc = "displayport", mac = "hdmi" }`. Ordered left to right across the desktop.
  - `Display::is_monitor` now also recognizes the exact PnP id: it is what the generated
    configuration writes (and T-080's "Add monitor"), and it does not confuse models that
    share the EDID name ("Odyssey G5").
  - Network (port 52000, no `peers`), input (`server = "mac"`, ScrollLock, clipboard) and
    power (`pc_lost_after_secs = 15`) with comments on what to add by hand (static links,
    `[input.hub]`, `[power.wol]`) without example values.
- **Port** (`network::bind_first`, `config::FALLBACK_PORTS`): the configured one and then
  52000, 52100, 53100, 54200, 55300, 56400, 45500, 44600; it only keeps trying if the
  socket fails (busy, reserved, no permission). mDNS already announced the real port. The PC's
  pairing port (`pairing::pairing_ports`) is the one after the real port (or the fixed
  `pairing_port`) and, if it does not open, the one after each fallback port. The final error
  (`NetError::NoPort`) lists the ports tried, the last error, the `netsh ... show
  excludedportrange` to see the reserved ranges and asks to choose another in `[network] port`.
- **Installers**: `crates/tandemd/templates/tandem.pc.toml` deleted; `tandemd --install`
  only registers startup. `test-installer.ps1` checks that, after installing, the agent
  starts and generates a valid PC config. The macOS bundle did not ship a template: the
  LaunchAgent starts `tandemd`, which generates it. The first-launch guide says so.
- **UI** (protocol v9): `UiCommand::SetWiring { monitor, wiring }` (validates, saves with
  `config_edit::set_monitor_wiring` keeping comments, and puts it in `LiveDesk`, formerly
  `LiveDdc`, which now also carries the wiring: the plans, `GetDesk` and the screen steps
  use it without restarting), `UiCommand::GetSetup` → `Reply::Setup(SetupInfo { config_file,
  generated, port })` and `AgentToUi::Desk` when the desk changes. It is rejected while a mode change
  is in progress. "Desk" button → dialog with the machine, whether the agent generated the configuration,
  the file, the port and each monitor with its wiring ("DP → PC · HDMI → Mac") and
  "Swap wiring" (`src/desk.ts`, pure and tested). Demo mode: `/?demo&desk`.
- The wiring change is saved only on the machine where it is made; the input is switched by the
  PC with its wiring. Having it travel to the other machine is part of the sync (T-083); the
  dialog says so.
- `docs/examples/tandem.*.toml` remain as a reference for all options, with port
  52000 and the clarification that they do not need to be written.
