# T-351 — Every external display of the Mac by its EDID, and a mode for the built-in display

## Context

Reported on 2026-11-24: Tandem shows four monitors (two from the Mac, two from the PC) where there are two, even with only the Mac in use, and the Mac's built-in display (lid usually closed) should be controllable. The Mac sees the 34" (LC34G55T) on HDMI with DDC/CI and the 32" Odyssey G5 through a USB-C to HDMI adapter that passes the EDID but has no DDC/CI. The PC sees both over DisplayPort with DDC/CI.

## Findings (2026-11-24, on the real machines; serials not recorded)

- Confirmed: `monitor-ddc`'s `MacBus::monitors` **does** enumerate the G5 behind the adapter (it is the second `DCPAVServiceProxy` with location `External`, with its EDID); `Get 0xEA` to it fails with `IOAVServiceWriteI2C failed`, so `LocalMonitors::scan` announces it as `NoChannel` (T-340). Its debug-level log line is why the Mac log never names it.
- Confirmed: the G5's monitor id is the same on both machines (computed from the EDID the Mac reads over HDMI and from the one the PC's registry holds for `SAM7489`).
- Confirmed: both monitors give the Mac an **E-EDID 1.3** on HDMI (byte 20 = `0x80`, no interface type), so `edid_input` gave the Mac no input of its own for either; the PC's DP EDIDs are 1.4 (`0xB5`, DisplayPort). The desk had a `[[cables]]` entry only for the 34": the G5 was never introduced (introducing needs the PC to own it compatibly and both inputs known), so neither machine linked it to a screen and the live desktops drew each machine's screens apart: the "four monitors".
- Confirmed: the IOKit registry holds every attached display's EDID in `IOPortTransportStateDisplayPort` (`EDID`), on the HDMI port and on the USB-C port of the adapter.
- Confirmed: with the lid open, macOS listed the built-in display mirroring the G5 (main) and the 34" as its own screen.
- Inferred from the T-341 log: the minutes of `CGCompleteDisplayConfiguration failed: 1001` (849 lines, two episodes) happened while the 34" was on the PC's input after the link with the PC dropped (unknown input, then the grace) and at start-up after an update; macOS refuses to turn on a display it cannot take the change for (gone, or with an id it no longer has). The agent retried every second and logged every try.

## Scope

1. The input of an old EDID comes from the model's per-input product id (`monitor-ddc`'s `host_input`), so the Mac states `HDMI` for both monitors itself.
2. EDID-only displays: `LocalMonitors::with_system_edids` adds, without a channel, every display of the system's EDID list that the DDC bus does not enumerate; on macOS the list is the IOKit registry (`tandem_input::macos::iokit::external_edids`, read-only). Never opened, never owner (T-340 rules).
3. Built-in display mode, a desk setting per machine (`[builtin_display]`, `DeskPatch::BuiltinDisplay`, protocol v49): `external-only` (default), `mirror`, `extended`. Applied by `DisplayGuard::reconcile_builtin` at start-up, on every desk change and every second: off, mirroring the main external display, or untouched (only what Tandem changed is undone). Without an active external display the built-in display is always on; with the lid closed it is never touched. What it was before is saved in `builtin-display.json` and put back at exit, on a panic, at AppKit's exit and at start-up after a crash.
4. Turning a display back on (T-341) is robust: macOS refusing it is reported once, then retried with a doubling wait (1 s up to 60 s); a display that came back with another id is found by its EDID identity.
5. UI: Settings, "Desk and machines", one row per Mac: "Built-in display of <Mac>" with External only / Mirror / Extended.

## Acceptance criteria

- [x] `LocalMonitors` test: a display only the system lists is announced as `NoChannel` with its input from the product id, never opened, read or written; a monitor the bus lists is not announced twice.
- [x] An EDID 1.3 gets its input from the product id.
- [x] Guard tests: external only, mirror (follows the main display), extended (only undoes Tandem's change), lid closed, no external display (always on), restore at exit and after a crash, a failed change waits, T-341 together with external only leaves a screen.
- [x] Re-enable tests: a refused display is retried with a growing, capped wait; a display with a new id is turned on by its EDID.
- [x] Two-agent test (`tandem-sim/tests/builtin_display.rs`): the PC's UI sets the Mac's mode and the Mac applies it; unplugging the external display turns the panel on; exit puts it back.
- [x] Desk, file and wire: the mode round-trips through `tandem.toml` and postcard; an unused section keeps the old desk fingerprint (no false hand edit after the update).
- [x] UI (vitest): the row exists only for the Mac, defaults to External only and a pick reaches the store.
- [x] Quality gate on Linux; macOS code built, linted and tested on the Mac.

## Notes

- Turning the built-in display off renumbers the screens if it was not the last active one; a learned `screen` end (T-340) is then stale until cleared, as T-340 already notes. With the lid closed or the built-in mirrored, it is not in the active list, so nothing moves.
- `monitor-ddc` needs no change for this: its macOS bus already lists the G5. A possible follow-up there: expose `host_input` for a raw EDID (or the `Edid`) so callers without a `MonitorInfo` do not build one.
