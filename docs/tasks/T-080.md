# T-080 — "Add monitor": wizard in the UI and the CLI

## Scope

"Add monitor" screen in the UI: lists the detected monitors (EDID), says whether they already have a profile (from the database or the user's), and for those that do not, runs T-077's calibration with T-078's confirmation, with visual progress per input and a result ("34": HDMI ✓ DP ✓"). When it finishes it saves the user profile, updates the monitor's config and offers to export it.
Also `tandem-ddc calibrate <monitor>` for the terminal, with keyboard confirmation (Enter = I see it), always with automatic rollback.

## Acceptance criteria

- [x] Complete flow in demo mode with simulated monitors, with screenshots in the PR.
- [x] `tandem-ddc calibrate` with the simulated bus finds the 32"'s profile (CLI test).
- [x] The saved profile is used in the next mode change without restarting the agent (test).

## Notes

- Protocol v7 (`tandem-proto`): `UiCommand::{ListDisplays, StartCalibration { display, monitor }, CancelCalibration, UseProfile { display, monitor }}`, `Reply::Displays(Vec<DisplayInfo>)` (each monitor on the bus with its `DisplayProfile`: `None`, `Configured` or `Known` with the TOML to export) and `AgentToUi::Calibration(CalibrationUpdate::{Started, Progress(CalibrationStep), Finished(CalibrationOutcome)})`.
- `tandemd::add_monitor`: `MonitorWizard` (PC only; on the Mac it is rejected with "monitors are calibrated from the PC") and `LiveDdc`, the codes learned live that `DisplaySteps` applies over the configuration at each step: that is why the next mode change uses them without restarting. The calibration runs on its own thread with its own runtime (the engine's future is not `Send` and each DDC operation blocks); while it lasts, the orchestrator is reserved and a mode change is rejected ("a change is already in progress"). The bus monitor is matched to the `[[monitors]]` by `edid_model` (only if it matches one and nothing else); otherwise the UI lets the user choose. The calibration starts from the input the monitor is on according to the state (and returns to it); the probe for the PC's input is shown by the PC, the other is requested from the peer (T-078).
- On finishing: user profile (`ProfileDb::save_user`, replaces the user's own file with the same PnP id if there was one), the PC's `tandem.toml` with `ddc = { hdmi = 0x.., display_port = 0x.. }` (`tandemd::config_edit`, with `toml_edit`: keeps comments, validates the whole configuration before writing and writes to a separate file + renames), and `edid_model` = PnP id if the monitor had none. What could not be done (no EDID, unable to write) goes in `SavedProfile.notes`.
- `tandem-ddc calibrate <monitor> [--from hdmi|dp] [--no-save]` (`cli::run_calibrate`): `calibrate::console::LineConfirmer` reads stdin on its own thread (anything typed before each question is discarded); Ctrl+C cancels with rollback. `CalibratedProfile::to_profile` builds the `<PNP>.toml` (`generic_name = true`, today's date) and `summary` the line "HDMI ✓ 0x05 · DP ✓ 0x0F". `WindowsDdc` is now `Send` (the dxva2 handles are not tied to the thread).
- UI: "Monitors" button → "Add monitor" dialog (`src/addmonitor.ts`, pure and tested): list with badges (Configured / In the database / Your profile / No profile), progress per input (HDMI and DP with their machine, code and attempt number), the fallback question inside the dialog, and result "32": HDMI ✓ DP ✓" with where the profile ended up, the TOML and "Copy profile". Demo mode: `/?demo&addmon` (`&calib=fail`: no HDMI code works). Screenshots: removed later because they showed the retired Spanish UI; see git history.
- Tests: CLI with the simulated 32" without the database (finds HDMI 0x05 / DP 0x0F and saves the profile), by keyboard from HDMI, and without a manual switch; `add_monitor` (list with profiles, PC only and one at a time, the calibrated profile is used in the next DDC mode change without asking for it by hand and ends up in `tandem.toml` and in the user's database, cancellation with rollback, using a profile from the database, association by model); `config_edit`; protocol; UI session (JSON); frontend (`src/addmonitor.test.ts`).
- Not included: at startup the daemon does not apply database profiles by itself to monitors without `ddc` in the configuration; this is done with "Use profile" so the user sees it.
