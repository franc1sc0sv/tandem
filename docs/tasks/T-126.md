# T-126 — TypeScript UI with A/B sides

## Context

T-097 changed the agent and the Tauri layer to `Machine::{A, B}` (JSON `"a"`/`"b"`), `arrangement.a_side` and `MachineView { name, os: "macos" | "windows", color }`, and added `desk.machines.{a,b}`. The old TypeScript UI (`apps/tandem-ui/src/*.ts`, which T-112 replaces with Svelte) still has `Machine = "mac" | "pc"`, `mac_side` and fixed "Mac"/"PC" texts (`MACHINE_NAME`, `demo.ts`, `scene.ts`, `onboarding.ts`, `main.ts`), so today it shows the sides wrong.

## Scope

1. `model.ts`: `Machine = "a" | "b"`, `Desk.machines`, `arrangement.a_side`, `MachineCaps { name, os: "macos" | "windows", color }`.
2. Names and colors of each machine from `MachineCaps`/`desk.machines` (with "machine A" if unknown); the machine drawing (laptop/tower) by `os`, not by side.
3. ~~Demo mode with system combinations~~: moved to T-112 (see Notes).
4. Update the vitest tests.

## Acceptance criteria

- [x] `grep -rn '"mac"\|"pc"\|mac_side' apps/tandem-ui/src` finds nothing.
- [x] vitest (87 tests), `tsc --noEmit` and `vite build` green; the CI UI job, in PR #68.

## Notes

Done inside T-097's PR (#68), at the review's request, so that `develop` is not left with a broken UI: minimal adaptation of the old UI (T-112 rewrites it).

- `Machine = "a" | "b"`, `Desk.machines`, `arrangement.a_side` and `MachineCaps { name, os, color }`.
- `MACHINE_NAME` is no longer fixed: `learnNames` fills it with each state (what was announced, otherwise the desk's and otherwise "machine A"). The setup buttons, the tray and the scene use those names.
- Each card's machine is drawn by its system (`os`), not by its side, and the accent comes from each machine's `color`.
- CSS classes per side (`.a`/`.b`).
- **Scope moved to T-112:** demo mode with system combinations (macOS+Windows, Windows+Windows, macOS+macOS) and its screenshot with two Windows machines. T-112 rewrites the UI and its demo mode, so that criterion is measured there, not in this old UI that is discarded.
