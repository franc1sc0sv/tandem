# T-126 — UI TypeScript con lados A/B

## Contexto

T-097 cambió el agente y la capa Tauri a `Machine::{A, B}` (JSON `"a"`/`"b"`), `arrangement.a_side` y `MachineView { name, os: "macos" | "windows", color }`, y agregó `desk.machines.{a,b}`. La UI vieja en TypeScript (`apps/tandem-ui/src/*.ts`, que T-112 reemplaza por Svelte) sigue con `Machine = "mac" | "pc"`, `mac_side` y textos fijos «Mac»/«PC» (`MACHINE_NAME`, `demo.ts`, `scene.ts`, `onboarding.ts`, `main.ts`), así que hoy muestra mal los lados.

## Alcance

1. `model.ts`: `Machine = "a" | "b"`, `Desk.machines`, `arrangement.a_side`, `MachineCaps { name, os: "macos" | "windows", color }`.
2. Nombres y colores de cada máquina desde `MachineCaps`/`desk.machines` (con «máquina A» si no se sabe); el dibujo de la máquina (laptop/torre) por `os`, no por lado.
3. Modo demo con combinaciones de sistemas (macOS+Windows, Windows+Windows, macOS+macOS).
4. Actualizar las pruebas de vitest.

## Criterios de aceptación

- [x] `grep -rn '"mac"\|"pc"\|mac_side' apps/tandem-ui/src` no encuentra nada.
- [x] vitest (87 pruebas), `tsc --noEmit` y `vite build` en verde; el job de UI del CI, en el PR #68.
- [ ] Captura del modo demo con dos Windows: el modo demo sigue con A = Mac y B = PC (su puesto de ejemplo); las combinaciones de sistemas en la demo quedan para T-112, que reescribe la UI.

## Notas

Hecho dentro del PR de T-097 (#68), a pedido de la revisión, para que `develop` no quede con la UI rota: adaptación mínima de la UI vieja (T-112 la reescribe).

- `Machine = "a" | "b"`, `Desk.machines`, `arrangement.a_side` y `MachineCaps { name, os, color }`.
- `MACHINE_NAME` ya no es fijo: `learnNames` lo llena con cada estado (lo anunciado, si no el puesto y si no «máquina A»). Los botones del asistente, la bandeja y la escena usan esos nombres.
- El equipo de cada tarjeta se dibuja por su sistema (`os`), no por su lado, y el acento sale del `color` de cada máquina.
- Clases CSS por lado (`.a`/`.b`).
