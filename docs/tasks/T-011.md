# T-011 — Topología de pantallas en Windows

## Alcance

`tandem-display::windows::topology`: listar rutas activas (QueryDisplayConfig), desactivar/activar un monitor (SetDisplayConfig) identificándolo por EDID. Spike S3: comprobar si el canal DDC sobrevive con el monitor desactivado; si no, investigar I2C por NvAPI y documentar el resultado en docs/research/.

## Criterios de aceptación

- [x] Nota de investigación con el resultado de S3: [`docs/research/s3-ddc-topologia-windows.md`](../research/s3-ddc-topologia-windows.md). Conclusión de API: `dxva2` no enumera un monitor desactivado; lo que depende del hardware queda abajo.
- [x] API attach/detach (`topology::{attach, detach, Detached}`, backend `windows::topology::WindowsTopology`) con pruebas `#[ignore = "hardware"]` listas; probada con el doble en Linux y en CI de Windows. La ejecución en la PC queda en la lista de abajo.

## Notas

Requiere los dos monitores conectados a la PC por DP.

La identificación por EDID ya se comprobó en la PC (solo lectura): `lists_real_displays_with_edid` lista el LC34G55T (SAM711A) y el Odyssey G5 (SAM7489), ambos activos.

Hallazgo para las transacciones (F3): como `dxva2` no ve monitores desactivados, el orden seguro es "activar en la topología → DDC" para traer un monitor a la PC y "DDC → desactivar" para cederlo. El ejemplo de DESIGN §5 lista DDC antes de activar; no se cambió el diseño, queda reportado.
