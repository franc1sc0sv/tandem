# T-011 — Display topology on Windows

## Scope

`tandem-display::windows::topology`: list active paths (QueryDisplayConfig), deactivate/activate a monitor (SetDisplayConfig) identifying it by EDID. Spike S3: check whether the DDC channel survives with the monitor deactivated; if not, investigate I2C through NvAPI and document the result in docs/research/.

## Acceptance criteria

- [x] Research note with the result of S3: [`docs/research/s3-ddc-topologia-windows.md`](../research/s3-ddc-topologia-windows.md). API conclusion: `dxva2` does not enumerate a deactivated monitor; what depends on the hardware is below.
- [x] attach/detach API (`topology::{attach, detach, Detached}`, backend `windows::topology::WindowsTopology`) with `#[ignore = "hardware"]` tests ready; tested with the double on Linux and in the Windows CI. Running it on the PC remains in the list below.

## Notes

Requires both monitors connected to the PC over DP.

Identification by EDID was already checked on the PC (read-only): `lists_real_displays_with_edid` lists the LC34G55T (SAM711A) and the Odyssey G5 (SAM7489), both active.

Finding for the transactions (F3): since `dxva2` does not see deactivated monitors, the safe order is "activate in the topology → DDC" to bring a monitor to the PC and "DDC → deactivate" to give it up. The example in DESIGN §5 lists DDC before activating; the design was not changed, it is reported.
