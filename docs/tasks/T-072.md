# T-072 — tandemd: assemble the network (QUIC, discovery, links, real peer)

## Scope

Today `crates/tandemd/src/main.rs` only starts the local `Agent` and the IPC; the network pieces exist (tandem-link: identity, transport, manager, discovery; tandemd: orchestrator/peer, pc_watch) but are only assembled in `tandem-sim`.
Assemble them in the real binary, following how tandem-sim does it:
- Load or create the Ed25519 identity and the trust store in the data directory.
- QUIC endpoint with pinning, mDNS discovery + static links from the config, link manager with the plane policy.
- Real orchestrator `PeerLink` over the active link (serve and request steps), final state to the peer, `pc_watch` on the Mac.
- With no paired peer: the agent works local-only and the UI indicates it.
- Example configs `docs/examples/tandem.mac.toml` and `tandem.pc.toml`.

## Acceptance criteria

- [x] Integration test: two `tandemd` (lib) with paired identities on loopback discover each other through static links, connect and run a mode change with injected simulated backends.
- [x] With no paired peer the agent starts, answers over IPC and reports that there is no peer.
- [x] `main` has no logic: what is assembled is a tested function (`daemon::start` or similar).

## Notes

- What is assembled lives in `tandemd::daemon::start` (state, `identity.key` identity, `trust.toml` trust, network) and `tandemd::network::Network` (QUIC endpoint with pinning, serving the peer's connections, mDNS, link manager, `ManagedPeer` and `pc_watch`). `main` only resolves paths, log, runtime and IPC.
- The orchestrator has the `ManagedPeer` only while some link sees the other agent (`set_peer` / `clear_peer`): that way powering on the PC really waits for its agent to appear.
- Protocol v3: `UiCommand::GetPeer`, `Reply::Peer` and `AgentToUi::Peer` with `PeerStatus` (`Unpaired` or `Paired { name, link }`). The window shows the peer and the link in the link pill ("no peer", "no link", "USB4"...) and the tray menu adds "no paired peer".
- If what is discovered through mDNS changes the candidates, the link manager is rebuilt (it does not accept new links while running).
- The endpoint listens on IPv4 unless some static link is IPv6.
- Also fixed `apps/tandem-ui/src/tray.ts`, which had not compiled (`pnpm build`) since T-063 because of the `power` notice.
- Tests: `crates/tandemd/tests/network.rs` (two agents paired over a static link on loopback switch modes, the Mac stops seeing the PC when it powers off, powering on the PC waits for its agent, agent with no peer, persistent identity) and `example_configs_are_valid` in `tests/check_config.rs`.
- Left to verify on the real desk: mDNS discovery between the Mac and the PC on the home LAN and the direct USB4/Ethernet links with the IPs from the example configs.
