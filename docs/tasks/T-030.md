# T-030 — PC power on and off

## Scope

`tandem-power`: Wake-on-LAN (magic packet over the configured Ethernet interface), and on Windows a clean power-off (`shutdown /s /t 0` via API) as the `PowerOffPc` step. `PowerOnPc` = WoL + wait for the agent (timeout 120 s).

## Acceptance criteria

- [x] Test of the magic packet format.
- [x] The PowerOffPc step is only accepted if the plan has already returned all the monitors to the Mac (validated in the executor).

## Notes

The real test needs the Ethernet cable and the BIOS configured (ErP off, WoL on, Fast Startup disabled).

- `tandem-power`: `MacAddr` (accepts `aa:bb:..` and `AA-BB-..` from `ipconfig /all`), `magic_packet` (6 × `0xFF` + the MAC 16 times, 102 bytes), `UdpWake` (trait `Wake`) which sends the packet over UDP from the configured source IP, and the `Shutdown` trait with `WindowsShutdown`: `InitiateShutdownW` with `SHUTDOWN_POWEROFF`, no grace period, not forced and without `SHUTDOWN_HYBRID`, after enabling `SeShutdownPrivilege` in the token.
- `tandem.toml`: optional `[power.wol]` section with `mac`, `source` (the Mac's IP on the Ethernet link), `broadcast` (255.255.255.255 by default; on macOS the link subnet's is advisable, e.g. `10.77.2.3`) and `port` (9). Port 0 and source/destination of different families are rejected.
- `tandemd::power::PowerSteps`: wraps the machine's `LocalSteps`; on the Mac `PowerOnPc` = one WoL send (without `[power.wol]` it fails with «[power.wol] missing in tandem.toml»), on the PC `PowerOffPc` = power-off (outside Windows, «not implemented»). `main` already uses it, with `Unimplemented` for the rest.
- Orchestrator: `PowerOnPc` repeats the WoL every 5 s (`WOL_RESEND`) until the other agent is connected (`set_peer` marks it, `clear_peer` unmarks it; `peer_connected()` gives the notice), within the `power_on_timeout_secs` cap; an error sending the packet cuts it short immediately. `PowerOffPc` is validated by the `Dispatcher` against the state with the steps already applied: if any monitor is still on the PC, the step fails without reaching the PC («power off the PC: m34 is still on the PC; the monitors must be returned to the Mac first») and the transaction rolls back. Property test: for any starting and ending split, the power-off reaches the PC if and only if the plan leaves everything on the Mac.
- Out of scope: the UI does not yet have a command to power off the PC (`Plan::shutdown_pc` exists, the `UiCommand` and the button are missing, T-04x); and since `main` does not yet connect with the other agent, nobody yet calls `set_peer`/`clear_peer` in the real agent: until that task, powering on the PC ends in a timeout even if the WoL works. Whoever connects the link manager must call `clear_peer` when the connection is lost, or a later power-on would end immediately without waiting for the PC.

## Pending hardware verification

- [ ] With the PC off (S5), `PowerOnPc` from the Mac over the direct Ethernet powers it on (BIOS: ErP off, WoL on; Windows: Fast Startup disabled).
- [ ] On macOS, the packet goes out over the Ethernet interface with `source` + `broadcast` of the link's subnet (check with `tcpdump -i <en>` on the Mac) and not over Wi-Fi.
- [ ] `WindowsShutdown` from the service (SYSTEM) powers off the PC without asking for confirmation and the agent manages to answer the step before shutting down.
- [ ] The power-off is not hybrid: the next boot is a full one (Fast Startup does not intervene).
