# T-070 — macOS installer (.app/.dmg) with tandemd

## Scope

Packaging for macOS with the Tauri bundler: `Tandem.app` that includes `tandemd` as a sidecar, a LaunchAgent that the app installs/updates to start `tandemd` at login, and a first launch that guides the permissions (Accessibility, Input Monitoring, local network) with screens in the mockup's style. Ad-hoc signing by default; Developer ID signing and notarization optional through environment variables (user's decision, documented). CI job on macos-latest that builds the `.dmg` and uploads it as an artifact.

## Acceptance criteria

- [x] The CI job produces `Tandem_*.dmg` as an artifact.
- [x] The LaunchAgent plist is generated and its content is tested in a unit test.
- [x] docs/dev/install-macos.md with installation, permissions and signing.

## Notes

- **Packaging** (`scripts/macos/bundle.sh`): builds `tandemd` in release for the target, leaves it as a sidecar (`src-tauri/binaries/tandemd-<target>`, not versioned) and runs `tauri build --bundles app,dmg` with `src-tauri/tauri.sidecar.json`, which adds `externalBin` only there (the app's `cargo build` and the `ui` job do not need the sidecar). Afterwards it checks that the app contains `Contents/MacOS/tandemd` and that it runs, the `NSLocalNetworkUsageDescription` in `Info.plist`, the signature (`codesign --verify --deep --strict`) and the image (`hdiutil verify`).
- **CI**: `dmg (macos-latest)` job that runs the script and uploads `Tandem_*.dmg` as the `tandem-macos-dmg` artifact.
- **Signing**: ad-hoc by default (`signingIdentity: "-"` in `tauri.macos.conf.json`, minimum macOS 13). Developer ID and notarization with the Tauri bundler's variables (`APPLE_SIGNING_IDENTITY`, `APPLE_CERTIFICATE`, `APPLE_ID`/`APPLE_API_KEY`...), documented in `docs/dev/install-macos.md`.
- **LaunchAgent** (`tandem_ui::launch_agent`, portable and tested with a simulated `launchctl`): on startup on macOS, the app writes `~/Library/LaunchAgents/com.franc1sc0sv.tandem.tandemd.plist` pointing to the app's `tandemd` and with its version; if it changed, `bootout` + `bootstrap` in `gui/<uid>`; if it was already up to date and loaded, it touches nothing. `RunAtLoad`, `KeepAlive` only on error, `ThrottleInterval` 30 s, `LimitLoadToSessionType = Aqua`. It is not installed from a development build, from the disk image or from App Translocation (the guide says so).
- **First launch** (`tandem_ui::setup` + `src/setup.ts`): guide in the mockup's style with a welcome (how `tandemd` ended up) and one screen per permission (Accessibility, Input Monitoring, Local Network) with a button that opens the System Settings panel. "Finish" marks it in `setup.done` next to `tandem.toml`; it reopens with the "Permissions" button. macOS only.
- The guide does not show whether each permission is already granted: the permissions belong to `tandemd` and the IPC does not report it yet.
- Screenshots (frontend in Chrome with the simulated agent, `/?demo&setup` and `/?demo&setup=fail`): `docs/screenshots/T-070-permisos-inicio.png`, `T-070-permisos-entrada.png`, `T-070-permisos-sin-agente.png`.
