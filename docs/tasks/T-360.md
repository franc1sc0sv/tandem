# T-360 — Window rescue on Windows

## Context

Seen on the real desk on 2026-11-26: while a shared monitor shows the Mac, Windows keeps that monitor's DP display in its desktop (the monitor keeps DP alive while it shows HDMI; T-341 assumed no phantom). Windows apps stay or open on a screen nobody sees; T3 Code, minimized with its restore rect on DISPLAY2 (the Odyssey G5 at x=-2560), restored off-sight. macOS does not have this: it turns the display off (T-341).

Decision: do not detach the display on Windows (the PC is the only DDC/CI path to the Odyssey and a detached display has no `HMONITOR`); rescue the windows instead.

## Scope

- `tandem_input::rescue`: portable `WindowRescue` logic, `WindowMover` trait, `FakeWindowMover`; Win32 backend in `windows::rescue` (`EnumWindows`, `GetWindowPlacement`, `SetWindowPlacement`); none on macOS.
- Wired in `DisplayGuard` (`with_rescue`, `rescue_windows`) and run by the agent's display loop (each change of what the monitors show, and once a second).
- DESIGN section 10 and docs/DECISIONS.md updated.

## Acceptance criteria

- [x] Windows mostly on a hidden screen move to the primary visible one (else the first), size clamped to its work area.
- [x] Maximized windows are re-maximized on the target; minimized windows get their restore rect moved.
- [x] Original placements are put back when the screen is seen again; windows the user moved or closed are not.
- [x] Elevated (denied) windows are logged once and not retried; nothing visible means nothing is done.
- [x] A hung window (`IsHungAppWindow`) is skipped without counting as failed and is rescued once it answers.
- [x] A screen whose input is briefly unknown keeps its windows moved for `UNKNOWN_GRACE` (15 s).
- [x] Invisible, cloaked, tool, owned, shell and Tandem's own windows are never listed.
- [x] Unit tests with the fake and a property test (a rescued window ends inside a visible work area).
- [x] Quality gate and `cargo check --target x86_64-pc-windows-gnu`.
