# T-361 — Special keys and commands work as they should on both systems

## Context

Reported on 2026-11-26: "replicate the whole keyboard of both OSes so special keys and commands work as they
should". Tandem sends physical keys (HID) and only swaps modifiers per direction (`event::remap`). Characters
are right (both machines use the U.S. layout), commands are not: the PC's Ctrl+Left (word jump) reaches the Mac
as Cmd+Left (line start), Alt+Tab as Option+Tab, Home/End scroll the document, Alt+F4 does nothing, Ctrl+Backspace
deletes the line, PrintScreen does nothing; the Mac driving the PC has the mirror problems.

## Scope

- `tandem_input::event::shortcuts::ShortcutTranslator`: pure and portable. A rule table per direction (written
  in the source's terms) plus a state machine that follows the source's held modifiers and the target's emitted
  ones. A translation lives while its key is held; releasing everything leaves nothing pressed at the target.
- Wired where the server applies `RemapPolicy` (`CaptureSink`), only when the desk's `cmd_ctrl` is on. The keys
  of the lock shortcut are exempt; the scenes' shortcuts already match the physical keys before this step.
- Tables (PC→Mac): Ctrl+Left/Right/Backspace/Delete → Option+...; Home/End → Cmd+Left/Right; Ctrl+Home/End →
  Cmd+Up/Down (Shift variants); Alt+Tab (Cmd held while Alt is) and Alt+F4 → Cmd+Q; Win tap → Cmd+Space, Win+D →
  F11, Win+L → Ctrl+Cmd+Q, Win+E → Cmd+Option+Space, Win+Shift+S → Cmd+Shift+4; PrintScreen → Cmd+Shift+3;
  Ctrl+Shift+Esc → Cmd+Option+Esc. Mac→PC is the mirror.
- Media and F-keys: verified in tests that they travel and are never touched by the translator.
- DESIGN §7, `docs/DECISIONS.md`, doc comment of `InputConfig::remap`.

## Acceptance criteria

- [x] Unit tests per table entry in both directions (press/release order, Shift variants, right-hand modifiers),
  held Alt+Tab with several Tabs, modifiers released in any order, key repeat, Win tap and its cancellation.
- [x] Proptest: after any sequence of source events and releasing everything, the target holds nothing; unmapped

- [x] Wired into the server send path; two-agent test (`tandemd/tests/input.rs`): the PC's Ctrl+Left arrives at

- [x] The lock shortcut keeps matching the physical chord (its keys are exempt); scenes already observe the
  physical keys.
- [x] Media, volume and F-keys reach both sides (keymap test; the Mac injects media through `media_key`).
- [x] DESIGN §7 and DECISIONS updated; `cmd_ctrl`'s doc comment mentions the table.
- [x] `cargo fmt`, `cargo clippy`, `cargo test --workspace`, `cargo check --target x86_64-pc-windows-gnu`.

## Notes

- Not translated: Cmd+Backspace (its Windows equivalent is "Shift+Home, Backspace", a two-step sequence this
  model does not support) and F2.
- Right Alt (AltGr / right Option) types characters, so no chord is translated while it is held.
- A modifier tap can leak: Ctrl pressed before Left reaches the Mac as a quick Cmd press and release before the
  translation swaps it for Option; the same happens on Win+D (a Ctrl tap on the Mac when Win goes up). Neither
  does anything on its own.
- Win pressed alone is held back until another key, a click or its release shows what it is, so Win+click is
  delivered as Ctrl+click only when the click arrives.
- Brightness keys have no Windows scancode (Windows injects none), so they reach the Mac only.
- The two-agent test lives in `tandemd/tests/input.rs` (the harness that already runs a Mac and a PC agent in one
  process), not in `tandem-sim`.
