# T-111 — Scenes with monitors

## Context

DESIGN §5 and §7 (the screens that show the other machine come out of the geometry); mockups `V3-Monitores` (scenes as cards with "Active" and "Apply"), `F-NuevaEscena`, `F-Transacciones`.

## Scope

1. Connect the abstract step of T-100 to a real `SwitchMonitor` (T-110).
2. When a scene is applied, the input engine's geometry is recalculated: a monitor that shows the other machine stops being a screen of this one.
3. Scene editor (backend): validate that only compatible monitors get in.
4. Active scene detected at startup from the real input of each monitor.

## Notes

- **Cabling (the desk's `[[cables]]`, `DeskPatch::Cable`).** To translate "make the 34" show B" into an input, we need to know which input each machine's cable goes to. It is declared on the desk (`a`/`b` with `input` and `screen`); when undeclared, it comes from the EDID interface type that each machine reads (E-EDID 1.4, byte 20: HDMI or DisplayPort), which travels in `MonitorChannel.via` and `MonitorView.via`. Knowing one input, the other is the other one (the standard has two). If they contradict each other, neither is known: we never guess.
- **Real scene step.** `ShowMachine` remains the step the UI sees ("show machine B on the 34""); the real monitors do it as a `SwitchMonitor` by the owner (D13) through the orchestrator, with a verdict and a timeout. An error without a verdict, without a response or with the link cut leaves the doubt and also rolls back that monitor. Monitors that already show their machine are removed from the plan before starting.
- **Geometry.** The `Geometry` step waits for the monitors to show what the scene says (according to what the owner reads). The input engine removes from a machine's screens those that, in `[[cables]]`, are a monitor showing the other one; it is recalculated with every change of the monitors. A monitor without a declared `screen` cannot be removed (the screens the system reads do not carry the monitor id): left for when the screen reading brings the EDID.
- **New monitors.** The owner of a compatible monitor without cabling, with both inputs known, records it in `[[cables]]` and adds it to the default scenes: "A only" with A, "B only" with B and "Work" with whatever it shows at that moment. Only once: after that the user is in charge. It does not raise "Changed from" (the agent did it).
- **Active scene.** Outside a transaction, if a monitor shows something other than the active scene, it stops being active; with no active scene, the one currently in place is recognized (all its monitors, its arrangement, its machines powered on; the one that asks for the most). This happens at startup and every time the monitors change (also from the monitor menu).
- **Protocol v29** (v25 is T-103's, v26 is T-093's and v28 is T-102's): `[[cables]]` on the desk, `DeskPatch::Cable` and `via` in channel and view.
- Tests: `crates/tandem-sim/tests/scene_monitors.rs` (two agents with the `monitor-ddc` doubles: "A only" → "B only" with the geometry, failed verdict, no verdict, scene recognized from the monitor menu, editor); pure logic in `tandem-core` (`Inputs`, `introduce_monitor`, `detect`, with properties) and in `tandemd` (`shows`, `hidden`, `skip_shown`).
