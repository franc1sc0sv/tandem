# T-191 — CI without a per-job timeout; a test hung on Ubuntu

## Context

Failure found by the acceptance agent, part C, round 2 (2026-11-18, `origin/develop` b3841bc). See `docs/reports/acceptance-2026-11-18-c2.md`.

## Failure

G11. Run 44345845261 (`develop`, 4751832, PR #117) had the `ubuntu-latest` job on `Run cargo test --workspace` since 16:20 UTC and at 18:43 UTC it was still `in_progress` (more than 2 h 20 min; normal runs last 10 to 15 min). Some Rust test hangs without finishing and nothing cuts it. The other jobs of that run passed. In addition `.github/workflows/ci.yml` only has `timeout-minutes` on one job (line 200); the others wait until GitHub's 6 h limit, and the commit is left without a verdict.

## Expected fix

- Set `timeout-minutes` (for example 30) on all the jobs of `ci.yml`.
- Identify which test hung (cancel the run and read its log; if that is not possible, run `cargo test --workspace` in a loop with a low `--test-threads` and `timeout`) and fix it; every async test that waits for something external goes inside a labeled `within`/`timeout`.
- Make `cargo test` print the test that has been running for more than 60 s (`RUST_TEST_TIME`/`--report-time` or a watchdog) so that the next hang can be diagnosed.

## Acceptance criteria

- [x] All the jobs of `ci.yml` have `timeout-minutes`.
- [x] The test that hung is identified in `## Notes` and fixed, or it is documented why it could not be reproduced and what watchdog was added.
- [x] CI green on Linux, Windows and macOS.

## Notes

- `timeout-minutes` was added to all the jobs of `ci.yml` (30 on rust/ui/dmg/coverage, 20 on mockups/screenshots; installer-windows already had 45) and 15 to `prepare` of `release.yml`. Normal runs last 10 to 15 min.
- `cargo test` also carries a 20 min cap per step, so that a hang fails early and with the step labeled.
- The hung test was neither identified nor reproduced; no per-test watchdog was added (`--report-time` requires nightly and there is no nextest). The candidate is `pairing_hot_opens_the_input_session` (T-190), which in the same round was left waiting on macOS; its fix goes in T-190. The watchdog is the 20 min cap of the `cargo test` step: a hang now fails with the step labeled instead of blocking the run for hours.
