# T-107 — Git workspace

## Context

DECISIONS D8; DESIGN §8.

## Scope

1. `tunnel_open { …, workspace: { repo_path } }`: on the origin, `git bundle` of the current branch + patch of uncommitted changes (includes new non-ignored files); on the target, working folder `<data>/workspaces/<tunnel>` with the bundle's clone and the patch applied. Default `cwd` of the tunnel's processes.
2. `bring_back { tunnel }`: on the target, commit of what is pending if requested; bundle of the new commits; on the origin, branch `tandem/<tunnel-or-title>` created without touching the current branch or the working tree. Returns the branch and the commits.
3. Workspace cleanup when the tunnel closes (configurable: keep).
4. Works with repos that use worktrees and with submodules (these are copied as they are).

## Acceptance criteria

- [x] Tests with real temporary repos (git in PATH in CI): outbound with uncommitted changes, commits on the target, return as a branch; the origin does not change its branch or its tree.
- [x] Quality gate and CI green on the three platforms.

## Notes

Done:

- Protocol v33: `TunnelUp::Workspace(WorkspaceUp::{Prepare, Checkout, Pack})` and `TunnelDown::Workspace(WorkspaceDown)`, `UiCommand::OpenTunnel { workspace: Option<WorkspaceSpec { repo_path, keep }> }`, `UiCommand::BringBack { tunnel, commit, name }` and `Reply::BroughtBack(BringBackReport { branch, commits, committed_pending })`.
- `tandem-workspace` crate (portable). The only system-dependent piece is `Git` (`SystemGit` invokes `git` with `core.autocrlf=false` and without inheriting `GIT_DIR`/`GIT_INDEX_FILE`; `FakeGit` for orchestration tests).
  - Outbound: `git bundle` of `HEAD` and patch (`diff --cached --binary` against a temporary index after `add -A`: includes new untracked files, respects `.gitignore` and does not touch the user's index). They travel as files (`tandem-files`, resumable) to `<data>/workspaces/<tunnel>.in`; the target does `init` + `fetch` of the bundle + `apply`, and the default `cwd` of the tunnel's processes (`HostTunnel::set_default_cwd`, not valid in `wsl:`/`docker:`) becomes the folder `<data>/workspaces/<tunnel>`. The target's commits go out in the origin user's name (their `user.name`/`user.email` is sent).
  - Return: with `commit`, the target commits what is pending; what is pending without asking for a commit does not come back. Bundle of `base..HEAD`, `fetch` on the origin to `tandem/<name>` (default name: the tunnel's title; if it exists, `-2`, `-3`…). The `fetch` does not touch the current branch, the index or the working tree. With no new commits: `branch: None`.
  - Cleanup when closing the tunnel (`Resource`), except `keep: true`. An `open` that fails closes the tunnel.
  - Worktrees: tested with a real linked worktree. Submodules: their files are copied as they are (without their `.git`) and the patch ignores them; on the return they are still the `160000` entry.
- `tandem-files`: `Files::serve_request` and `MemPath::with_server` (to hang other modules). `tandemd`: `Agent::workspaces()`, requests only from a client (the UI receives `Rejected`, D9) and `OpenTunnel` with workspace and `BringBack` run in their own task (they take a while).
- Tests: real git repos in temporary folders (`crates/tandem-workspace/tests/roundtrip.rs`: outbound with uncommitted changes, binaries and new files, commits on the target, return as a branch with the origin intact, worktree, submodule, cleanup and `keep`, errors) and `crates/tandemd/tests/workspace.rs` with two real agents over QUIC on loopback (like `files.rs`, not with `start_pair!`, which sets up the full pairing).

For other tasks: T-108 exposes `tunnel_open { workspace }` and `bring_back { tunnel, commit, name }` over these `UiCommand`s.

Known limits: if the origin repo moved on or rewrote its history and no longer has the base commit, `bring_back` fails with git's error (the bundle needs it); a repo with a `HEAD` without commits or outside git is rejected on opening; if `repo_path` is a subfolder, the workspace is the whole repo.
