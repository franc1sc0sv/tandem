# T-026 — Input session over the link

## Scope

Input protocol: datagrams for movement/scroll (coalesced, with a sequence number and absolute resync), reliable stream for keys/buttons/enter/leave. 1 s heartbeat; when the link changes or drops, `release_all()` on the client. Platform-independent server/client state machine, with capture/injection behind traits.

## Acceptance criteria

- [x] Loopback integration test with simulated capture and injection: a sequence of events arrives intact and in order.
- [x] Link drop in the middle of a pressed key → the client releases it (test).

## Notes

- Code in `tandem-input::session`: `ServerSession`/`ClientSession` (state machines without I/O), `Capture`/`Injector` traits with doubles in `session::fake`, and `ServerDriver`/`ClientDriver` over a `tandem-link` `Connection`. Messages in `session::msg` (`StreamMsg` over the reliable stream, `Datagram` for movement and scroll), encoded with `tandem-proto`.
- The server is the authority on the remote cursor's position: it crosses with `Layout::step` and carries the client's cursor in the client's native coordinates. Deltas travel in logical points (as T-021 anticipates); absolute positions, in the destination's native coordinates. The documentation of `InputEvent::MotionRelative`/`MotionAbsolute` was adjusted to say so.
- Datagrams: an increasing sequence number; one with an absolute position every `resync_every` (16), and when the mouse stops (`resync_idle`, 50 ms) the exact position goes over the reliable stream (`StreamMsg::Sync`), so the cursor converges even if the periodic datagram is lost. Buttons carry their position and their `seq` to land where the user saw them. The client never moves the position backward because of a late datagram, but it does apply its scroll.
- On entering, the modifiers the user already has held down are sent; on leaving, on link drop or change (`stop`), or after `heartbeat_timeout` (3 s) without signals, the client does `release_all()` and the server gives the local input back (`Grab(false)` + `Warp`). 1 s heartbeat in both directions.
- Integration tests (`crates/tandem-input/tests/session.rs`) with real QUIC over loopback and a UDP relay to simulate the cable being disconnected without notice.
- Still to be wired in `tandemd`: the input stream is opened by the server over the active link's connection, after the link manager's ping stream; the accepting side has to hand that second bidirectional stream to the `ClientDriver`, and each `run`'s `stop` is the manager's `LinkEvent`. That is part of the agent's wiring, outside this task.
- What is captured without a session (no link, or between one session and the next) is not replayed: at the start of each session, before and after opening the stream, the server drains the channel with `ServerSession::catch_up`, which only remembers pressed keys and buttons (the `Enter` carries the real modifiers) and the local cursor's absolute position; old relative movement and scroll are discarded, because they would cross without the user asking for it. While there is no link, `ServerDriver::idle` consumes the capture so the channel does not grow without bound; `ServerDriver::active` signals when the session is established. The wiring in `tandemd` must alternate `idle` and `run`.
- Leaving the remote display with a button pressed (drag between machines) is not prevented; the client releases it on leaving.
