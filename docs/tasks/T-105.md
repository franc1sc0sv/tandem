# T-105 — Environments and resources

## Context

DECISIONS D8, D10; DESIGN §8; mockup `V3-Machine` (resources grouped CPU / RAM / GPU + disk line; Environments panel of the same height as the others).

## Scope

1. `tandem-env` crate: scan at startup and on demand (`UiCommand::Rescan`, MCP tool): shells (zsh, bash, fish, PowerShell 5/7, cmd), WSL (distros with version), Docker (live daemon, version), git, cargo/rustc, node/pnpm/npm/bun, uv/python, GPU (model, VRAM, driver; `nvidia-smi` on Windows/Linux, `system_profiler`/IOKit on macOS).
2. Live resources: CPU (total and per-core usage, model), RAM (used/total), GPU (usage, VRAM used, temperature if possible), disk (free/total of the system volume). 1 Hz sampling only with subscribers.
3. Everything behind traits with doubles; nothing fixed to a machine model.
4. Announced in `Capabilities` (environments) and through `UiEvent::Resources` (live). Available to MCP (`resources`, `machines`).

## Acceptance criteria

- [x] Tests with doubles of the detection (real sample outputs of each tool saved as fixtures).
- [x] In each platform's CI, the real scan runs without error and finds at least the runner's shell.
- [x] Quality gate and CI green.

## Pending hardware verification

- [ ] PC: detects PowerShell, WSL (Ubuntu), Docker and the GPU with its VRAM. Mac: zsh, Docker if present, Apple GPU.
- [ ] PC: the agent started by the scheduled task (without a console) scans without opening black windows (`CREATE_NO_WINDOW`) and sees the user's `PATH` (git, uv, node).
- [ ] PC: with Docker Desktop closed, Docker shows as "not ready" with its reason; on opening it and rescanning, ready and with "--gpus all available".
- [ ] PC: the live resources match Task Manager (total CPU, RAM, GPU usage and VRAM, GPU temperature, free on C:).
- [ ] Mac: replace the `macos-*` fixtures (made with macOS's format because the Mac was not within reach) with real outputs of `zsh -lic <PROBE_SCRIPT>`, `system_profiler SPDisplaysDataType -json`, `ioreg -r -d 1 -c IOAccelerator` and `docker version --format json`.
- [ ] Mac: the launchd agent sees Homebrew and `~/.cargo/bin` through the login shell; GPU usage from `ioreg`, CPU temperature (`PMU tdie` sensors) and free space of the data volume.
- [ ] Both: with one machine's UI watching, the other's resources arrive at 1 Hz; when the UI closes the other stops sampling (≤ 10 s).

## Notes

- New `tandem-env` crate: `Runner` (programs, `FakeRunner` double) and `Meter` (counters with `sysinfo`, `FakeMeter` double) are the platform traits; `Host` scans and samples; `ResourceMonitor` samples at 1 Hz only with someone watching.
- Protocol v18: `Environment` with id, class, version, tools and GPU; `Capabilities.hardware` (CPU, cores, RAM, GPU with VRAM and driver); `UiCommand::{Rescan, WatchResources}`; `AgentToUi::Resources` (the task's `UiEvent::Resources`); `ControlMsg::{WatchResources, Resources, Rescan}` for the other machine's resources and rescan.
- The agent scans at startup (in the background) and on each `Rescan`; what is found goes out in the next capabilities announcement (`AgentToUi::Machines`).
- The MCP tool (`machines`, `resources`) and the CLI belong to T-108: they use `GetCapabilities`, `Rescan` and `WatchResources` over the IPC.
- The Windows fixtures are real outputs from the PC (user paths changed); the macOS ones follow macOS's format because the Mac did not answer over SSH (see the list above). Details in `crates/tandem-env/tests/fixtures/README.md`.
- Two-agent test (`crates/tandemd/tests/environments.rs`, with `Backends::Custom { env }`): B's UI sees A's environments and hardware, `Rescan { machine: A }` from B brings what is new, and `WatchResources` from B receives the resources of both; with `on: false`, A stops sampling.
