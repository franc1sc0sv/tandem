# T-040 — Tauri: esqueleto de la app y cliente IPC

## Alcance

`apps/tandem-ui`: Tauri 2 + frontend TypeScript (Vite, sin framework pesado o con uno ligero). Tokens de diseño tomados de `mockups/main.html` (colores apagados, sin neón). Comando Rust que habla con tandemd por la IPC local.

## Criterios de aceptación

- [x] `pnpm build` y `cargo build` del lado Tauri pasan en CI (Linux al menos).
- [x] Pantalla vacía con el estado leído de tandemd (o un error claro si no corre).

## Notas

- `apps/tandem-ui/src-tauri` es el crate `tandem-ui`, miembro del workspace. La app de Tauri va detrás de la feature `app` (y el binario la exige con `required-features`), porque en Linux necesita WebKitGTK: sin ella el crate es la lógica portable (`status`) y corre en la matriz de CI de las tres plataformas y en `cargo test --workspace` local. El job `ui` de CI (ubuntu) instala WebKitGTK y corre `pnpm test`, `pnpm build`, `cargo clippy` y `cargo build -p tandem-ui --features app`.
- Comando `agent_status`: calcula el endpoint igual que `tandemd` (`Paths` + `ipc::default_endpoint`; `TANDEM_DATA_DIR` equivale a `tandemd --data-dir`), se conecta con el cliente de `tandemd::ipc`, pide `GetState` con un límite de 2 s y devuelve `{kind: "connected", agent, state}` o `{kind: "unavailable", endpoint, reason}` con la razón en palabras (no corre, sin permiso, otra versión, se colgó, cerró la conexión).
- Frontend: Vite + TypeScript sin framework; tokens de color y tipografía copiados de `mockups/main.html`. Pregunta cada 3 s hasta que T-041 escuche los avisos empujados; botón «Reintentar» en el error.
- Desarrollo: `cd apps/tandem-ui && pnpm install && pnpm tauri dev` (en Linux hace falta `libwebkit2gtk-4.1-dev`).
- Capturas: `docs/screenshots/T-040-conectado.png` y `docs/screenshots/T-040-sin-agente.png` (frontend en Chrome con el puente de Tauri simulado).
