# T-040 — Tauri: app skeleton and IPC client

## Scope

`apps/tandem-ui`: Tauri 2 + TypeScript frontend (Vite, no heavy framework or with a light one). Design tokens taken from `mockups/main.html` (muted colors, no neon). Rust command that talks to tandemd over the local IPC.

## Acceptance criteria

- [x] `pnpm build` and `cargo build` of the Tauri side pass on CI (Linux at least).
- [x] Empty screen with the state read from tandemd (or a clear error if it is not running).

## Notes

- `apps/tandem-ui/src-tauri` is the `tandem-ui` crate, a workspace member. The Tauri app goes behind the `app` feature (and the binary requires it with `required-features`), because on Linux it needs WebKitGTK: without it the crate is the portable logic (`status`) and runs in the CI matrix of the three platforms and in the local `cargo test --workspace`. The CI `ui` job (ubuntu) installs WebKitGTK and runs `pnpm test`, `pnpm build`, `cargo clippy` and `cargo build -p tandem-ui --features app`.
- `agent_status` command: computes the endpoint the same way as `tandemd` (`Paths` + `ipc::default_endpoint`; `TANDEM_DATA_DIR` is equivalent to `tandemd --data-dir`), connects with `tandemd::ipc`'s client, asks for `GetState` with a 2 s limit and returns `{kind: "connected", agent, state}` or `{kind: "unavailable", endpoint, reason}` with the reason in words (not running, no permission, another version, hung, closed the connection).
- Frontend: Vite + TypeScript without a framework; color and typography tokens copied from `mockups/main.html`. It polls every 3 s until T-041 listens to the pushed notices; «Retry» button on the error.
- Development: `cd apps/tandem-ui && pnpm install && pnpm tauri dev` (on Linux `libwebkit2gtk-4.1-dev` is needed).
- Screenshots: `docs/screenshots/T-040-connected.png` and `docs/screenshots/T-040-no-agent.png` (frontend in Chrome with the Tauri bridge simulated).
