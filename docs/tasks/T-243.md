# T-243 — The T-223 Network notices: no file editing, same warning pattern as the rest

## Context

Finding of the acceptance agent (part A, round 4, `docs/reports/acceptance-2026-11-19-a4.md`), rules D4 ("all configuration from the UI; `tandem.toml` remains as storage, not as an interface"), G10 and G4/G5.

T-223 added two notices to the Network screen (`crates/tandem-link/src/metrics/notices.rs`, drawn by `apps/tandem-ui/src/screens/Network.svelte`). Rendered in the demo build with the exact texts `link_notices` builds (`?demo#/network`, notices injected; harness `docs/reports/acceptance/2026-11-19-a4/harness/sweep.ts`, case `new:network-notices`):

> **Ethernet path**
> 169.254.252.182:47770 also reaches the Ethernet path; only [fe80::2%3]:47770 is used. Remove the extra peer from [network] in tandem.toml to silence this.
>
> **Link manager**
> not running, so there is no link with the other machine: invalid configuration: the port cannot be 0

Screenshots: `docs/reports/acceptance/2026-11-19-a4/new-screens/network-notices.png` and `network-notices-win-win.png`. `V3-Network` does not draw a notice, so there is no mockup to diff against; the problems are of meaning and pattern:

1. **D4 / G10:** the first notice asks the user to edit `tandem.toml` by hand. Nothing else in the app does that, and there is no UI to edit `[network]` peers.
2. **Wrong advice:** `relabel_with_shadowed` keeps the first candidate in order, "so a declared peer beats a discovered one" (T-223 notes). When the left-out address is a discovered (mDNS) candidate, it is not in `[network]` at all, and the advice cannot be followed.
3. **Nothing to do, but it is shown as trouble:** Tandem already keeps one path per kind and ignores the extra address; the user loses nothing. The States rule (`V3-States`) is "what happened, what Tandem did on its own and what you can do"; this notice turns a handled condition into a to-do.
4. **Pattern:** the box (`section.notice`, amber border, no icon) is a one-off. Every other warning in the app carries an icon (`StateCard`, the tray `.warn` with `Icon name="warn"`, the toasts). The "Link manager" message also starts in lower case after the bold label.

## Expected fix

- Shadowed candidates: say what Tandem did, without a file instruction, for example "Two addresses reach PC-Desktop over Ethernet. Tandem uses [fe80::2%3]:47770 and ignores 169.254.252.182:47770." Or drop the notice and keep only the log warning (the user cannot act on it). Pick one and record it in `docs/DECISIONS.md`.
- Link manager not running: a sentence that starts with a capital ("The link manager is not running, so there is no link with the other machine: …"), and the same trouble look as the other warnings.
- Draw the Network notices with the app's warning pattern (icon plus text, the same tokens as `StateCard` or the tray warning) instead of the bare bordered box.
- Unit tests for the new texts in `metrics/notices.rs`, and a UI test that the notice shows an icon and no `tandem.toml`.

## Acceptance criteria

- [ ] No visible text in the app tells the user to edit `tandem.toml` (`git grep -n "tandem.toml" -- crates/*/src apps/tandem-ui/src` finds no user-facing string asking for it).
- [ ] The shadowed-candidate case says what Tandem did (or is not shown), and is correct for both declared and discovered candidates.
- [ ] The Network notices use the app's warning pattern, with an icon; messages start with a capital.
- [ ] Tests updated; quality gate and CI green.
