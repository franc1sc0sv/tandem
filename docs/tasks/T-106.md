# T-106 — Files and ports

## Context

DESIGN §8. It is also the foundation of `tandem-files` (T-121).

## Scope

1. `tandem-files` crate: transfer of files and folders in 1 MiB chunks with BLAKE3 per chunk and of the total, resumable after a cut, permissions and dates preserved where the system allows, paths normalized between Windows and Unix.
2. `files_put { tunnel, local, remote }` and `files_get` over the data channel (T-101), with progress.
3. `port_forward { tunnel, local_port, remote_host, remote_port, direction }`: TCP in both directions, several simultaneous connections, closes with the tunnel.

## Acceptance criteria

- [x] Property test: any file tree (including empty files, binaries, names with spaces and accents) arrives identical; cut at any chunk and resumption without repeating what was already received.
- [x] Port forward with a TCP echo server in both directions and 20 connections at once.
- [x] Quality gate and CI green.

## Notes

Done:

- Review of #93: the manifest (`Put`/`ManifestHead` + `Entries`) and the plan (`Plan { needs, last }`) travel in pages of at most 256 KiB (`page_entries`, `page_needs`), so a tree of tens of thousands of files fits; an entry that alone does not fit in a frame gives `FilesError::TooLarge`, with no retry. `MemPath` now rejects messages larger than `MAX_FRAME_LEN`, like the wire. `Sink` no longer breaks a complete file because of an old `.tandem-part` and strips setuid/setgid/sticky (`& 0o777`); the target limits ports' `pending` to `MAX_CONNS` per tunnel.
- `tandem-proto::files` (protocol v31, after T-128 v30): requests `TunnelUp::Files(FilesUp)` / `TunnelUp::Port(PortUp)` and their responses, manifest with BLAKE3 per chunk and of the total, `UiCommand::{FilesPut, FilesGet, PortForward, StopForward}`, `Reply::{Files, Forward}` and `AgentToUi::Transfer` (progress). A message does not exceed 1 MiB (`MAX_FRAME_LEN`), so a 1 MiB chunk travels in pieces of 256 KiB (`PIECE`).
- `tandem-files` crate (portable; only `std::fs`, with permissions and dates through `cfg(unix)` and best effort):
  - `path`: wire path with `/`, without `.`/`..`; the receiver rejects what its system does not store (Windows: `:`, `\`, `?`, reserved names, trailing dot or space).
  - `Source` (manifest and chunk reading) and `Sink` (validates the other machine's manifest, plan, verified writing to `<file>.tandem-part`, total hash, rename, permissions and dates; folders at the end). Symbolic links are skipped.
  - Resumption: there are no per-chunk acknowledgements. After a cut, `Put` asks for the plan again and the target compares the per-chunk hash on disk, so only those that do not match are missing (a chunk of zeros in a preallocated file counts as present: it is already what it should be). `put`/`get` retry by themselves (`Options::attempts`) over whatever link there is.
  - `ports`: one stream per direction and per connection (`Send` only origin to target, `Recv` only the other way), so as not to wait for two things on the same stream. `LocalToRemote` (like `ssh -L`) and `RemoteToLocal` (`-R`: the target announces each connection with `Incoming`; a `Beat` heartbeat every 2 s detects that the origin left). Up to 32 simultaneous connections per forward. They are released with the tunnel (`Resource` on the target; the origin polls the tunnel every 250 ms) or with `StopForward`. A `RemoteToLocal` forward does not survive a link cut (it is requested again); `LocalToRemote` does, because each connection opens its streams over the active link.
  - `Files`: what the agent hangs; `serve` distributes `Files`/`Port` and leaves the rest to `tandem_tunnel::serve_request`. `mem::MemPath`: in-memory paths that are cut after N pieces.
- `tandem-tunnel`: `serve_request` (separates reading the request from handling it), `Origin::dial` and `Origin::is_open`, `OriginWire::start_data`.
- `tandemd`: `Agent::files()`, `QuicOrigin` with data mode like `QuicTarget` (files and ports go with data priority and cap, T-101, in both directions); in the IPC the copies run in their own connection task and send `AgentToUi::Transfer`; only a client requests them (the UI receives `Rejected`).
- Tests: properties of identical tree and of cut/resumption (upload and download, without repeating what was received), TCP echo with 20 connections in both directions, closing the tunnel releases the ports, and `crates/tandemd/tests/files.rs` with two real agents over QUIC (2.5 MB folder round trip, progress, ports).

For other tasks: `files_put`, `files_get` and `port_forward` as MCP and CLI tools (T-108, over these `UiCommand`s); T-121 reuses `Source` and `Sink`.
