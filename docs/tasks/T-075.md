# T-075 — End-to-end test with two real tandemd processes

## Scope

Integration test that launches two `tandemd` processes (compiled binary) with temporary configs and data directories, paired through pre-provisioned trust files, on loopback, with simulated backends that can be enabled only in tests (feature or `--sim-backends` flag). An IPC client changes mode and checks the state in both processes. Runs in Linux CI.

## Acceptance criteria

- [x] The test launches the two binaries, switches Mac only → Shared → Windows only → power off, and checks state and events.
- [x] Killing a process in the middle of a change leaves the other in a consistent state and reports it.

## Notes

- Feature `sim-backends` in `tandemd` (`src/sim.rs` and the `--sim-backends` option, which does not appear in the help and does not go with `--install`/`--check-config`). It is enabled by `tandemd`'s `[dev-dependencies]` on itself: the binary the tests launch has it and the distributed one does not.
- With `--sim-backends`: simulated steps recorded in `<data>/sim-steps.jsonl`, held back while `<data>/sim-hold` exists; no mDNS and no input engine.
- `tests/two_processes.rs` (Linux only): Mac only → Shared → Windows only → power off with the notices of each step, the state equal in both processes and saved in both after the orderly power off (SIGTERM). Killing the PC (SIGKILL) with an input change half done: the Mac reports `Inconsistent` (it could not return the input), takes the PC as off (`PcLost`), is left with no link and everything on the Mac, and accepts the next change. Killing the Mac in the middle of a step on the PC: the PC reports the link down and stays with the last confirmed state; the Mac restarts with that same state and carries on.
