# T-331 — Start a loaded `tandemd` that has no process

## Context

Seen on a real Mac with Tandem v0.3.0 (launchd and unified log evidence, not a hypothesis):

- `tandemd` exited with code 0: AppKit closed it on a Quit AppleEvent sent by System Settings ("Quit & Reopen" after granting a permission). That exit is fixed in `tandemd` separately.
- The LaunchAgent (`launch_agent::plist`) has `KeepAlive { SuccessfulExit = false }`, so launchd did not relaunch it. `launchctl print gui/<uid>/com.franc1sc0sv.tandem.tandemd` said `state = not running`, `last exit code = 0`.
- Opening the app calls `launch_agent::ensure()`: the plist was up to date and `is_loaded(LABEL)` was true, so it returned `Outcome::Unchanged` and did nothing. The window stayed forever on "tandemd is not running: nobody is listening on the local IPC".
- `launchctl kickstart -k gui/<uid>/com.franc1sc0sv.tandem.tandemd` brought it back.

## Fix

- `Launchd::is_running(label)`: loaded and with a live process. The real one runs `launchctl print gui/<uid>/<label>` and reads it with the portable `print_says_running` (only the job's own lines, one tab deep: `state = running` or `pid = <n>`).
- `ensure()`: plist up to date + loaded + not running → `kickstart` and the new `Outcome::Restarted`.
- While the app is open: `revive()` (loaded and not running → `kickstart`; not loaded → nothing, that is `ensure()`'s job) behind `ReviveGate`. The session's connect closure (`app::start_session`) feeds each attempt to the gate: only NotFound / ConnectionRefused (`status::nobody_listening`) count as misses; after `REVIVE_AFTER_MISSES` (3, about 6 s at `RETRY_EVERY`) misses in a row it asks launchd, and never more often than `THROTTLE_SECS` (30 s, the plist's `ThrottleInterval`), so a `tandemd` that dies on start is never kickstarted in a loop. `session.rs` stays transport-generic and untouched.

## Acceptance criteria

- [x] Failing test first with the existing `FakeLaunchd`: `up_to_date_and_loaded_but_not_running_is_kickstarted` (failed with `Unchanged`, passes with `Restarted`).
- [x] `print_says_running` tested with real `launchctl print` output: `print_of_a_running_job_says_running` (`state = running … pid = 92836`) and `print_of_an_exited_job_says_not_running` (`state = not running … last exit code = 0`, nested blocks ignored).
- [x] `revive_starts_only_a_loaded_job_without_a_process`, `revive_gate_waits_for_misses_in_a_row`, `revive_gate_never_asks_more_often_than_the_throttle`, `only_a_missing_listener_counts_as_nobody_listening`.
- [x] Quality gate (`fmt`, `clippy -D warnings`, `cargo test --workspace`) passes.

## Notes

- `kickstart -k` during launchd's own throttle wait (`state = spawn scheduled`) only shortens that wait; the gate keeps such calls to one per `THROTTLE_SECS`.
- T-332 changes `KeepAlive` so launchd itself relaunches on exit 0; this task stays as the safety net for a job left without a process for any other reason.
