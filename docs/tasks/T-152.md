# T-152 — "Leave desk" leaves the other machine paired

Found by the acceptance agent (part B), flow F12 (Settings) and D1.

## What fails

Settings → Desk and machines → "Leave desk" says "This machine forgets the other machines' keys **and they forget theirs**", and the setup's "Your desk" step says "You can remove it later from any machine". With two real agents, after "Leave → Confirm" on machine A:

- A becomes `unpaired` and empties its trust.
- B **stays `paired`** (without a link) and keeps `trust.toml` with A's key, 20 s later and beyond (it waited up to 20 s; B's Desk still shows A as paired and "off").

This is the behavior pinned by the `unpairing_from_the_ui` test (`crates/tandemd/tests/pairing.rs`: "The Mac still trusts the PC"), but it contradicts the UI text and leaves B trusting a key that A no longer uses until B also does "Leave".

## Expected fix

Decide and write down (DECISIONS) one of two, and make the UI and the agent match:

1. The agent that leaves notifies the other over the link (if connected) so that it also forgets the key and is left without a peer; if there is no link, the other does it on seeing the notice as soon as it reconnects (or on trying to connect with a key that is no longer valid).
2. Or the UI text tells the truth ("the other machine keeps trusting this one until it leaves too") and its Desk shows it as such.

## Acceptance criteria

- [x] After "Leave desk", the other machine ends up `unpaired` or the UI of both says it exactly.
- [x] Two-agent test (online and with the other disconnected).
- [x] Quality gate and CI green.

## Notes

After "Leave desk" the other machine also forgets the key if there is a link (`ControlMsg::Unpaired`); without a link, the UI text says so. Two-agent tests: `unpairing_from_the_ui` (online: the other is left without a peer) and `unpairing_with_the_other_machine_offline` (no link: it leaves without error and there is no pending state, see DECISIONS).

Without a link: on reconnecting, if the other rejects it because of an untrusted key, it becomes `Unpaired` by itself (test `a_peer_that_still_trusts_us_unpairs_when_rejected_on_reconnect`).
