# T-096 — Live UI

## Context

User's request (2026-11-15): a more dynamic app. Design in `docs/DESIGN.md` §10 and mockup `mockups/next.html`.

## Scope

1. **Live link** between the two cards: active type (USB-C, Ethernet, Wi-Fi), speed, RTT and T-093's input p50/p99 latency; the line's pulse follows real traffic (events per second), not a fixed animation.
2. **Live cursor:** mini arrangement of the two machines' screens with a dot that follows the focus (position sampled at 30 Hz over IPC, only with the window visible) and a flash on the edge when crossing.
3. **Screen arrangement:** editor with draggable rectangles per machine (size, scale, position), with snapping to edges; saves to `[[screens]]` and syncs through `Desk`.
4. **Monitors and modes disabled** with the caption "Coming soon: custom firmware" (from T-092), without interaction.
5. Animations respecting `prefers-reduced-motion`.
6. **Arrangement step in the wizard** (DESIGN §5), before the summary: the editor from point 3 with the default value and the "Test crossing" button. The test asks to take the mouse to the other machine through the edge the arrangement says; it passes when tandemd reports through `CursorSample` that the focus crossed to the other machine through that edge, and if it does not arrive in 20 s it offers to go back to the editor.
7. **Agent:** new IPC events with explicit subscription: `InputActivity` (events/s and machine with the focus, 2 Hz) and `CursorSample` (position in the arrangement, 30 Hz), which tandemd only emits while a UI is subscribed; the UI unsubscribes when the window is hidden (`visibilitychange`). Tests in `tandemd/tests/ipc.rs`.

## Acceptance criteria

- [ ] Vitest tests for the arrangement editor (snapping, no overlaps, round trip to `[[screens]]`) and for the pulse calculation.
- [ ] Demo mode with simulated data for the three pieces; screenshots of the demo.
- [ ] With the window hidden there is no sampling: an IPC test that checks that after unsubscribing no `CursorSample` arrives, and a vitest test that the unsubscription happens on `visibilitychange`.
- [ ] Wizard arrangement step with a vitest test (`onboarding`: passes with a crossing `CursorSample` through the expected edge, fails through another edge or with no crossing in 20 s) and in `tandemd/tests/wizard.rs` (the agent emits the crossing with the edge).
- [ ] `pnpm test` and `pnpm build` green; CI green.
