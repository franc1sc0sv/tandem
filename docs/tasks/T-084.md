# T-084 — Symmetric P2P: per-machine capabilities and shared desk

## Context

Real test of 2026-10-16 (user's screenshot on the PC): the app running **on** the PC showed the PC as "off", both monitors on the Mac and "Keyboard here" on the Mac. The design had ended up centered on the Mac (`State::initial` = everything on the Mac and `pc_on = false`; `pc_watch` and Wake-on-LAN only from the Mac; "server/client" texts). The user asks for real peer-to-peer: either machine can be the main one, there is no fixed server, and each machine lists what it has and what it can do.

## Scope

1. **Capabilities:** on connecting, each agent publishes a capabilities announcement over the control plane (tandem-proto, versioned): machine name and OS; monitors it sees with EDID/PnP id and whether it can switch them over DDC; built-in screen; whether it has the hub's keyboard/mouse; capture and injection permissions (macOS); power (can wake the other through WoL / can be woken / can shut down cleanly); available data-plane services. It is re-announced on change.
2. **The UI is drawn from those capabilities:** "this machine" card (always on) and "the other" (with its link state), with no Mac-left/PC-right written in the code; actions enabled only if some machine has the capability (e.g. switching a monitor over DDC asks whoever can).
3. **No fixed center:** power/cut watching (`pc_watch`) becomes symmetric (watch the peer, whichever it is), Wake-on-LAN from whoever can toward whoever can be woken, the orchestrator keeps accepting changes from either machine.
4. **Keyboard and mouse:** remove "server/client" from the UI and from user-facing texts; the role is "where the keyboard is" and the hub decides it (T-029/T-066) in either direction. Internally it can keep being called source/sink.
5. **Shared desk** (what was T-083): on pairing and on each reconnection, the two machines sync the desk's config (monitors, DDC profiles, wiring, shortcuts) with a version and a logical clock; a change made in either UI is replicated on the other and saved in its `tandem.toml`; local-only data (identity, port, paths) is not synced. The Mac, which does not see the EDIDs of monitors that are only on the PC, completes its config with what the PC announces (T-082).
6. **The desk's state (`State`) stops assuming a perspective:** the local machine is never "off" to itself; the peer's state comes from the links and its announcement.

## Acceptance criteria

- [x] tandem-sim: with the PC as "main" (the user uses the PC and the Mac sleeps/powers off), the modes, the power watching and the keyboard work the same as in the opposite direction (mirror scenarios of the existing ones).
- [x] An agent running on the PC never shows the PC as off (UI test in demo mode with PC perspective, with screenshot in the PR).
- [x] Changing a monitor's wiring in the Mac's UI shows up in the PC's config and vice versa (test with two agents on loopback).
- [x] No user-facing text says "server" or "client" for the keyboard/mouse.
- [x] Compatibility: an agent without a capabilities announcement (earlier version) is rejected with a clear version error.

## Notes

- **Core** (`tandem-core`): `State.on: Powered { mac, pc }` replaces `pc_on` (an old `state.json` with `pc_on` is still read: `on` comes from the links). `State::initial(cfg, me)`: `me` on, the other off; the initial assignment is still "everything on the Mac" until T-085 asks for it to be confirmed. Steps `PowerOn { machine }` / `PowerOff { machine }` and `SwitchInput { .., by }` (who switches the input). `Abilities` (who switches each monitor, who can be woken) goes into `Plan::to_mode`, `Plan::power_off(cfg, from, machine, ..)` and `Plan::power_on`; the plan powers on each machine that is going to show something or that switches an input, and does not touch the desktop or built-in screen of a machine that stays off. New errors: `NoSwitcher`, `CannotWake`. The core's properties generate states from both perspectives.
- **Protocol v10** (T-082 already used v9): `ControlMsg::Capabilities(Capabilities)` and `ControlMsg::Desk(DeskSync)`; `UiCommand::SetPower { machine, on }` (formerly `SetPcPower`) and `GetCapabilities`; `Reply`/`AgentToUi::Capabilities(DeskCapabilities { here, peer })`; `PowerEvent::PeerLost { machine, .. }` (formerly `PcLost`). `CAPABILITIES_SINCE = 10`: an earlier `Hello` is rejected with "incompatible protocol version … (an earlier version, without a capabilities announcement): install the same version of Tandem on both machines", and the agent leaves it in the log as a warning.
- **Capabilities** (`tandemd::capabilities`): the only system-dependent things are per-capability functions (`switches_inputs`, `has_builtin`, `powers_off`); today the PC switches inputs (dxva2) and powers itself off, the Mac has a built-in screen. `[power] wakeable` (`true` by default) is what the machine announces about itself; `[power.wol]` on either one serves to wake the other. With no announcement from the other, `abilities` assumes it can do what this one cannot (switch the inputs this one does not switch, be woken); if it is wrong, the step fails with its reason and is undone. The announcement goes in `Agent::set_peer` (each new link) and is repeated when the hub, the permissions or the desk change. Waking takes two: the other enters `Abilities::wakeable` only if this one announces `wake_peer` (it has `[power.wol]`) and the other `wakeable`; without `[power.wol]` the plan gives `CannotWake` and the UI does not show "Power on the …". The announced monitors are those the agent detects at startup (`autoconfig::platform_scan` in `main.rs`, only once, shared with the generation of `tandem.toml`; `autoconfig::seen` → `Agent::set_seen_monitors`), tied to the desk by PnP id or EDID model. Those of the desk wired to this machine that were not detected are added (with the other's input selected, the system may not see them); one that is not wired here is never announced as switchable from here. Without detection (Linux, `--sim-backends`, a backend that failed) the desk's are announced. Detection is only at startup: a monitor that is connected later is seen when the agent restarts.
- **No fixed center:** `pc_watch` became `peer_watch` and runs on both (`peer_lost_after_secs`, with `pc_lost_after_secs` as an alias). Taking it as on when it reappears no longer reserves the orchestrator (its first step could be rejected); it only waits until no change is in progress. The geometry (`Target::Both`) is only done on machines that are on. The keyboard arbiter takes the other as off in both directions. `[input] keyboard` replaces `server` (which remains valid).
- **Shared desk** (`tandemd::desk_sync`): `DeskSync { rev, origin, desk, lock_shortcut }`. A local change (wiring from the UI, learned DDC profile) raises `rev`; the newest wins and a tie is resolved by the origin; two freshly generated desks (`rev = 0`) merge the same from both sides (the PC's and then those only the Mac has). What is adopted enters live (`LiveDesk::replace`) and is written to `tandem.toml` with `config_edit::with_desk`: `[[monitors]]` in place (keeps comments), `[input] lock_shortcut`, `desk_rev` and `desk_origin`; machine, network and power are not touched. The synced lock shortcut takes effect from the agent's next startup.
- **UI:** the scene has two cards, "this machine" on the left (always "this machine") and "the other" on the right (on / starting / off); the built-in screen goes on the card of the one that announces it and the power button on the other's, visible only if it can be woken or knows how to shut down. A monitor can only be moved if someone can switch its input. The keyboard chip says "Keyboard here", "Has the keyboard" or "PC's/Mac's keyboard". The tray's mini scene and its menu ("Windows only · Mac off" on the PC) follow the same perspective. Demo mode: `/?demo&as=pc` (the PC's window, Mac asleep) and `&mac=on`.
- **Tests:** `tandem-sim/tests/mirror.rs` (walkthrough, the Mac also orchestrates, failure and timeout at each step, Mac suspend in Shared, brief drop, requested power off, manual wake, all with the PC as main), keyboard mirrors in `tandem-sim/tests/hub.rs`, `peer_watch` with each test from both machines, `tandemd/tests/network.rs` (`wiring_changed_on_either_machine_reaches_the_other`, `a_change_made_while_the_other_was_away_arrives_on_reconnect`), `desk_sync` (with a convergence property), `config_edit::with_desk`, `capabilities`, the version in `tandem-proto` and `tandem-link/tests/transport.rs`, and the frontend (`scene.test.ts`: the agent's machine never off, no text with server/client, power button by capability).
- Screenshots (the PC window with the Mac asleep, the Mac awake receiving the PC's keyboard, and the usual one from the Mac): removed later because they showed the retired Spanish UI; see git history.
