## Scope

1. Rust workspace in `monitor-firmware/crates/monitor-ddc` (and root `Cargo.toml` if needed), 2024 edition, `thiserror`, no `unwrap` outside tests.
2. `DdcBus` trait: enumerate monitors (handle, EDID), `get_vcp`, `set_vcp`, capabilities. Backends: Windows (`dxva2` + EDID through SetupAPI), macOS Apple Silicon (private `IOAVService`, behind `#[cfg]`, with "no channel" handling). `FakeMonitor` double with personalities: `standard` (firmware v3: `0xEA` protocol 2, events, verdicts, real `0x60`), `factory` (`0x60` repeats the port asked, no `0xEA`), `disconnected`.
3. **Probe with reads only** (`Get 0xEA`): compatible / not compatible. Never a manufacturer code before confirming compatibility.
4. Standard protocol: live state (`0xEE`), event reading with cursor (`0xEB`–`0xED`), input switch (`Set 0x60`) that waits for the `switch-done`/`switch-failed` verdict with a maximum time.
5. Identity: `<model>-<short hash of the EDID serial>` (never the serial in the clear); links DP and HDMI.
6. Rust CI in that repo (Linux + Windows + macOS: fmt, clippy -D warnings, test).
7. In Tandem, only update this task's note with the commit to pin.
