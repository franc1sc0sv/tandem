## Scope

1. Workspace de Rust en `monitor-firmware/crates/monitor-ddc` (y `Cargo.toml` raíz si hace falta), edición 2024, `thiserror`, sin `unwrap` fuera de pruebas.
2. Trait `DdcBus`: enumerar monitores (handle, EDID), `get_vcp`, `set_vcp`, capacidades. Backends: Windows (`dxva2` + EDID por SetupAPI), macOS Apple Silicon (`IOAVService` privado, detrás de `#[cfg]`, con manejo de «sin canal»). Doble `FakeMonitor` con personalidades: `estándar` (firmware v3: `0xEA` protocolo 2, eventos, veredictos, `0x60` real), `fábrica` (`0x60` repite el puerto preguntado, sin `0xEA`), `desconectado`.
3. **Sondeo solo con lecturas** (`Get 0xEA`): compatible / no compatible. Nunca un código de fabricante antes de confirmar compatibilidad.
4. Protocolo estándar: estado en vivo (`0xEE`), lectura de eventos con cursor (`0xEB`–`0xED`), cambio de entrada (`Set 0x60`) que espera el veredicto `switch-done`/`switch-failed` con tiempo máximo.
5. Identidad: `<modelo>-<hash corto del serial del EDID>` (nunca el serial en claro); vincula DP y HDMI.
6. CI de Rust en ese repo (Linux + Windows + macOS: fmt, clippy -D warnings, test).
7. En Tandem, solo actualizar la nota de esta tarea con el commit a fijar.
