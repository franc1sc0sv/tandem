# T-060 — Desk simulation harness (tandem-sim)

## Scope

Crate `tandem-sim` (tests only): starts two agents in the same process over loopback with simulated backends for screens (monitors with inputs and the 34"'s "always reports 0x09" rule), input, power (PC off/on) and peripherals. `FaultPlan` to inject failures at any step, timeouts and link drops.

## Acceptance criteria

- [x] Scenarios: Mac only → Shared → Windows only → power off; failure at each step with verified rollback; drop of the preferred link in the middle of a mode.
- [x] All with a paused tokio clock, no real sleeps.
- [x] docs/TESTING.md documents how to add a scenario.

## Notes

- Crate `tandem-sim` (`publish = false`): `Desk` assembles two real `tandemd` instances (orchestrator, `tandem-link` link manager and the real control protocol over in-memory streams) with a simulated physical desk (`World`), a network with one link per type that can be cut (`SimNet`) and a `FaultPlan`. Details and how to add scenarios in `docs/TESTING.md`.
- Scenarios (`crates/tandem-sim/tests/scenarios.rs`): walkthrough Mac only → Shared (with Wake-on-LAN and boot) → Windows only → power off; the 34" that always reads `0x09`; the PC orchestrating; failure (`Fail`) and timeout (`Hang`) at each step of each machine across the three legs, with rollback verified against the physical desk (monitors, desktops, built-in screen, geometry) and the PC agent in agreement; USB4 drop between steps (continues over Ethernet and is applied), USB4 drop with the response in flight (rolls back over Ethernet) and Wi-Fi only.
- Power off is run by building `Plan::shutdown_pc` in the Mac's orchestrator (`Desk::shutdown_pc`): the UI does not yet have a request to power off.
- Bugs found by the harness (failing test first, then the fix):
  - **Uncertain step not undone** (`tandemd::orchestrator`): if a step timed out or the connection was cut, it may have been done anyway (the response was lost), but rollback only undid the confirmed steps. Real case: the PC adds the 32" to its desktop, USB4 drops before the response and the PC is left with a phantom 32". Now the orchestrator also undoes the uncertain step before the others (steps are idempotent); if that fails, the result is `Inconsistent`.
  - **Stale geometry after rollback** (`tandem_core::run`): the inverse of `UpdateInputGeometry` ran in its place in the list, with the monitors still in the new layout, and if the failing step was the geometry (done on one machine and not on the other) it was not recalculated. Now rollback recalculates it once, at the end.
- Out of scope (for T-062): if the PC takes more than 120 s to boot, power on times out and is undone, but the PC finishes booting anyway and the agent thinks it is off; the two agents serve each stream separately, so a step requested over a dropped link and its inverse requested over another have no guaranteed order on the PC if the first is still in progress.
