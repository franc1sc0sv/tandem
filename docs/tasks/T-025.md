# T-025 — Input injection on Windows

## Scope

`tandem-input::windows::emulate`: SendInput with scancodes and extended keys, absolute VIRTUALDESK mouse with fraction accumulation, high-resolution wheel, `dwExtraInfo` mark.

## Acceptance criteria

- [x] Compiles for windows-gnu and on windows CI.
- [x] Test on the PC documented.

## Notes

- The `InputEvent` → `INPUT` translation is portable (`Emulator` + `InputSink` trait, with a double in the tests); only `SendInputSink` goes under `#[cfg(windows)]`. A test on Windows checks that the winuser.h constants repeated in portable code match those of the `windows` crate.
- Pause is injected by virtual key code (`VK_PAUSE`): its real scancode is the sequence E1 1D 45 and the bare `0x45` from Chromium's Windows table takes it as Num Lock.
- The cursor position is kept in `f64` and clamped to the nearest monitor (not to the virtual rectangle), so as not to get lost in the gaps between monitors of different sizes. If the real cursor is not where it was left (the local mouse moved it), the next relative movement starts from there.
- Pixel scroll (the Mac's trackpad) → wheel with `PIXELS_PER_NOTCH = 100` px per notch, accumulating the remainders.
- `TANDEM_EXTRA_INFO` (`windows::TANDEM_EXTRA_INFO`) is left for the capture (T-024) to discard what is injected.
- `SendInputSink::new()` declares the process Per-Monitor-V2 (if it already was, it is not an error).
- The non-ignored tests were also run as a native `.exe` on the PC (26 ok) from WSL.
