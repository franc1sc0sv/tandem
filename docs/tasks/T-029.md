# T-029 — USB hub and automatic roles

## Scope

`tandem-peripherals`: detect the configured keyboard and mouse (VID/PID) on macOS (IOKit) and Windows (SetupAPI/RawInput devices), with a 3 s debounce; on change, the orchestrator swaps server/client. Manual selector that wins over detection.

## Acceptance criteria

- [x] Test of the debounce logic and of the manual selector's priority with simulated detectors.
- [x] Platform implementations compile on CI.

## Notes

- Code in `tandem-peripherals`:
  - `UsbId` (VID/PID; in the config `"046d:c52b"`) and `HubConfig { keyboard, mouse }`, which deserializes from TOML to be embedded in `tandem.toml`.
  - `Debouncer<T>` and `HubTracker`: pure debounce (no clock of its own) of 3 s (`DEFAULT_DEBOUNCE`). The first reading is accepted without waiting.
  - `HubWatcher`: polls a `DeviceScanner` every 500 ms and publishes the stable `Presence` in a `watch`. A failed reading is ignored (it does not count as «no hub»). The hub is «here» if the keyboard or the mouse is seen.
  - `RoleArbiter` + `Selector { Auto, Manual(machine) }`: the manual selector always wins. In automatic mode it only decides with the local reading **and** the other agent's report, with the hub on a single machine; if the report is missing (no connection) or the hub is on neither or on both, the server that was there stays. This way the two machines cannot split apart by seeing it differently while they are not talking (property test `both_agents_agree`).
  - Platform: `SystemScanner` = `SetupApiScanner` on Windows (nodes of the `USB` enumerator, VID/PID from the instance identifier) and `IoKitScanner` on macOS (`IOUSBHostDevice`, `idVendor`/`idProduct`, direct FFI to IOKit and CoreFoundation).
- Tests: unit and property tests of the debounce, the parsing and the arbiter; `tests/hub_roles.rs` with two agents and simulated scanners (`fake::FakeScanner`) over a paused tokio clock: moving the hub swaps the roles after 3 s, a short tug does not, and the manual selector rules.
- Still to be wired in `tandemd` (out of scope, like T-026's input session, which is not connected yet): a `[peripherals]` section in `tandem.toml` with `HubConfig`, a control-plane message to report the hub's presence to the other agent (`set_peer_hub`, and `None` when the connection is lost), the UI selector being applied on both agents, and a change of `RoleArbiter::server` starting `ServerDriver` or `ClientDriver`.
- Known race: if the hub changes on both machines within the report's latency (milliseconds, versus 3 s of debounce), each one decides with the latest it knew; they converge as soon as the hub is on a single machine.

## Pending hardware verification

- [ ] Windows: with the hub connected, `SetupApiScanner` lists the keyboard's and the mouse's VID/PID; when disconnected, they disappear.
- [ ] macOS: the same with `IoKitScanner` (including a wireless receiver in the hub, if one is used).
- [ ] Moving the hub from one machine to the other swaps the roles about 3 s later, without reacting to a brief tug on the cable.
