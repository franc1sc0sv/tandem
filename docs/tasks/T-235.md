# T-235 — Race in `a_local_setting_moved_to_the_desk_does_not_leave_the_machines_apart`

## Context

Failure found by the acceptance agent, part C, round 3 (2026-11-19, `origin/develop` bbdc245). See `docs/reports/acceptance-2026-11-18-c3.md`.

## Failure

G11. The commit quality gate (`cargo test --workspace`, full parallel run) failed once on a clean `develop` checkout:

```
test a_local_setting_moved_to_the_desk_does_not_leave_the_machines_apart ... FAILED
panicked at crates/tandemd/tests/network.rs:828:5:
assertion `left == right` failed
  left: None
 right: Some(false)
```

In isolation it passes (6 of 6 runs, ~1.2 s). Likely cause: both agents start from `before_t099` with the same `desk_rev = 3` and `desk_sum`, so `until_same_desk(&a, &b)` is already true at the start, before the migration of `[input] clipboard = false` into `[modules.b] clipboard` has been merged. The assertion that follows then reads the desk before the merge.

## Expected fix

Wait for the condition the test asserts (`modules.get(Machine::B, "clipboard") == Some(false)` on both agents, and in the saved file) instead of `until_same_desk`, which cannot tell the initial equal state from the converged one. Check the other tests that start from equal revisions for the same pattern.

## Acceptance criteria

- [ ] The race is reproduced (a controlled delay or a loop under CPU load) before the fix.
- [ ] The test waits for the asserted state and passes 200 consecutive runs under load.
- [ ] No other test in `crates/tandemd/tests` uses `until_same_desk` as a guard for a change that is already equal at the start.
- [ ] Quality gate and CI green.
