# T-235 — Race in `a_local_setting_moved_to_the_desk_does_not_leave_the_machines_apart`

## Context

Failure found by the acceptance agent, part C, round 3 (2026-11-19, `origin/develop` bbdc245). See `docs/reports/acceptance-2026-11-18-c3.md`.

## Failure

G11. The commit quality gate (`cargo test --workspace`, full parallel run) failed once on a clean `develop` checkout:

```
test a_local_setting_moved_to_the_desk_does_not_leave_the_machines_apart ... FAILED
panicked at crates/tandemd/tests/network.rs:828:5:
assertion `left == right` failed
  left: None
 right: Some(false)
```

In isolation it passes (6 of 6 runs, ~1.2 s). Likely cause: both agents start from `before_t099` with the same `desk_rev = 3` and `desk_sum`, so `until_same_desk(&a, &b)` is already true at the start, before the migration of `[input] clipboard = false` into `[modules.b] clipboard` has been merged. The assertion that follows then reads the desk before the merge.

## Expected fix

Wait for the condition the test asserts (`modules.get(Machine::B, "clipboard") == Some(false)` on both agents, and in the saved file) instead of `until_same_desk`, which cannot tell the initial equal state from the converged one. Check the other tests that start from equal revisions for the same pattern.

## Acceptance criteria

- [x] The race is reproduced (a controlled delay or a loop under CPU load) before the fix.
- [x] The test waits for the asserted state and passes 200 consecutive runs under load.
- [x] No other test in `crates/tandemd/tests` uses `until_same_desk` as a guard for a change that is already equal at the start.
- [x] Quality gate and CI green.

## Notes

Closed in branch `task/T-230`.

**Cause (confirmed by instrumenting the test; 2 of 80 runs failed under load before the fix):** `until_same_desk` caught an equal state that was real but did not last. When the test started waiting, A had committed version 4 (by A, from `learn_machines`) without the migrated clipboard, and B was halfway through adopting it. B's `desk_sync()` already returned stamp `(4, A)` but still the old desk with `clipboard = false`, because the stamp and the desk are read separately. A few milliseconds later both held `(4, A)` with no clipboard, so they counted as "the same desk". Only after that did B's migrated setting come back and spread to both. The assertion read that intermediate state.

**Fix:** the test waits (`subscribe_desk().wait_for`) until both agents have `modules.b.clipboard == false`, then for the desks to match. Only then does it check the saved file, which is written before the desk is published.

**Evidence:** before the fix, 2/60 and 2/80 failures (the `network` test alone, 8 `yes` processes, `taskset -c 0,1`). After it, 0/200 under the same load and 0 failures in run 44442801041 (all `tandemd` tests 20 times per OS).

**Other tests:** the other two `until_same_desk` calls in `network.rs` come after edits that make the desks differ when the wait starts, and the version they converge on is final. They do not have this race.

Side note, not fixed here: `Agent::desk_sync()` reads the stamp and the desk non-atomically, so during `receive_desk` a reader can see the new stamp with the old desk. That did not cause this failure by itself, but it makes "same desk" checks less reliable.
