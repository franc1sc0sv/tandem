# T-121 — Drag files between machines

## Context

DECISIONS D14; DESIGN §9 (spike S13).

## Scope

1. Detect on the source machine a file drag in progress on reaching the edge (macOS: `NSPasteboard(name: .drag)`; Windows: state of OLE drag-drop / active `DoDragDrop` via hook) — behind a trait with a double.
2. Allow the crossing with a button pressed only in that case (even if "Drag between machines" is turned off).
3. Transfer with `tandem-files` to a temporary folder on the destination while the cursor travels; on the destination start a synthetic drag with those files (macOS: `NSDraggingSession` from an invisible window of the agent/UI; Windows: `DoDragDrop` with a file `IDataObject`) so the system does the copy on drop.
4. Cancellation (Esc or drop outside): delete what was transferred. Notice with progress in the UI.

## Acceptance criteria

- [x] Tests with doubles of the whole flow (detect → transfer → drag on destination → drop/cancel).
- [x] Quality gate and CI green.

## Pending hardware verification

- [ ] Drag a file from Finder to Windows Explorer and the other way around.
- [ ] Windows destination: `DoDragDrop` with the shell's `IDataObject` (CF_HDROP) allows dropping onto Explorer and apps, and Esc cancels and deletes the temporary folder.
- [ ] macOS destination: the invisible window under the cursor starts the `NSDraggingSession` with the synthetic click, and dropping in Finder copies the files.
- [ ] macOS source: `NSPasteboard(name: .drag)` brings the URLs during a real Finder drag (and nothing after dropping).
- [ ] Windows source: the drag target window (`tandem-files::drag_target_windows`, `RegisterDragDrop`, alpha 1/255, `WS_EX_NOACTIVATE`) receives CF_HDROP in `DragEnter` on reaching the edge strip, and lets the drag through to Explorer without stealing focus or accepting the drop. Check that the strip (4 px, the edge of the screens' box that faces the Mac) looks and moves right with several monitors and different DPIs.
- [ ] Crossing with the button held end to end with real files: `follow` turns the flag on when it sees the files, the cursor crosses, it is copied through the tunnel the agent opens (`TunnelUploader`) and the destination starts the drag. With a large file, releasing the button before the copy finishes cancels and deletes what was copied.
- [ ] macOS: `tandemd` runs the agent on a thread and leaves the main one in `NSApplication.run` with the `Accessory` policy (`run_app_loop`); check that `MacDragStarter` gets the main thread through `main_queue`, that no icon appears in the Dock and that input capture (CGEventTap) and the agent's shutdown keep working with that split.
- [ ] Progress notice in the UI with a real transfer.

## Notes

- Portable logic in `tandem-files::drag`: traits `DragDetector` (source), `DragStarter` (destination), `DragPeer` (control) and `Upload` (with `TunnelUpload` over `Files::put`); `DragOut` and `DragIn` carry the flow, the temporary folder and the cleanup.
- `ServerSession::set_file_drag(true)` allows the crossing with a button pressed only for the duration of the file drag, even if "Drag between machines" is turned off.
- Protocol v35: `ControlMsg::Drag(DragMsg)` with `Begin`/`Staged`/`Ready`/`Finished`/`Cancel` (each with the source's `id`) and `AgentToUi::Drag(DragStatus)` for the UI. `tandemd::drag` connects them: `ControlDragPeer` (source), `serve` (destination, already launched on Windows from `daemon::start`) and `run_origin`. Two-agent loopback test in `crates/tandemd/tests/drag.rs` (`start_pair!`): drop, cancel halfway and invalid names.
- Platform: `tandem-files::drag_windows` (`WindowsDragStarter`, own `IDropSource` + `SHCreateDataObject`) and `drag_macos` (`MacDragDetector`, `MacDragStarter` with `NSDraggingSession`). What can be decided goes in `drag_os` with tests (Esc/drop, empty effect, `file://` URL). They are verified with `cargo check --target x86_64-pc-windows-gnu` and `aarch64-apple-darwin`; the macOS CI compiles the second.
- UI: no notice mockup in `mockups/v03`; the short notice of `Toasts.svelte` is reused, a single notice that updates (`lib/drag.ts`, `Store.showDrag`) with vitest tests.
- Windows source: `tandem-files::drag_target_windows::WindowsDropWatcher` (own thread with OLE and the strip window) writes to a `DragProbe` (`drag_os`, portable and with tests) that is read through `DragDetector`. `drag_os::strip_rect` and `tandemd::input::file_drag::edge_target` decide where the strip goes (property tests).
- Wiring: `InputSetup.file_drag: Option<Arc<dyn FileDragBackend>>` (`tandemd::drag`; `SystemFileDrag` builds it with a `DragDetector` and the agent's tunnel, `TunnelUploader`). `input::file_drag::follow` watches while a button is pressed (`ServerDriver::buttons`), turns on the `ServerSession::with_file_drag_flag` flag when it sees files, and when focus moves to the other machine it launches `run_origin`; releasing the button or returning to the edge before the copy finishes cancels. Two-agent tests with `start_pair!` in `crates/tandemd/tests/input.rs` (`mod file_drag`): crossing, `begin`/`staged`, synthetic drag on the destination and `finished`; cancelling by releasing the button halfway through the copy; and without files it does not cross.
- macOS destination: `tandemd` is not the UI (the UI is an IPC client and does not have the `Agent`), so the agent hosts the main thread: `main.rs` runs the agent on another thread and leaves the main one in `drag_macos::run_app_loop`; `drag_macos::main_queue` (GCD main queue) provides the `RunOnMain` and checks the thread with `MainThreadMarker::new()` instead of assuming it (no `unsafe`).
- The protocol version is 35 (develop's, with T-107 and T-094, was 34).
