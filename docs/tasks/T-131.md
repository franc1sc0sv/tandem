# T-131 — Administrator service from the setup

## Context

In step 3 of the setup (F-Asis3, T-119) the "Administrator service" row shows a spinner whenever the `tunnels` module is not active (`apps/tandem-ui/src/lib/wizard.ts`, `foundRows`). With the real agent it is an endless spinner with no action (G6), and the mockup's "Install" button is covered. T-104 already installs the privileged task on Windows only if the launcher is in an administrators-only path (ACL); on macOS the LaunchDaemon is missing. Found in the review of T-119 (#106).

## Scope

1. Real state of the row: `off` / `pending` / `ok` according to what the agent reports; never an endless spinner.
2. Working "Install" button: macOS installs the LaunchDaemon (asks for administrator credentials with the system dialog); Windows registers the elevated task (UAC) with the same ACL checks as T-104. If it does not apply (per-user installation), the row explains it and does not offer the button.
3. Remove the "Install" mask in `shots-spec.ts` and measure against F-Asis3 (≥ 0.99 / ≥ 0.97).

## Notes
- The state is given by the app (`admin_status`: `off` / `pending` / `ok`), not by the agent's module; with no reading the row is `off`, it never spins. `pending` keeps the mockup's spin next to the button and is resolved on installing, cancelling or failing.
- macOS: LaunchDaemon `com.franc1sc0sv.tandem.admin`. The administrator script copies the `.app`'s `tandemd` with `install -o root -g wheel -m 755` to `/Library/PrivilegedHelperTools/` and the plist points to that copy (not to the `.app`'s binary, which a user could replace); before elevating, it is checked (`not_admin_only` with `UnixAcl`) that the source `tandemd` — resolved path, with no links, and its ancestors — and the destination belong to root and are not writable by the user; if not, the row says that the per-user installation does not support the service and the password is not asked for (DECISIONS, 2026-11-18; the release is unsigned, D19). The script rejects a link in `source` before copying. It uses its own `--data-dir` (`/Library/Application Support/Tandem`), via `osascript ... with administrator privileges`. What the daemon does with privileges (protected screens, T-027) is out of scope for this task.
- Windows: `tandemd --install` with UAC after checking the ACL in the app (`not_admin_only`, now public) of the two executables: `tandemd.exe` (the one that gets elevated) and the launcher the task registers (`launcher_for`, the same one the elevated `--install` chooses); if the launcher is writable, the row explains it and does not offer the button.
