# T-128 — Live cursor from the agent

## Context

The Desk (T-113, "live desktops" with the cursor dot at 30 Hz and a flash on crossing) and Arrangement (T-117, crossing test with the real agent) screens consume the cursor position and the edge crossings. Today the agent does not emit them: `CursorSample` does not exist in `tandem-proto` nor in `tandemd`. T-096 (which included it) is blocked and replaced by the v0.3 plan. Found in the review of T-117 (#86).

## Scope

1. Protocol: `AgentToUi::Cursor(CursorSample { machine, screen, x, y })` and `AgentToUi::Crossed { from, to, edge }` (final names at discretion, noted in DECISIONS). Next free protocol version.
2. `tandemd`: the input engine (T-093) publishes samples at most at 30 Hz and every edge crossing, **only while there is a subscription** from the UI (`WatchCursor { on }`), counted per window like T-105's `WatchResources`; with no subscribers there is no cost on the hot path.
3. The sample comes from the side that has focus; if focus is on the other machine, it travels through the control channel (not the input one) and is dropped if it falls behind.
4. Tauri forwards the events to the UI; TS types in the UI model.

## Acceptance criteria

- [x] Two-agent test (loopback, `start_pair!`): with a subscription, B receives samples from A and a `Crossed` on crossing; without a subscription nothing is emitted.
- [x] Test that the frequency never exceeds 30 Hz (proptest over the limiter).
- [x] The input latency measured by T-093 does not get worse with the subscription active (`tandem-sim` bench).
- [x] Quality gate and CI green.

## Notes

- 2026-11-18: the measurement was repeated without the user's hardware (`cargo test -p tandem-sim --release --test latency -- --ignored input_latency_does_not_get_worse_with_the_live_cursor_watched`, it does not need real machines): it passes in both runs (best p99 without the live cursor / with it: 0.47 / 0.50 ms and 3.2 / 2.4 ms). The difference stays within the machine's noise; the cost is structurally zero without a subscription and CI watches for a large regression. That is why the criterion is considered met and no hardware list is left.

- Protocol v30 (v29 belongs to another task in parallel). Names and decisions in `docs/DECISIONS.md`.
- Tests: `tandemd/tests/input.rs::the_live_cursor_flows_only_while_the_ui_watches_and_crosses_between_agents` (two agents, nothing without a subscription, with it samples from the other machine and the crossing, and it turns off when it stops watching), `tandem-input` (`Limiter` with proptest, drivers over QUIC), `tandemd` (lease, per-window count, droppable send) and `tandem-ui` (forwarding and re-subscription).
- Latency: `tandem-sim/tests/latency.rs` runs the bench with the live cursor requested on both machines (in CI, the same large-regression cap) and `input_latency_does_not_get_worse_with_the_live_cursor_watched` (`--ignored`, in release) compares the best p99 with and without a subscription. Measured: with the events dropped in the forwarder there is no difference; with full forwarding it cannot be told apart from the machine's noise (best p99 between 0.38 and 0.83 ms with it and 0.42 to 2.6 ms without it, depending on the machine's load).
