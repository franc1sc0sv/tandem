# T-321 — Remove the stray root `package.json` and `pnpm-lock.yaml`

## Context

Failure found by the acceptance agent, part C, round 6 (2026-11-19, `origin/develop` 9fe53be). See `docs/reports/acceptance-2026-11-19-c6.md`.

## Failure

Repository hygiene. `git ls-files package.json pnpm-lock.yaml` lists two files at the repository root, added by T-119 (dac103b):

- `package.json`: `"name": "agent-a0781272cae4a878b"`, version `1.0.0`, `"test": "echo \"Error: no test specified\" && exit 1"` (the output of `npm init -y` run by an agent session).
- `pnpm-lock.yaml`: 9 lines, one empty importer (`.: {}`).

Nothing uses them: the UI is `apps/tandem-ui`, `tools/mockup-render` has its own package, `ci.yml` and the release scripts point at those two `package.json` files only, and `docs/dev/release.md` lists `apps/tandem-ui/package.json` as the version file. A `pnpm install` or `pnpm test` run by mistake at the root succeeds or fails with a meaningless "no test specified" instead of saying there is no project there, and the file carries an internal session id.

## Expected fix

- `git rm package.json pnpm-lock.yaml`.
- Confirm that no workflow, script or doc refers to them (`grep -rn "package.json" .github scripts docs/dev`) and that CI stays green.

## Acceptance criteria

- [x] `git ls-files package.json pnpm-lock.yaml` prints nothing.
- [x] `pnpm -C apps/tandem-ui install --frozen-lockfile && pnpm -C apps/tandem-ui test` and `pnpm -C tools/mockup-render install --frozen-lockfile` still work.
- [x] Quality gate and CI green.
