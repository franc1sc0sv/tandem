# T-155 — Copiar una sola credencial da «manifiesto no válido»

Hallada por el agente de aceptación (parte B), flujo F5 (T-130).

## Qué falla

`files_put` con un único archivo que parece credencial (`id_rsa`, probado por `tandem mcp` contra dos agentes reales) no devuelve «omitido por parecer credencial» con el `warning` de T-130, sino el error `la otra máquina: manifiesto no válido: una copia de un archivo trae exactamente una entrada`: el filtro vacía el manifiesto y se manda igual a la otra máquina. No se filtra nada hacia la otra máquina (bien), pero Claude no recibe la razón correcta ni el camino para pedirlo con `include_secrets`. Con varios archivos (`tunnel_open` con workspace) el aviso sí sale bien.

## Corrección esperada

- Si el filtro deja la copia sin entradas, `files_put` no abre la copia y devuelve `skipped` con el archivo y el `warning` de `docs/dev/mcp.md` (código de éxito parcial, nada enviado).
- Prueba en `crates/tandem-cli/tests/e2e.rs` o `crates/tandemd/tests/files.rs`: un solo archivo secreto, con y sin `include_secrets`.

## Criterios de aceptación

- [ ] `files_put` de un archivo secreto devuelve `skipped` y `warning`, sin error del otro agente.
- [ ] Con `include_secrets` nombrándolo, se copia.
- [ ] Puerta de calidad y CI en verde.
