# T-155 — Copying a single credential gives "invalid manifest"

Found by the acceptance agent (part B), flow F5 (T-130).

## What fails

`files_put` with a single file that looks like a credential (`id_rsa`, tested through `tandem mcp` against two real agents) does not return "skipped because it looks like a credential" with the `warning` from T-130, but the error `the other machine: invalid manifest: a file copy carries exactly one entry`: the filter empties the manifest and it is sent all the same to the other machine. Nothing is leaked to the other machine (good), but Claude does not get the right reason nor the way to ask for it with `include_secrets`. With several files (`tunnel_open` with workspace) the notice does come out right.

## Expected fix

- If the filter leaves the copy with no entries, `files_put` does not open the copy and returns `skipped` with the file and the `warning` from `docs/dev/mcp.md` (partial success code, nothing sent).
- Test in `crates/tandem-cli/tests/e2e.rs` or `crates/tandemd/tests/files.rs`: a single secret file, with and without `include_secrets`.

## Acceptance criteria

- [x] `files_put` of a secret file returns `skipped` and `warning`, without an error from the other agent.
- [x] With `include_secrets` naming it, it is copied.
- [x] Quality gate and CI green.

## Notes

`transfer::put` returns the report with `skipped` and without opening the copy if the filter leaves the manifest empty. Tests in `crates/tandem-files/tests/files.rs`.
