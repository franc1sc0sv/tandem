# T-115 — Machine screen (resources, modules, environments)

## Context

DESIGN §12. Reference mockups (visual and interactive source of truth): `V3-Machine`, `F-MachineMac`. The screen must look and behave the same as the mockup: same structure, sizes, colors, icons, texts, animations and transitions; everything interactive in the mockup really works against the agent.

## Scope

1. Grouped resources: CPU, RAM, GPU group, and a disk line; live values with animation.
2. Modules with state and reason (T-098), switch where applicable.
3. Environments panel stretched to the same height as the others, with the switch fixed at the bottom; re-scan button.
4. Machine color and name editable (shared config).

## Acceptance criteria

- [x] Similarity ≥ 0.99 against each listed mockup and state, in the screenshot harness (T-112/T-125), with the screenshots saved in `docs/screenshots/v03/`.
- [x] Everything that is interactive in the mockup works connected to the agent (real IPC) and in demo mode; vitest tests of the logic and of the interactions.
- [x] Mockup animations and transitions present; with `prefers-reduced-motion` they are turned off (test).
- [x] No filler texts or elements without a function (DESIGN §3.8).
- [x] `pnpm test`, `pnpm build`, `pnpm check` and CI green.

## Notes

- Similarity measured with `pnpm shots --check` (screenshots in `docs/screenshots/v03/`), both with threshold ≥ 0.99 / ≥ 0.97:
  - `machine-b` against `V3-Machine`: screen 100.00 % (worst tile 99.5 %); sidebar 100.00 % (99.9 %) and content (`main`) 100.00 % (99.5 %). Only "Add machine" is covered (D1). The sidebar draws "My desk" next to the logo on the machine pages, like the mockup (captain's decision in DECISIONS).
  - `machine-a` against `F-MachineMac`, in the state the mockup draws (`trouble=permissions`, battery in the demo): content 99.99 % (worst tile 98.4 %). Only the content is compared and the three differences that `mockups/README.md` now allows for that mockup are covered (sidebar per G3, color picker per D17, module state per G4). The app is captured at 1492 px with the sidebar fixed at 220 px so that the content measures 1216 px in whole pixels, like the mockup.
  - This machine's page uses the compact list of `F-MachineMac` (37 px rows, "default" as text), the "Permissions" row with "Open settings" when a macOS permission is missing, the battery on the disk line and "no fan"; it has no "Power off" nor the remote execution switch (its tunnels module is turned off from the row).
- Interactions, in demo mode and against the agent (`LiveSource` → actions of `tandem_ui::session`):
  - Color: `radiogroup` with the D17 palette (arrow keys included); the other machine's color is disabled. `set_machine` → `UiCommand::EditDesk { DeskPatch::Machine }`.
  - Name: clicking the title edits it in place (Enter saves, Escape cancels, empty or > 40 characters is rejected with a notice). Same `set_machine`.
  - Modules: the status chip of those that can be turned off is a `role="switch"` (`set_module` → `UiCommand::SetModule`); unavailable ones show the agent's reason and cannot be touched. "Allow remote execution" is that machine's `tunnels` module (on the other machine's page).
  - Environments: the default one (the default WSL distro; otherwise the shell) goes first and highlighted with the accent; re-scan button (`rescan` → `UiCommand::Rescan`) that spins while working; the panel stretches to the height of Modules with the switch at the bottom.
  - Resources: the screen asks for `watch_resources` on entering and releases it on leaving. The session (`session.rs`) counts the windows that are watching (main and tray share a session), asks for them again on reconnect and forwards `AgentToUi::Resources` as the `agent-resources` event; the UI builds the history of each line (30 samples) and the summary on the Desk and the tray comes from the same view.
  - Power off / Power on the other machine (`set_power`).
- No protocol change: everything used was already in v20 (T-098, T-099, T-105).
- Data the agent does not send yet and the view already accepts (without data they are not drawn; the demo brings them): GPU fans or "no fan", battery and the desk name (by default "My desk"). The system version ("Windows 11", "macOS 26") does not travel either: with the real agent you see "Windows" / "macOS".
- Tests: `src/lib/machine.test.ts` (units, machine names, environment order, trends, samples → view; with properties over percentages and environments), `src/screens/machine.test.ts` (each interaction in demo and against a simulated IPC, animations and `prefers-reduced-motion`), `scripts/shots-spec.test.ts` (thresholds) and in Rust `session.rs` (resources that arrive and survive a reconnection, two windows watching, module turned off end to end with a real agent, JSON of the views and of the new actions).
