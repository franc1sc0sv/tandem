# T-073 — Pairing from the UI

## Scope

End-to-end pairing flow from DESIGN §9: a UI→agent command to start, the agent discovers the other and shows the 6-digit code (T-003) in both UIs, the user confirms on both, the trust is saved. Pairing screen in the mockup's style (sober, visual). Unpair from the UI.

## Acceptance criteria

- [x] Test with two agents: start → same code on both sides → confirm on both → they end up paired; reject on one → neither ends up paired.
- [x] Frontend tests of the pairing screen.
- [x] Screenshot in the PR (demo mode).

## Notes

- **Pairing transport** (what T-004 left pending): a separate QUIC endpoint, `Endpoint::bind_pairing`, with a different ALPN (`tandem-pair/1`) and a verifier that accepts any Ed25519 key but still requires the handshake signature. It only exists while pairing and only carries `PairingMsg` (`Offer`, `Answer`, `Reveal`, `Confirm`, `Reject`). The normal endpoint does not change: it still rejects anyone not in the trust at the handshake, and the two ALPNs cannot talk to each other (test).
- The keys in `Offer`/`Answer` have to be the ones that authenticated the connection; otherwise it is cut before showing a code (test with a middleman that offers another's key).
- **Fixed roles**: the PC waits on `network.pairing_port` (by default `port + 1`) and announces it through mDNS as `_tandem-pair._udp`; the Mac looks for it at the IP of each static link with that port and in whatever shows up through mDNS. The user presses "Pair" on both, in any order. Times: 2 min to find each other and 2 min to confirm.
- Each side sends `Confirm` when its user confirms and saves the trust once it has both; rejecting, cancelling, cutting or timing out on either side ends without saving anything. If the connection is cut right after the last confirmation, only one side may end up paired (it shows as "no link" and is fixed by unpairing).
- **Hot network**: `Network` no longer decides everything at startup. When pairing it starts following the new peer (link manager, mDNS, `pc_watch`) without restarting; when unpairing it removes it from `trust.toml` (`TrustStore::remove_and_save`), stops following it and cuts the connections it opened (pinning only looks at the trust during the handshake).
- Protocol v4: `UiCommand::{GetPairing, StartPairing, ConfirmPairing, CancelPairing, Unpair}`, `Reply::Pairing` and `AgentToUi::Pairing(PairingStatus)` (`Idle`, `Searching`, `Comparing { code, peer, confirmed }`, `Done`, `Failed`). Once paired, it cannot be paired again without unpairing.
- UI: the link pill is a button ("no peer · Pair", or the link if there is a peer) that opens the dialog: the two machines with the line between them (searching, found, linked, cut), the code in two groups of 3 digits, "Match" / "Don't match", result and unpair with confirmation. Closing the dialog cancels whatever is in progress. Pure logic in `apps/tandem-ui/src/pairing.ts` (`pairing.test.ts`); the simulated agent of `/?demo` simulates the other machine (`&peer=none`, `&pair=reject`, `&pair=code`).
- Tests: `crates/tandemd/tests/pairing.rs` (two `tandemd` with no prior trust: start → same code → confirm on both → paired, saved and connected through the static link with a mode change; reject on one → neither paired; search that times out; cancel; unpairing cuts the link), `tandemd::pairing` (protocol, swapped key, same machine on both ends, timeout), `tandem-link` (pairing endpoint, separate ALPNs, `PeerResolver::any`, `remove_and_save`), UI session and frontend.
- Screenshots: removed later because they showed the retired Spanish UI; see git history.
- Left for the real desk: mDNS of `_tandem-pair._udp` on the home LAN and the pairing port getting through the Windows firewall (T-071's installer would have to open it along with QUIC's).
