# T-330 — Record T-322 in `docs/DECISIONS.md`

## Context

Failure found by the acceptance agent, round 7 (2026-11-19, `origin/develop` 22674c3, tag v0.3.0). See `docs/reports/acceptance-2026-11-19-r7.md`. Same kind of gap as T-320 (T-291) in round 6.

## Failure

Documents against code. T-322 (#188) changed how the shared desk converges after the start-up migration, and no decision line was written:

- `grep -n "T-322" docs/DECISIONS.md docs/DESIGN.md` finds nothing. T-270, T-280, T-291 and T-310 each have a dated line; T-322 does not. The reasoning lives only in `docs/tasks/T-322.md`.
- The line "2026-11-17 · T-099 · (Review of #74.) When migrating, an `[input] clipboard = false` (formerly per machine) becomes `[modules.<side>] clipboard = false` and counts as a change of that machine, with a new version, so the other adopts it" is not true on its own: when both machines migrate at the same time, their two versions have the same `rev`, "last write wins" (T-099, line "compares (version, date in ms, side A first)") keeps the other one whole, and the moved switch was lost. Since T-322 (`MovedHere` and `keep_moved_here` in `crates/tandemd/src/agent.rs`):
  - after adopting a simultaneous sibling (same `rev` as its own migration), a machine puts its migrated module switches back on top as a new local change (`rev + 1`) and sends it;
  - that restore records no "Changed from X" notice and no history entry for the sibling, so "Undo" cannot turn the switch off again;
  - the record is dropped as soon as a newer version holds, so a later deliberate change by the other machine is never undone;
  - known limit: the record is in memory only, so a restart between the migration and the first desk exchange can still lose the switch.

## Expected fix

- Add a dated T-322 line to `docs/DECISIONS.md` in the usual format: the exception to "last write wins" for a simultaneous migration sibling, why (both machines migrate a pre-T-099 desk on the first start of the new version and bump the same `rev`), the no-notice/no-history rule, and the in-memory limit.
- Mark the T-099 migration line as refined by T-322 (the way T-115 says `(superseded by T-270)` and T-152 points to T-291).
- Check that `docs/DESIGN.md` does not describe desk convergence as plain "last write wins" without this exception.
- Keep `scripts/ci/status.sh` passing (counts and the "Open tasks" row) when this task closes.
