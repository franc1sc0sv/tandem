# T-356 — Desk and Monitors polish

## Context

On 2026-11-24 the user reported, from screenshots of v0.3.3 on the Mac:

- Live desktops drew the two external monitors (the 32" Odyssey G5, 16:9 2560 × 1440, and the 34"
  LC34G55T, 21:9 3440 × 1440) as two identical boxes labelled `screen-1 · Mac` and `screen-2 · Mac`:
  the agent sent no physical size, so the UI estimated it from points at 110 ppi and named each screen
  by its engine id.
- The link bar under the machine cards read `USB-C – · –` and `Input –`: the Desk did not ask the
  agent for the network, so the figures it already measures never reached it.
- The two machine cards left a 200 px gap on the right (the mockup's "Add machine" column, D1).
- Scene cards with long machine names overflowed under the shortcut chip (Desk) or wrapped into four
  lines (Monitors): the lines used the EDID model ("LC34G55T", "Odyssey G5") instead of the size.

## Scope

1. Protocol v50: `MonitorChannel::size_mm` and `MonitorView::size_mm`, the picture's physical size
   from the EDID (`tandem_monitor::edid_size_mm`: the first detailed timing descriptor in mm, else
   bytes 21–22 in cm; an aspect ratio in either is ignored). The directory takes the shown channel's,
   else any machine's.
2. UI: a monitor is named by its diagonal (`34"`, `32"`) everywhere it was named by its model in a
   sentence (scenes, progress, notices, tray, Desk states). Live desktops link each engine screen to
   its monitor through the desk's `[[cables]]` (each machine's end names its screen), draw it at its
   EDID size (screens of different densities placed edge to edge, `placePhysical`), label it
   `34" · Mac`, and give a known model its own stand (the LC34G55T a wide V, the 32" G5 a trapezoid,
   the rest the mockup's generic one), all standing on the same table.
3. The link bar shows the agent's real measurements: the primary path's ping round trip, the input
   latency the session measures (capture → injection, p99; in a second without input, the newest one
   of the last 60 s) and the last bandwidth test. The Desk and the tray now ask for the network
   (`watch_network` with the `link` topic). Nothing measured yet reads `0`, never a dash, and the
   title says what is missing.
4. The machine cards fill the row (the "Add machine" card is gone from `V3-Desk` itself), one column
   when the page is narrow.
5. Scene cards: one line per monitor (`34" → PC`), name and lines ending in an ellipsis with the
   full text as the title, the shortcut chip never overlapped; the scene and monitor grids never wider
   than the page.
6. Demo `?demo&desk=g5`: the real two-monitor desk (a Mac and a PC with a long Windows name, both
   cabled to both monitors) for screenshots and tests. The G5's 70 × 40 cm is what its EDID reports
   (read on the real monitor); the LC34G55T's 797 × 334 mm is its panel's active area (spec sheet).

## Acceptance criteria

- [x] `edid_size_mm` reads a timing descriptor, falls back to bytes 21–22 and ignores an aspect
      ratio; a scan announces it; the view takes either machine's (Rust unit tests).
- [x] `PROTOCOL_VERSION = 50` with DESIGN §4.5 updated (`scripts/ci/protocol.sh`).
- [x] A cabled monitor is drawn at its EDID size, named by it, with its model's stand; one without a
      size keeps the estimate (vitest, `layoutFromDesk`, `sceneOf`, `placePhysical`).
- [x] The Desk asks for the network and its link bar shows the agent's figures, `0` before any
      measurement and never a dash (vitest with the real IPC source).
- [x] Machine cards fill the row; `V3-Desk` updated and `pnpm shots --check` passes.
- [x] Scene lines use `34"`/`32"`, one per monitor, with ellipsis and a title.
