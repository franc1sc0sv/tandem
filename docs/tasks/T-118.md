# T-118 — Network screen

## Context

DESIGN §12. Reference mockups (visual and interactive source of truth): `V3-Network`. The screen must look and behave the same as the mockup: same structure, sizes, colors, icons, texts, animations and transitions; everything interactive in the mockup really works against the agent.

## Scope

1. Animated link map: the two machines with halo and the three curved paths (USB-C with color flow, dotted Ethernet if there is no cable, slow amber Wi-Fi) with their labels.
2. Indicators: latency ring (p50 and p99), bandwidth ring, 60 s area chart with the peak marked and the note of the last path change.
3. Cards per path with uniform status chips (Primary green with pulse, Backup amber, No cable dotted gray) and metric bars.
4. "Measure bandwidth" button (`MeasureLink`).

## Notes

Done:

- Network screen equal to `V3-Network`: link map (`red/LinkMap.svelte`: machines with halo and their own color; USB-C with flow in the color of the two machines, straight dotted Ethernet if there is no cable, slow amber Wi-Fi), indicators (`red/Indicators.svelte`: p50/p99 latency ring against the target, bandwidth ring, 60 s chart with the peak marked and the note of the last change) and one card per path (`red/PathCard.svelte`: Primary / Backup / No cable / Down chip and bars). The DOM-free logic is in `lib/network.ts` (chart scale, per-second series, note, formats).
- Real IPC: the Tauri session (`src-tauri/src/session.rs`) asks for `WatchNetwork` while the Network screen is visible (it is remembered and repeated on reconnect), forwards `AgentToUi::Network` as the `agent-network` event and answers `MeasureLink` with `ActionResult::Bandwidth` (with a wait limit of 3 s + the usual: with 2 s the session would be given up for lost in the middle of the test). `LiveSource` requests and releases the network depending on the screen and measures the path that carries the input.
- Harness: `red` with a threshold on the whole screen (similarity ≥ 0.99, worst tile ≥ 0.97): 99.98 % and 97.9 %. `ShotSpec.min` and the whole-screen check are the same ones T-117 uses.
- Tests: `lib/network.test.ts` (logic), `screens/red.test.ts` (demo, IPC with a simulated bridge, mockup animations and `prefers-reduced-motion`), `store.test.ts` and 4 Rust session tests.

Differences from the mockup (in `docs/DECISIONS.md` and `mockups/README.md`):

- The chart says "Latency · 60 s", not "10 min": the agent keeps 60 s (DESIGN §6). It is the only thing covered in the comparison (the label, in addition to "Add machine" per D1).
- "USB4 · 20 Gbps", "2.5 GbE" and "Wi-Fi 7 · home" only appear in the demo: `PathMetrics` does not carry the link detail, and in the real app that line is not drawn until T-094 detects it.
- The note under the chart and the peak marker come from the data (last drop in the last 60 s; peak only if it exceeds the target); with no drops there is no note.
- No search box in the header: `V3-Network` does not have one.

Pending outside this task:

- The input p50/p99 (latency ring) appears when T-093 delivers the measured latency; until then the ring says "no input" and the chart uses the round trip of the pings.
- `app.rs` (the event emission) only compiles with WebKitGTK/Tauri: the CI of the three platforms checks it.
