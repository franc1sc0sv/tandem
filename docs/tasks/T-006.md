# T-006 — LAN discovery

## Scope

mDNS (crate mdns-sd) announcing `_tandem._udp` with the key's fingerprint; resolving the peer by fingerprint. Static addresses of the direct links from configuration (`10.77.1.0/30` USB4, `10.77.2.0/30` Ethernet).

## Acceptance criteria

- [x] Unit test of fingerprint filtering (ignores other announcements).
- [x] The static addresses from the config are handed to the link manager as candidates.

## Notes

The real network test needs both machines; mark those tests `#[ignore = "hardware"]`.

- Implemented in `crates/tandem-link/src/discovery/`: `Fingerprint` (SHA-256 with domain `tandem/fingerprint/v1` over the public key; 64-digit hex and a 12-digit short prefix for DNS names), `PeerResolver` (pure announcement filter: accepts only the fingerprint of a peer in the trust store and ignores our own, foreign, malformed ones and announcements without a fingerprint; forgets the peer when it withdraws or changes fingerprint), `validate_static_links` / `link_candidates` and `MdnsDiscovery` (mdns-sd: registers `_tandem._udp.local.` with instance and host `tandem-<short fingerprint>`, the QUIC port and the full fingerprint in the TXT key `fp`; browses the same type and publishes the peer's addresses in a `watch`, from best to worst: IPv4, link-local IPv4, global IPv6, link-local IPv6 with its interface index).
- Candidates for the manager: the config's fixed links as they are and, if the config does not fix Wi-Fi, the best discovered address as a Wi-Fi candidate. Discovered addresses that match the IP of a fixed link are discarded (the peer also announces on the wired interfaces).
- `tandem.toml`: `network.peers` goes from bare addresses to typed links (`{ kind = "usb4" | "ethernet" | "wifi", addr = "..." }`, T-005's `LinkCandidate`); port, address and that a type is not repeated are validated. `NetworkConfig::link_candidates(discovered)` builds the list for `LinkManager::spawn`.
- Tests: unit and property tests of the filter and the candidates; conversion from/to mdns-sd types without a network; integration (`tests/discovery.rs`) with TOML config + simulated announcements → `LinkManager` with a transport double, which connects to USB4, Ethernet and the LAN IP and leaves USB4 active. The test with real multicast (`dos_agentes_se_encuentran_en_la_lan`) is marked `#[ignore = "hardware"]`; on WSL2, two agents on the same machine found each other in ~1 s.
- Out of scope (integration in `tandemd`): starting `MdnsDiscovery` with the key and the trust store and updating the running `LinkManager`'s candidates when the discovered addresses change (T-005's manager receives a fixed list at startup).
