# T-197 — Workspace preparation breaks with a relative `--data-dir`

## Context

In the cable run (`docs/reports/hw-2026-11-18-cable.md`) both agents were started with `--data-dir agent/data`. `tunnel-workspace` failed on both sides: git runs with `…/scratch/repo` as its working directory but receives `agent/data/workspaces/<id>.out/repo.bundle` (Mac, `git bundle create`) or `agent/data/workspaces/<id>.in/repo.bundle` (PC, `git fetch`), which resolve under the wrong directory. `scripts/hw/run.sh` starts the Mac agent the same way.

## Expected fix

Make the data directory absolute once at startup (canonicalize `--data-dir` and config-derived paths), so no later path depends on the process's or a child's working directory. Add a failing test first: a workspace round trip between two agents started with relative data directories.

## Acceptance criteria

- [x] Test reproducing the failure with a relative data directory, then passing.
- [x] Data directory resolved to an absolute path at startup.
