# T-244 — Demo data tied to Mac/PC (notices, administrator service, permissions card, module switches)

## Context

Finding of the acceptance agent (part A, round 4, `docs/reports/acceptance-2026-11-19-a4.md`), rules G2/D2 ("nothing tied to Mac/PC; tested with a simulated Windows+Windows and macOS+macOS pair"), G6 and the T-098 decision ("only Keyboard and mouse and Clipboard can be turned off"). Same class as T-170 (round 2). The demo is what the parity screenshots and the acceptance runs use, so it must behave like the real app for each pair.

Found with the text sweep (`docs/reports/acceptance/2026-11-19-a4/harness/sweep.ts`, 261 demo cases):

1. **Seeded notices** (`?demo=win-win&notices`, `?demo=mac-mac&notices`): `DEMO_NOTICES` (`apps/tandem-ui/src/lib/notices.ts:39`) is fixed text, so a Windows+Windows desk shows "34" confirmed on PC-Desktop in 1.8 s." and "MacBook Pro → PC-Desktop · WSL.", and a macOS+macOS desk shows "PC-Desktop" and "WSL", machines and environments that are not in the desk.
2. **Administrator service, `admin=off`** (`?demo&wizard=0&admin=off`, this machine is the MacBook Pro): the setup row says "per-user install: install Tandem under Program Files for the service" (`apps/tandem-ui/src/lib/store/demo.ts`, `adminStatus`). That is the Windows wording on a macOS machine; the real macOS note (`apps/tandem-ui/src-tauri/src/admin_service.rs`, `check`) is "user-level installation does not support the administrator service: … Move Tandem to Applications (owned by root) to install it". Screenshot: `docs/reports/acceptance/2026-11-19-a4/new-screens/setup1-admin-off.png`.
3. **Trouble states reference view on a Windows machine** (`?demo=win-win#/states`, `?demo&here=b#/states`): the "Permissions" card says "A system permission is missing … Grant it to Tandem" with an "Open System Settings" button. Windows has no such permission (the setup says "Windows lets you capture and inject the keyboard and mouse without asking for anything"), and the real `open_settings` on Windows returns "these permissions only exist on macOS" (`apps/tandem-ui/src-tauri/src/app.rs`). The card appears only because `stateCards` shows every card in the demo (`gallery: store.demo`, `apps/tandem-ui/src/lib/states.ts`).
4. **Module switches** (`#/machine/b` in `?demo`, both pages in `?demo=win-win`): the demo marks Monitors, Tunnels / Remote compute and Protected screens as `switchable: true` (`demo.ts`, `modulesOf`), so their chip is a `role="switch"` button that turns them off. The agent only lets Keyboard and mouse and Clipboard be switched (`crates/tandemd/src/modules.rs`, `fn switchable`; DECISIONS T-098), so the real app shows a plain chip there.

## Expected fix

- Notices: build the seeded texts from the desk (the scene's monitor and the machine that shows it, the tunnel's two machine names and an environment of the receiving machine). With `?demo&notices` (mac-win) the texts must stay exactly the mockup's, so the `notices` screenshots do not move.
- `admin=off`: the note follows this machine's system (the macOS and Windows wordings of `admin_service.rs`).
- Reference view: on a machine whose system has no input permissions, leave out the Permissions card (or say it does not apply, without a button), in the demo too.
- Demo modules: `switchable` exactly as the agent announces it (only `input` and `clipboard`).
- UI tests per pair for each of the four points (no "PC"/"WSL"/"Windows" on a macOS+macOS desk, no "Mac"/"macOS"/"MacBook" on a Windows+Windows desk; no switch on non-switchable modules).

## Acceptance criteria

- [x] `?demo=win-win&notices` and `?demo=mac-mac&notices` name only the desk's machines and environments; `pnpm shots --check` still passes with `notices` unchanged.
- [x] `?demo&wizard=0&admin=off` shows the macOS note on the macOS machine and the Windows note on a Windows machine.
- [x] No Permissions card with "Open System Settings" on a Windows machine, demo included.
- [x] Only Keyboard and mouse and Clipboard have a switch on the machine pages, demo included.
- [x] Tests added; quality gate and CI green.

## Notes

Evidence: `docs/reports/acceptance-2026-11-19-a4.md`, sections "Global rules" (G2) and "New since round 3".

Done: `apps/tandem-ui/src/lib/capabilities.ts` holds what the demo repeats from the agent (switchable modules, per-system administrator note, which systems ask for input permissions); `capabilities.test.ts` reads `crates/tandemd/src/modules.rs` so the copy cannot drift. `demoNotices(desk)` builds the seeded notices from the desk (seeded by `Store.seedDemoNotices` once the desk is known). Only Keyboard and mouse and Clipboard have a switch in the Modules list (DECISIONS T-098); Monitors, Tunnels, Protected screens and Power are plain chips. The mockup's separate "Allow remote execution" block stays on the other machine's page as a locked switch (it cannot be toggled, but it is not dimmed, so mockup parity holds without masking anything).
