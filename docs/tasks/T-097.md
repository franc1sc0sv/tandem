# T-097 — Two equal sides

## Context

DECISIONS D1, D2, A1. Today `tandem_core::Machine` is `{Mac, Pc}` (~660 uses) and many modules assume which system is on each side (the Mac does not power off, the PC has DDC, the Mac on the left…). In v0.3 either side can be macOS or Windows.

## Scope

1. `Machine::{A, B}` with `other()`. The side is decided by the Ed25519 public key: the lower one (byte order) is `A`. The two machines reach the same result without coordinating. Pure function with tests.
2. `MachineInfo { os: Os::{MacOs, Windows}, name, color }` per side, which travels in the capabilities announcement and is saved in the shared config. Everything that today decides by `Machine::Mac`/`Pc` moves to deciding by capabilities (`Capabilities`) or the side's `Os`.
3. Configuration migration: an old `tandem.toml` (`mac`/`pc` sections/keys) is read and converted to the new format with the sides resolved by identity; test with the examples in `docs/examples/`.
4. Protocol: bumps the version; an old agent is rejected at the greeting with a clear error.
5. UI and IPC: names and colors come from `MachineInfo`, not from fixed "Mac"/"PC" texts.
6. `tandem-sim`: the scenarios use `A`/`B` and scenarios with **two Windows** and **two macOS** (simulated) that pass the same are added.
7. Find and remove every remaining assumption: `grep -rn "Mac\b\|Pc\b\|mac_side\|is_mac"` in crates and UI; whatever remains must be real platform code (`#[cfg]`).

## Acceptance criteria

- [x] No `Machine::Mac` or `Machine::Pc` is left in the code; the "Mac"/"PC" texts only exist as example data or default names derived from the system (`Os::default_name`). What remains with `mac`/`pc` is the v0.2 migration, the direction of the Cmd↔Ctrl remapping (`mac_to_win`, which is per system, not per side) and variable names in tests.
- [x] Property test: for any pair of distinct keys, the two machines assign the same sides (`tandem-core/tests/props.rs::both_machines_agree_on_the_sides`).
- [x] `tandem-sim` scenarios with macOS+Windows, Windows+Windows and macOS+macOS green (`tandem-sim/tests/power.rs::any_system_on_each_side`); also two Windows agents over loopback with keyboard and mouse (`tandemd/tests/input.rs::two_windows_machines_share_the_keyboard_without_remapping`).
- [x] Migration of the old config with a test (`tandemd/tests/migration.rs`, with the examples moved to `docs/examples/v0.2/`).
- [x] Quality gate green in WSL and `cargo check --target x86_64-pc-windows-gnu` green; CI on the three platforms: in the PR.

## Notes

Done:

- `tandem-core`: `Machine::{A, B}` (`of_keys`: the lower key is A), `Os::{MacOs, Windows}`, `MachineInfo { os, name, color }` and `Config::machines` (`[machines.a]`/`[machines.b]`). `Config::swap_sides` and `State::swapped` for when a machine discovers that it is the other side.
- Side by identity: `daemon::start` resolves it with the identity and the trust's peer before assembling the agent; on pairing, `Agent::adopt_side` swaps the sides live (state, desk, keyboard, file) and the input engine restarts.
- Symmetric pairing: both machines wait and search; the connection that A opens is the one that counts (decision noted in DECISIONS).
- Decisions by system/capability: clean power off by `Os` (Windows), Cmd↔Ctrl only between macOS and Windows according to each side's system (the capture is rebuilt if the other's changes), the clipboard is opened by A, keyboard default A.
- Protocol v16 (`SIDES_SINCE`): a v15 agent is cut at the greeting with a message that names the A/B sides.
- Capabilities with `info: MachineInfo`; the desk saves both when they get to know each other (after the desk exchange, so as not to overwrite a real change).
- Migration of `tandem.toml` v0.2 (`crates/tandemd/src/migrate.rs` + `config_edit::with_sides`), which rewrites the file keeping comments.
- IPC/Tauri: `MachineView` carries `name`, `os` and `color`; the tray says the other machine's name (announced or from the desk, or "machine A").

The TypeScript UI was adapted in this same PR (T-126's scope, which stays `done`).

Fixes after the review and the CI of PR #68:

- `tandem.toml` is written one at a time (agent and process lock), the side always goes in the same write as the desk and the temporary file is unique per write. Test: `changing_side_while_the_peer_talks_keeps_the_file_coherent` and `concurrent_changes_do_not_lose_each_other`.
- The side is adopted when pairing is confirmed, before saving the trust: nothing from the other arrives before the change.
- When changing sides the default arrangement is not inverted (nor one that never synced): two fresh installs continue with A on the left (test in `tests/pairing.rs`).
- Pairing no longer cuts connection attempts that take a while (with the machine loaded or on Windows) and does not call itself over loopback.
- The Tauri UI takes this machine's side from its capabilities (follows `adopt_side`).
- Tests that assumed the machine's system fix each side's `Os`; the installer expects `machine = "a"`.
