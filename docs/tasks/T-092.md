# T-092 — Remove monitor, DDC and screen control

## Context

User's request (2026-11-15): monitor control will be done with custom firmware for the 34" (`personal-projects/monitor-firmware`) that reports its real state. Everything that exists today for monitors is surplus and is removed: communication, backend, core and the Windows and macOS APIs. The monitors UI stays **visible but disabled**. See `docs/DESIGN.md` v0.2, §5, §7 and §8.

User's decisions:

- The **reading** of the screen topology in `tandem-display` (monitors, EDID, active outputs) is also removed. The screen bounds that `tandem-input` already reads in order to inject are kept, and serve as the default value of the arrangement. The input engine takes the screens from an arrangement declared in the shared desk (`[[screens]]` per machine), DESIGN §7.
- The **MacBook's built-in screen** (off, mirror, extended, bring windows) is also removed.

## Scope

1. **Delete the whole `tandem-display` crate** (DDC, EDID, caps, profiles, calibration, console, switcher, Windows and macOS topology, Quartz, AX, `desktop`, CLI and the `tandem-ddc` binary) and the `profiles/` directory.
2. **tandemd:** delete `add_monitor.rs`, `calibration.rs`, `display.rs`, `safety.rs` (and `detached.json`), `agent/probe.rs`, and the monitor parts of `wizard.rs`, `autoconfig.rs`, `capabilities.rs`, `config.rs`, `config_edit.rs`, `desk_sync.rs`, `store.rs`, `orchestrator.rs`, `peer.rs`, `agent.rs`, `agent/setup.rs`, `daemon.rs`, `sim.rs`, `ipc`. The wizard is left with the steps of DESIGN §5 (permissions, pair, key, summary; the arrangement arrives in T-096). **`bin/tandemw.rs` stays**: it is the agent's console-less launcher on Windows and has nothing to do with the probe. The tests in `tandemd/tests/` that touch monitors (`orchestrator`, `wizard`, `network`, `pairing`, `input`, `two_processes`, `check_config`) are trimmed to what remains.
3. **tandem-core:** remove monitors, inputs, wiring, monitor modes and the `SwitchInput` / `Attach` / `Detach` / built-in screen steps from the model, the state, the plans and the screen safety property (`tests/safety.rs`). The transactions (power) and whatever the rest uses stay.
4. **tandem-proto:** remove `ScreenRect.monitor` (screens get their own id), `ShowProbe`, `HideProbe`, `ProbeResult`, `MonitorCaps`, `Rescan` if it only serves monitors, the `monitors` / `scanned` / `builtin` fields of `Capabilities`, profiles and monitors of `DeskSync`, and the UI commands for monitors, calibration, "what does it show" and modes. Bump the protocol version.
5. **Declared geometry** (DESIGN §7):
   - `[[screens]]` per machine in the shared desk: id, x, y, width, height in that machine's native cursor coordinates, and scale; plus the relative position of the two desktops (edge and offset). Synced with `ControlMsg::Desk`.
   - `tandem_input::geometry` stops depending on `tandem_core::{Config, State, MonitorId, BuiltinDisplay}`: `Layout::compute` receives the arrangement, without filtering by monitor owner or built-in screen, and `mac_facing` stops using `cfg.monitors`. `ScreenId` becomes a per-screen id. The edge-crossing algorithm and its property tests are kept; `tandem-input/src/session/testutil.rs` and `tandem-input/tests/session.rs` are adjusted.
   - `tandemd/src/input/screens.rs` and `input/backends.rs` stop using `tandem_display::{topology, desktop}`. Default value for each machine: the bounds that `tandem-input` already reads to inject (`screens()` of `macos/emulate/cg.rs`; the virtual desktop on Windows), the Mac on the left.
6. **tandem-sim:** remove `LC34G55T_READS`, the monitor world and the `calibration`, `mirror`, `initial_state` tests and the monitor parts of `scenarios`, `adversarial`, `power_cut`, `props`; keep the link, hub, input and power scenarios.
7. **UI (`apps/tandem-ui`):** delete `addmonitor`, `probe` (and `probe.html` with its entry in `vite.config.ts`), the tray modes (`tray.ts`, `src-tauri` `tray.rs`), in `src-tauri` `probe.rs` and whatever concerns monitors or modes in `session.rs`, `status.rs`, `shortcuts.rs` and `capabilities/default.json`, the monitor parts of `desk`, `onboarding`, `scene`, `model`, `bridge` and `demo`. In the scene, the monitors and the mode cards are drawn **disabled** with the caption "Coming soon: custom firmware"; the mode shortcuts are removed from "Shortcuts". Unused Tauri commands, out.
8. **Documentation:** `docs/STATUS.md`, `docs/dev/HANDOFF.md`, `docs/TESTING.md`, `docs/dev/install-*.md`, delete `docs/dev/ddc-profiles.md` and `tools/windows/ddc/`, and the READMEs that mention DDC or `tandem-ddc`. This task authorizes editing `CLAUDE.md` (lines that talk about DDC and about tests that change a monitor's input) to reflect v0.2; `docs/examples/*.toml` examples without `[[monitors]]` and with `[[screens]]`. `docs/research/ddc-*` stays as history.
9. **CI and release:** remove steps or artifacts of `tandem-ddc`.

## Notes

- It is a large removal: do it in layers (UI and tandemd first, then core and proto) with separate commits inside the branch, each one compiling.
- T-088 is replaced by T-095.
- Implementation decisions:
  - The `[arrangement]` offset (`offset`) is saved and synced, but the edge crossing does not apply it yet: the edge is still divided proportionally, as before. The arrangement editor (T-096) will use it.
  - The default screens come from the same injection backends (`CGDisplayBounds` on the Mac, the virtual desktop's monitors on Windows), with id `<machine>-<n>`.
  - A `tandem.toml` with the desk edited by hand is detected by a fingerprint (`desk_sum`): at startup it raises `desk_rev` and the change reaches the other machine through `Desk`.
  - The transactions are left with only `PowerOn`/`PowerOff`; without screen steps there is no rollback, so `RollingBack`/`Inconsistent` are reduced to `Failed`. An uncertain power off is taken as done.
  - `ResetDesk`, `UpdateInputGeometry` and the monitor, calibration and mode commands were removed; protocol v15.
  - The wizard opens by itself on a clean install (connected, with no peer and no keyboard stated).
  - The mode shortcuts of an old `ui.toml` are ignored on load; only showing or hiding the window remains.
  - `CLAUDE.md` and `.claude/` were not touched from the task (agent configuration): lines 3, 6 and 57 of `CLAUDE.md`, `.claude/agents/hardware-verifier.md` (`tandem-ddc`, automatic monitor rollback) and `.claude/rules/platform.md` (reference to `ddc-34-LC34G55T.md`, which stays as history) are left for the user.
