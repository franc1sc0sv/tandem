# T-166 — The other machine's "Activity detected" still does not appear

Found by the acceptance agent (part B, round 2, `docs/reports/acceptance-2026-11-18-b2.md`), flow F1, screen P8 (`F-Asis4`). It is what T-151 was meant to fix and it was not closed end to end.

## What fails

With two real `tandemd` over loopback and the production UI on each one, both windows on step 4 "Keyboard and mouse": a key is pressed and the mouse is moved in B's window. B's window marks its own row ("Activity detected", that is only the local window), but A's window **never** marks B's row. It was repeated with a freshly paired pair (`docs/reports/acceptance/2026-11-18-b2/F1-setup/04-activity-other.png`) and by hand with `key_probe` + `heard_key` sent directly to B's agent: A receives nothing.

## Cause

`crates/tandemd/src/ipc/mod.rs` (the `select!` loop of each UI connection) pushes `Peer`, `Pairing`, `Input`, `Desk`, `Monitors`, `Update`, `Tunnels`…, but it does **not** listen to `Agent::subscribe_key_probe()` nor ever send `AgentToUi::KeyProbe`. The agent does do its part (`setup.rs`: `heard_key` → `ControlMsg::KeyProbe(Heard)` → `receive_key_probe` → `hear`, and `tests/wizard.rs` checks it by subscribing to the agent directly), the window does have the consumer (`session.rs` converts `AgentToUi::KeyProbe` into `Notice::KeyProbe`; `live.ts` hands it to `watchKeyProbe`), but between the two the IPC does not forward the state. That is why T-151's test passes without the UI.

## Expected fix

1. The IPC loop subscribes to `subscribe_key_probe()` and sends `AgentToUi::KeyProbe(status)` on every change (and the current state on connecting), as it does with `Input` or `Pairing`.
2. Integration test **through the IPC** (not only against the agent): two agents, A's UI connected through its socket, `KeyProbe { on: true }` on both, `HeardKey` on B and A receives `AgentToUi::KeyProbe` with `heard = B`.
3. Live UI test with the bridge: the other machine's row becomes "Activity detected" without A's window having received any key.

## Acceptance criteria

- [x] With two agents and two windows on step 4, activity on B marks "Activity detected" on B's row in A's window (and vice versa).
- [x] A test through the IPC that fails before the fix.
- [x] Quality gate and CI green.

## Notes

The IPC loop subscribes to `subscribe_key_probe()` and pushes `AgentToUi::KeyProbe` on every change. No initial state is sent on connecting: the window arms the probe on entering the step and arming already emits the current state (an initial push broke the notice-sequence tests in `session.rs`). The UI consumer (`session.rs` -> `live.ts`) was already tested in `wizard-ipc.test.ts`. New test: `the_other_ones_activity_reaches_the_ui_over_ipc` (`crates/tandemd/tests/wizard.rs`). Protocol unchanged.
