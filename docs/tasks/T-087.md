# T-087 — Initial setup wizard with verification

> Specification written on 2026-10-16 after the first test with the two machines. Replaces a T-086 that was stopped without finishing (it does not exist in develop).

Initial setup wizard with verification: empty desk by default, monitors by picker, screen and keyboard safety. This file already exists: in your PR set status: done and check the criteria. Update docs/DESIGN.md (§5 Modes/state and §8 Monitors) with the new model. If task/T-086 or task/T-087 branches or worktrees from earlier stopped attempts exist, ignore them: this task starts from origin/develop.

User's request (2026-10-16, after the first test with the two machines): "let's make it work like a setup: by default nothing will have anything, only the PC with its things and the Mac, and the monitors will come from a picker that tells us the connected monitors, and never again; only connected monitors will show up; also, if we remove a monitor from the view, any configuration made has to be removed" and "we need a better start and verification for this".

Facts from the real test (PC log):
- The Samsungs expose a different EDID per input: the PC (DP) sees the 34" as SAM711A and the 32" as SAM7489; the Mac (HDMI) sees them as SAM7119 and SAM748A. When syncing the desk, 4 monitors ended up (duplicates), one without ddc and with the wiring inverted after touching the wiring switch in the UI; "Windows only" failed ("m32: no connected monitor matches `Odyssey G5`").
- Since the app started on the Mac, the 32" went black: most likely the Mac removed its output to the 32" (Detach / CGSConfigureDisplayEnabled because of the ghost monitor) with an unconfirmed or wrong state.
- Without [input.hub] the UI said the keyboard was on the Mac; the user has it on the PC. The MacBook always has a built-in keyboard.
- Windows: "clipboard: could not read: … being held by another party" in a loop.

Scope:
A. Empty desk by default. The generated config (T-082) no longer adds monitors: only the machine, the network and default values. The scene shows "this machine" and "the other" without monitors until the user adds them. "Reset desk" option that deletes monitors, links, those monitors' user profiles and state, on both machines.
B. Startup wizard (first launch and when the desk is empty; it can be reopened), one step per screen, sober mockup style, and each step verified before moving to the next:
  1. This machine: shows how it was detected (PC/Mac, name); macOS permissions (those of the current guide) verified live.
  2. Pair with the other machine (or "continue alone for now"); verifies the link (Wi-Fi/cable) with a visible ping.
  3. Keyboard and mouse: "press a key on the keyboard you use" → the machine that receives it has it (both listen). Verification: "is that right?". With no answer: "undefined", never assume the Mac.
  4. Monitors (picker): lists the monitors CONNECTED NOW, combining what each machine reports. For each physical monitor it proposes the link between the two machines' identities (by EDID serial number if it matches; otherwise by model/size) and asks to confirm it ("is this PC monitor this Mac one?"). The wiring is deduced from where each machine sees it (DP/HDMI output technology from the topology when available) and confirmed. The user chooses which to add.
  5. Per-monitor verification: looks for its DDC profile in the database (by any of its PnP ids); if there is none, runs the calibration (T-081). In both cases it ends with a real round trip: "do you see the PC?" / "do you see the Mac?" with buttons; if it fails, the monitor stays in assisted manual mode and this is stated clearly.
  6. Initial state: choose a mode and "Apply mode" (T-085) sending all inputs; final visual verification.
  7. Desk summary with everything verified.
C. Connected monitors only: the scene and the plans only include desk monitors that are connected now on either machine; disconnected ones do not appear (at most, a discreet notice "1 desk monitor is not connected"). Sync never creates monitors: only the wizard or "Add monitor" creates them.
D. Delete a monitor from the view: asks for confirmation and deletes everything about it ([[monitors]] entry, identity links, that monitor's user profile, wiring, state), on both machines.
E. Profiles: a profile can list several PnP ids (aliases per input): SAM711A+SAM7119 = 34", SAM7489+SAM748A = 32"; update profiles/ddc and note in docs/research that the EDID changes per input.
F. Screen safety (hard rule, with tests): no machine removes a monitor from its desktop or turns off the output to it at startup, on sync, during the wizard without confirmation, or with the state unconfirmed. Detach only inside a mode change and after that monitor's SwitchInput succeeded; if a step fails, rollback reactivates everything. At startup, if the agent finds outputs that it deactivated earlier and the state is not confirmed, it reactivates them.
G. Changing the wiring outside the wizard asks for explicit confirmation.
H. Windows clipboard busy with another app: retry with progressive backoff and a single warning in the log.

Acceptance criteria:
- [x] Clean install: the scene shows no monitors until going through the wizard (agent and UI test).
- [x] With two agents on loopback and the real desk simulated (the per-input ids above), the wizard ends with exactly 2 linked monitors, correct profiles and wiring, and confirmed state.
- [x] Deleting a monitor deletes everything about it on both machines (test).
- [x] A disconnected monitor does not appear in the scene or in the plans (test).
- [x] Property test: no sequence of startup, sync, cancelled wizard or failed mode changes leaves a monitor without an active output on the machine that shows it.
- [x] Frontend tests of each wizard step; screenshots of all the steps in the PR (demo mode).

## Notes

- Tests: `crates/tandemd/tests/wizard.rs` (two agents over loopback), `crates/tandem-core/tests/safety.rs` (screen safety proptest), `apps/tandem-ui/src/onboarding.test.ts` (each step). Screenshots: removed later because they showed the retired Spanish UI; see git history.
- Design decision (F): `Plan::follow` ("say what it shows") no longer emits `Detach`, because there is no `SwitchInput` backing it; the ghost is removed at the next mode change. Rollback also does not undo with `Detach` an `Attach` on a monitor the machine was already showing (proptest finding).
- Protocol v12. `MonitorConfig.edid_aliases` and `pnp_aliases` in the profiles. Syncing desks with version 0 no longer merges them.
- "Press a key" listens through each machine's Tandem window (not with a global system hook): the window of the machine where the keyboard is has to be open; if it does not respond, it is chosen by hand or stays "undefined".
- The output technology (DP/HDMI) is only given by Windows; on the Mac the cable is asked.
