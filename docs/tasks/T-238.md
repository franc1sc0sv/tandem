# T-238 — `tunnel-process` check: wait for the state of a killed process

## Context

In the real Mac and PC cable test, the Mac half of the `tunnel-process` check (`crates/tandem-hw`, covers H2, T-103 and T-104) failed after 258 ms with `the process stayed in Some(Running)`, while the files, port and workspace tunnels passed. The Mac launches a process on the Windows PC through the process tunnel, kills it and expects to see it ended.

## Root cause

The check read the state once, right after `UiCommand::Kill` returned. `Kill` answers as soon as the destination has killed the tree, but the origin learns the new state over the tunnel's data channel, a different stream from the control request (`Origin::kill` documents it: "Its new state arrives over the data channel"). `GetProcesses` is a read-only view of what already arrived (D9), so over a real link the single read can land before the update and see `Running`.

The other two suspects were ruled out by reading the code:

- The kill reaching the Windows process: `Table::kill` marks the process killed on the destination before the reply, and `SystemSpawner` puts each process in a Job Object (`TerminateJobObject` kills the whole tree). `crates/tandem-tunnel/tests/system.rs` already checks that killing a tree leaves nothing alive, on the three systems in CI (`windows-latest` included).
- The exit status not travelling back: the state reported was `Running`, not an exit without a code; the destination's own state was already `Killed`.

## Fix

- The check polls the process state (every 100 ms, bounded by `STEP`) until it is no longer running, and only then asserts `Killed`. The failure message now says how long it waited.
- The polling lives in `settled_state`, tested without hardware: a state that arrives late is waited for, a process that never stops is reported after the limit, a missing process or a failed read does not loop.

## Criteria

- [x] Failing tests first: `a_state_that_arrives_late_is_waited_for` and `a_process_that_never_stops_is_reported_after_the_limit` failed with a single read and pass with the bounded polling.
- [x] The check no longer depends on the update arriving before the first read.
- [x] The kill of a whole tree on Windows stays covered by `tests/system.rs` (unchanged, green on `windows-latest`).
- [x] Quality gate passes.
