# T-354 — Protocol 3 monitors, a stable link and live terminals

## Context

On 2026-11-24 the user reported, on v0.3.2: neither monitor could be controlled, phantom monitors,
the USB4 cable link dropping all the time, the keyboard and mouse not crossing, and remote
terminals that flicker and are slow. Causes found:

- The 34" (patch v3.2) and the 32" G5 (production image) now speak `monitor-ddc` protocol 3, which
  v0.3.2's crate rejected as not compatible; the G5 also uses MCCS `0x60` values (`0x0F`/`0x11`).
- The link manager was rebuilt ~680 times a day by mDNS answers that alternate addresses; the PC
  dialled the Mac's `lo0` `fe80::1` over the cable; the backup Wi-Fi ping timeout (400 ms) was below
  the measured spikes; the data pause tripped at a p99 a fraction over the target and stayed up to 65
  minutes.
- Tunnel output rode the paused data lane, the Tunnels screen reset its output on every desk update,
  and processes had no terminal.
- Learned cable screens (`screen-N`) were never updated when the Mac's screens were renumbered.

## Scope

1. `monitor-ddc` at the protocol 3 revision; each monitor opened with its model's `0x60` values;
   soft standby reported as power off; `Step::MonitorPower` / `UiCommand::MonitorPower` (owner only,
   only with power wake); Standby/Wake in the Monitors screen; `monitor_switch` and `monitor_power` in
   the CLI/MCP.
2. Cable screens learned again when the engine renumbers the screens; names given by hand kept.
3. Link: a path identified by its kind (a cable by its interface), no manager rebuild on discovery
   changes, `fe80::1` ignored, backup patience 2 s, bounded data pause.
4. Tunnels: terminal processes (openpty / ConPTY), typed input delivered once and in order, pushed
   output on a lane the input pause does not hold, an output view that only appends.

## Acceptance criteria

- [x] A protocol 3 G5 switches with its own values and goes to standby and back by command from the
      other machine's UI (two-agent simulation); a protocol 2 monitor refuses standby without a Set.
- [x] A learned engine screen follows the monitor after a renumbering; a hand-given name is kept.
- [x] Each link fix has a failing-first test with a simulated clock.
- [x] Terminal output flows while bulk data is paused; keystroke echo and throughput bounds over loopback.

## Pending hardware verification

- [ ] Both monitors compatible on both machines; the G5 gets its `[[cables]]` entry; two monitors, not four.
- [ ] Standby/Wake from the UI on both monitors; the screen dims and leaves the geometry.
- [ ] No "link manager running" storms; the cable stays up for a day; data pauses ≤ 2 s.
- [ ] A ConPTY terminal on the PC from the Mac: prompt, colours, typing, resize, kill.
