# T-089 — Wizard fixes after T-087's real test

In the real test (Windows PC with DDC, Mac without DDC; 34" Samsung SAM711A/SAM7119 and 32" Odyssey G5 SAM7489/SAM748A) step 5 left monitors without an image. This task fixes what was found, each point with a test that fails first.

## Causes

Checked with a test that failed before the fix:

1. **Matching by contained text.** `DdcSwitcher::find`, `bind` and `cli` used `MonitorInfo::matches` (`contains` over description, output, PnP id, name and serial): a partial id or name (`SAM7`, `G5`) chose two monitors or the wrong one. Now `MonitorInfo::is_model` is exact (PnP id or EDID name), like `Display::is_monitor` in the topology.
2. **The profile went to the wrong monitor.** `StartCalibration` receives the bus index and the monitor separately and did not check that they were the same: if the bus order changes between "list" and "calibrate", the profile was saved to the named monitor. Now the calibration and `UseProfile` refuse if they do not match.
3. **Rollback that turned off the PC's output.** `txn::run` undid in reverse order: the inverse of `Attach(pc)` (a `Detach`) ran before returning the input, and left the monitor on the PC without an active output. The inverse of an uncertain step, in the orchestrator, did the same. Now: reactivate, return inputs, and remove outputs at the end and only if the input came back.
4. **"No DDC profile" after a failed round trip.** `MarkManual` always deleted the DDC codes, even if the failure was a transport one (timeouts). Now it only deletes them with `discard_codes`, which the UI sends only when the user said they did not see what was expected.

Reasoned from reading the code and covered by an agent test, but not reproduced on the real equipment:

5. **"Try again" on the 32" moved the 34".** The wizard used `MoveMonitor` (a mode change). With the state unconfirmed, `Plan::to_mode` sends the input of *all* unconfirmed monitors, in addition to `Attach`/`Detach`: the 34" moved along with the 32". Now the test is `ProbeInput`: only a `SwitchInput`, without touching desktops or the state.
6. **The `Attach`/`Detach` to the Mac with no response** (the Mac's agent does not answer in 10 s) were part of that same round trip; without `Attach`/`Detach` in the test there is no one to request them from. A Mac that does not respond can no longer leave an output deactivated.
7. **Assuming the Mac as the origin.** With the state unconfirmed the UI assumed `home = mac`, and the return went where the monitor was not. Now it asks "what do you see now?".

## Decision: safe round trip

See DESIGN §8 "Wizard round trip". Summary: only `SwitchInput`; the DDC channel stays alive because the PC does not lose its output; the agent builds the return (30 s deadline, retries) and it does not depend on the UI; without a DDC profile it is not tested (calibrate first or it stays in assisted manual mode). It does not contradict DESIGN §2/§8/§10.

## Criteria

- [x] Exact match by PnP id/name and a single monitor on DDC (tests in `switcher/ddc.rs`).
- [x] The calibration and "use profile" refuse if the bus monitor is not the named one (`add_monitor.rs`).
- [x] Rollback never removes a machine's output before the monitor has come back from its input (`txn.rs`, `orchestrator.rs`, `peer.rs`).
- [x] The wizard's round trip only sends the input of the monitor being tested, with automatic return in the agent (`agent.rs`, agent tests and `tests/wizard.rs` over loopback with the per-input ids of the real desk).
- [x] A transport failure does not discard the database profile (`setup.rs`, `onboarding.test.ts`).
- [x] The disabled "Add" button states the specific reason (same cable, cable not chosen, link not confirmed).
- [x] "Try again" and "Calibrate" do not send changes to a monitor without a verified profile: without a profile only calibrating (PC) or assisted manual mode is offered, and the agent rejects `ProbeInput` without a profile.
- [x] Each monitor's calibration / profile is resolved before the round trip, the initial state and "Apply mode" (`onboarding.test.ts`; step 6 requires step 5 to be verified).

## Notes

- Interpretation of the request "calibrate each monitor before autodetecting whether it is on the Mac or the PC": what was being autodetected was where the monitor is (the Mac was assumed). It was reordered within step 5: first the profile (calibrate or manual), then it asks where it is seen and only then is it tested. The order of steps 4-5-6 did not change. The round-trip, initial state and "Apply mode" steps use that specific monitor's codes through any of its identities (`add_monitor::the_calibrated_profile_is_used_by_the_next_mode_change` and the tests in `switcher/ddc.rs` with the two per-input ids).
- Limit: if the agent dies during the test deadline, the monitor stays on the test input.
- With the desk confirmed, the reopened wizard can no longer test the round trip (the ghost): the UI shows the rejection and the monitor stays manual without losing the profile.
- Step 1 of the wizard was not touched (T-090 touches it).

## Changes after review

- The round trip is refused ([`Plan::probe`]) if the target machine could have removed the monitor from its desktop: only a monitor whose location was never known (`Unknown`) is tested on both machines; if it was ever known (confirmed, from an earlier startup or black) only the return to where it is is accepted. Property test `Op::Probe` in `safety.rs` (fails without the rule).
- Undoing an `Attach` of an unconfirmed monitor no longer removes it (`Step::undo`): nothing is removed when unconfirmed.
- Rollback does not return the input to a machine whose reactivation failed (`txn.rs`); `safety.rs` also injects a second failure in an undo call.
- Protocol v13.
- The return deadline is only cancelled when the mode change succeeds, before releasing the orchestrator.
- The automatic return retries with growing backoff, is retried when the link returns and notifies the UI (`PowerEvent::PeerLost` with the monitor) after 2 min; test with the PC unreachable during the deadline.
- "Mark manual" without knowing where the monitor was does not invent the Mac; the timeout of "what do you see?" does not discard the profile; asking for the return while the automatic one runs answers `Done`.
- The deferred `Detach` of an uncertain step, with an incomplete rollback, is reported in the undo failures instead of being discarded.
- The bus identity guard also applies to a monitor without `edid_model` (it is another one if a different desk monitor recognizes it).
