# T-145 — "Create a new desk" state of setup step 2

## Context

Finding of the acceptance agent (part A), item P8. In `V3-Setup` (state `new`: second option of step 2) the mockup shows the "Desk name" field and the text "Afterwards, on the other machine, choose 'Join a desk'…". The app, when choosing "Create a new desk", shows the pairing code ("MacBook Pro code 4 1 8 0 2 7" and "Waiting for PC-Desktop to type the code…") and not the field. Measured against `docs/mockups-png/V3-Setup--new.png`: **99.27 %, worst tile 83.0 %** (threshold 0.99 / 0.97). The difference is not in the README and `shots-spec.ts` does not measure this state, so it was not seen. Screenshots: `docs/reports/acceptance/2026-11-18-a/new-setup/{app,mockup,diff}.png`.

The Settings mockup already covers the desk name because the agent neither stores nor sends it (DESIGN §3.8: a field that saves nothing is not shown), and `deskName` does not exist in the IPC. One of the two ways out has to be decided (without improvising architecture: if it involves touching the protocol, report it).

## Scope

1. Option A (preferred if the name already exists on the desk): show the "Desk name" field in this state, make it save and sync with the other machine (D4), and show the code below, like the rest of the flow.
2. Option B: document in `mockups/README.md` the allowed difference (the code appears on choosing the option because pairing is symmetric, T-097) and cover only the field's area in the screenshot.
3. In both cases, add the `setup-desk-new` screenshot to `shots-spec.ts` with a threshold ≥ 0.99 / ≥ 0.97.

## Acceptance criteria

- [x] `V3-Setup--new` measured at ≥ 0.99 / ≥ 0.97 with a documented mask or without one.
- [x] No field without a function (G6).
- [x] Quality gate and CI green.
