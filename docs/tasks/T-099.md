# T-099 — Shared configuration

## Context

DECISIONS D4, D5, D17, D18; DESIGN §4.4.

## Scope

1. `Desk` desk document in `tandem-core` with sections: machines (name, color), arrangement (side of the other: top/bottom/left/right; alignment start/center/end; screens per machine), scenes (list; the detailed model is T-100), shortcuts, keyboard and mouse preferences (Cmd↔Ctrl, drag between machines, clipboard), modules on. Version `desk_rev`, author and date.
2. Typed patches (`DeskPatch`) applied by the agent; persistence in `tandem.toml` (atomic write); sync through `ControlMsg::Desk`. **Last write wins** by version + clock; ties go to side `A`.
3. History of the last 20 versions; `UiCommand::UndoDesk { to_rev }`. The UI receives `UiEvent::DeskChanged { by, rev, summary }` for the "Changed from X · Undo" notice.
4. Colors per machine assigned on pairing (the mockups' palette: blue `#7aa7e6`, violet `#a99be8`, teal `#5fbfb0`, amber `#d9a75a`), different from each other, editable.
5. The input engine takes the geometry from the `Desk`'s arrangement (side + alignment → shared edge), with no hand-written X/Y. It keeps the default value when there is no arrangement.

## Acceptance criteria

- [x] Property tests: applying patches in any order with "last write wins" converges to the same `Desk` on both machines; undoing restores exactly the requested version (`tandem-core/tests/props.rs::last_writer_wins_converges_on_both_machines`, `undo_restores_exactly_the_requested_version`).
- [x] Geometry test: the 4 sides × 3 alignments produce the correct crossing edge (with screens of different height/width) (`tandem-input/src/geometry.rs::four_sides_by_three_alignments_give_the_shared_edge`, plus `with_alignment_the_stretch_is_measured_in_logical_points` and the properties on the 4 sides).
- [x] Two-agent scenario: editing on A is seen on B; editing on both at once converges and B gets the notice (`tandemd/tests/network.rs::desk_edits_from_either_ui_converge_and_the_other_gets_the_notice`, which also undoes from B).
- [x] Quality gate and CI green (gate in WSL; CI in the PR).

## Notes

Done:

- `tandem-core`: `Desk` (formerly `Config`, which remains as an alias) with machines, screens, arrangement (4-sided `Side` + `Align`, no X/Y; `Option`: undeclared = the default), scenes (id and name, T-100 completes them), shortcuts (`[shortcuts] lock`), preferences (`[prefs]` Cmd↔Ctrl and drag files) and modules on (`[modules.a]`/`[modules.b]`, including the clipboard). `DeskPatch` + `Desk::apply` (validates; a rejected one changes nothing), `DeskStamp { rev, at, by }`, `DeskVersion::receive` (last write wins) and `DeskHistory` (20 versions, `undo`). 4-color palette and `Machines::distinct_colors`.
- `tandem-proto` v17: `ControlMsg::Desk(Box<DeskVersion>)`, `UiCommand::{EditDesk, UndoDesk, GetDeskHistory}`, `AgentToUi::DeskChanged { by, rev, summary, undo_to }`, `Reply::DeskHistory`.
- `tandemd`: the agent applies patches, undoes, saves to `tandem.toml` (atomic write, keeps comments and each section's place), sends to the other and notifies the UI. Migration of the earlier format (`migrate::desk_v03`) without counting as a change. The input engine takes side + alignment from the desk, and the shortcut and Cmd↔Ctrl (rebuilt if they change).
- `tandem-input`: `Layout` with the 4 sides and the shared span (`shared_span`, `Layout::crossing_span`).

Fixes after the review of #74:

- The migration of `[input] clipboard = false` (it used to be per machine; now it is `[modules.<side>] clipboard`, in the desk) counts as a change by that machine; and with the same stamp and a different desk, `DeskVersion::receive` breaks the tie by the greater desk. Test red first: `tests/network.rs::a_local_setting_moved_to_the_desk_does_not_leave_the_machines_apart`.
- Two-agent tests for what is new in the input engine: `tests/input.rs::turning_off_cmd_ctrl_and_the_clipboard_in_the_desk_changes_both_engines` and `the_lock_shortcut_changed_in_the_desk_applies_without_restarting` (both fail if the engine is not rebuilt).
- Round-trip property through `tandem.toml` with all sections (`config_edit::any_desk_round_trips_through_the_file`); a desk from the other machine with an unknown shortcut is ignored.

Integration with T-098 (#72):

- The module switches live in the desk (`Desk.modules`, text id `ModuleId::as_str`): `SetModule` and `EditDesk { Module }` make the same change, with T-098's checks; each agent copies those of its side (`Agent::sync_switches`). No `ControlMsg::SetModule`. The clipboard has a single source: each machine's "clipboard" module (there is no `prefs.clipboard`). Protocol v18.

Pending outside this task:

- The new UI (T-112) already reads `arrangement` as `{ a_side, align } | null`, but does not edit the desk yet: it still has to use `EditDesk`, `UndoDesk`, `GetDeskHistory` and show `DeskChanged` (screens of T-113 onwards).

The clipboard still is not shared (one side off is enough), but the other's module shows as on, and if the first is later turned on it is shared again. Possible fix: that each one's migration merges its side with the other's on receiving the first desk, or a per-pair migration step.
