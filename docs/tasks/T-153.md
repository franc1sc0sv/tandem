# T-153 — "Measure bandwidth" and other buttons stay disabled forever on reload

Found by the acceptance agent (part B), flows F6 and G6.

## What fails

`Store.can()` calls `source.can()`, which reads a normal field of `LiveSource` (`this.last`), not reactive state. Buttons with `disabled={!store.can(...)}` are evaluated when drawn; if the window opens (or reloads) before the agent's first snapshot arrives, they stay disabled and are not evaluated again. Reproduced with the real UI against a paired pair: reloading on `#/network` leaves "Measure bandwidth" disabled indefinitely (3 s and 30 s later); entering Network from Desk does work. The same happens with "Apply", "Test crossing" and the palette actions that depend on `can()`.

## Screenshots

- App: `docs/reports/acceptance/2026-11-18-b/F6-network/measure-end.png` (the button enabled when arriving from Desk); the reproduction with reload is in the report (G6).

## Expected fix

- `can()` depends on reactive state (for example, `Store` exposes `desk.ready` and the snapshot type, or `LiveSource` keeps `last` in a `$state`), so that the buttons are enabled on connecting.
- Component test: draw "Measure bandwidth" with the source in `connecting`, deliver the first snapshot and check that it becomes enabled.
- Button sweep (`G6`) with no permanently disabled ones with the agent connected.

## Acceptance criteria

- [x] Reloading on `#/network`, `#/monitors`, `#/arrangement` leaves the buttons enabled as soon as there is an agent.
- [x] A test that covers it.
- [x] Quality gate and CI green.
