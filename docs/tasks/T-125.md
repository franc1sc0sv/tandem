# T-125 — Mockup renderer

## Context

DESIGN §12: every app screen must look ≥ 99 % like its mockup. The mockups in `mockups/v03/*.dc.html` use a template format (`<x-dc>`, `<helmet>`, `{{expr}}`, `<sc-for list as hint-placeholder-count>`, `<sc-if value>`, and a `Component extends DCLogic` class with `state`, `setState` and `renderVals()`) whose runtime (`support.js`) is not in the repo.

## Scope

1. `tools/mockup-render/`: an own minimal `support.js` that implements that format: evaluates the class of the `<script type="text/x-dc">`, calls `renderVals()`, substitutes `{{…}}` (text and attributes, including `style` and `onClick`), repeats `sc-for`, shows/hides `sc-if`, inserts the content of `<helmet>` into `<head>`, and re-renders with `setState`. The `href="X.dc.html"` links navigate between mockups.
2. Script `pnpm mockups:shot` (in `apps/tandem-ui` or `tools/`) that opens each mockup with headless Chromium (Playwright), viewport 1280×860 (or each file's `$preview`), waits for the entrance animations to finish and saves `docs/mockups-png/<name>.png`. Also named interactive states (for example `V3-Acomodo` with each side) by means of a list of steps (clicks) per mockup.
3. Comparison utility `compare(app.png, mockup.png) → { similarity, diff.png }` (SSIM or pixelmatch with antialiasing tolerance), used by the tests of each screen (T-113…T-120) and by the acceptance agent.
4. `mockups/README.md` updated with how to render.

## Acceptance criteria

- [x] The 23 mockups in `mockups/v03/` render without console errors and their screenshots look complete (no `{{` in the text; automatic test).
- [x] Comparison test: same image = 1.0; image with a changed block < 0.99.
- [x] CI (UI job on Linux) generates the screenshots as an artifact.

- Follow-up from the review of PR #67: Chromium with `--disable-partial-raster` (with partial raster, 12–13 screenshots of `V3-Acomodo` changed between runs), a character coverage test that also reads the `script[type="text/x-dc"]` and the CSS `content:` values, `mockups:shot` does not delete references if something failed, `worstTile` over an overlapping grid (`tile/2` step), an invalid `--concurrency` gives an error, and `@tandem/mockup-render/harness` (`launchBrowser`, `capture`, `compareWithMockup`) for the T-112 harness.
