# T-125 — Renderizador de mockups

## Context

DESIGN §12: cada pantalla de la app debe parecerse ≥ 99 % a su mockup. Los mockups de `mockups/v03/*.dc.html` usan un formato de plantillas (`<x-dc>`, `<helmet>`, `{{expr}}`, `<sc-for list as hint-placeholder-count>`, `<sc-if value>`, y una clase `Component extends DCLogic` con `state`, `setState` y `renderVals()`) cuyo runtime (`support.js`) no está en el repo.

## Scope

1. `tools/mockup-render/`: un `support.js` propio y mínimo que implementa ese formato: evalúa la clase del `<script type="text/x-dc">`, llama `renderVals()`, sustituye `{{…}}` (texto y atributos, incluidos `style` y `onClick`), repite `sc-for`, muestra/oculta `sc-if`, inserta el contenido de `<helmet>` en `<head>`, y vuelve a renderizar con `setState`. Los enlaces `href="X.dc.html"` navegan entre mockups.
2. Script `pnpm mockups:shot` (en `apps/tandem-ui` o `tools/`) que abre cada mockup con Chromium headless (Playwright), viewport 1280×860 (o el `$preview` de cada archivo), espera a que terminen las animaciones de entrada y guarda `docs/mockups-png/<nombre>.png`. También estados interactivos nombrados (por ejemplo `V3-Acomodo` con cada lado) mediante una lista de pasos (clics) por mockup.
3. Utilidad de comparación `compare(app.png, mockup.png) → { similarity, diff.png }` (SSIM o pixelmatch con tolerancia de antialias), usada por las pruebas de cada pantalla (T-113…T-120) y por el agente de aceptación.
4. `mockups/README.md` actualizado con cómo renderizar.

## Acceptance criteria

- [x] Los 23 mockups de `mockups/v03/` renderizan sin errores de consola y sus capturas se ven completas (sin `{{` en el texto; prueba automática).
- [x] Prueba de la comparación: misma imagen = 1.0; imagen con un bloque cambiado < 0.99.
- [x] CI (job de UI en Linux) genera las capturas como artefacto.

## Notes
