# T-076 — Release in CI

## Scope

GitHub Actions workflow that, on pushing a `v*` tag or by hand, builds the macOS and Windows installers, generates checksums and creates a draft release with the artifacts and notes generated from the integrated tasks.

## Acceptance criteria

- [x] A manual run (workflow_dispatch) in test mode produces the two installers and checksums as artifacts, without publishing a release.
- [x] docs/dev/release.md.

## Notes

- Workflow `.github/workflows/release.yml`: `v*` tag → draft release; by hand (`workflow_dispatch`) with the `prueba` input (`true` by default) → artifacts only; PR that touches the workflow or `scripts/release/` → test mode. Jobs: `prepare` (version, mode, notes), `dmg (macos-latest)`, `installer (windows)` (with the install/uninstall test), `checksums` (`SHA256SUMS.txt` and the `tandem-<version>` artifact) and `release (draft)`, the only one with `contents: write` and which does not run in test mode.
- `scripts/release/version.sh`: the version has to match in `Cargo.toml`, `tauri.conf.json` and `package.json`, and the tag must be `v<version>`.
- `scripts/release/notes.sh`: notes since the previous tag from the `T-<id>: ... (#pr)` squashes, grouped by each task's phase, with "Other changes" and the list of tasks with pending hardware verification.
- `scripts/release/test.sh`: tests of the two scripts on throwaway repos; run by `prepare` and the CI's Ubuntu job.
- `workflow_dispatch` can only be launched once the workflow is on `main` (default branch), which only the user touches. Test mode was checked with the PR trigger, which follows the same path (same jobs, without `release`).
- Real signing (Developer ID / Authenticode) in the release is left for when the user loads the secrets; see `docs/dev/release.md`.
