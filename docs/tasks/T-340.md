# T-340 — The monitor is recognized by its EDID, not only by its DDC channel

Found on real hardware on 2026-11-19 (v0.3.0, Mac on HDMI and PC on DP to the same 34").

## What fails

- **Live desktops shows two monitors** where there is one. `screen-1 · <PC>` is the 34" over DP. `screen-2 · Mac` is the same 34" over HDMI. On the Mac that screen is a phantom: while the 34" shows the PC, macOS still has the HDMI display, and the Mac's cursor walks into a screen nobody sees.
- **The Monitors screen only shows the PC's connection** (`<PC> · DP`), never the Mac's HDMI.
- The shared desk has `[[cables]] monitor = "lc34g55t-…"`, `a = { input = "display_port" }`, `b = { input = "hdmi" }`, but **no `screen` on either end**. Nothing fills it. Without it, T-111's rule ("a monitor that shows the other machine stops being a screen of this one", `crates/tandemd/src/input/screens.rs`) has nothing to remove.

## Cause

- `tandem_monitor::local::Local::scan` drops every monitor whose probe gives `Probe::NoChannel` (`continue`). The 34" only answers DDC on HDMI while HDMI is its active input (confirmed in `monitor-firmware`, `docs/targets/lc34g55t/journal.md`). So while it shows the PC, the Mac does not announce it at all, and its EDID never reaches the desk.
- `monitor-ddc`'s macOS backend already enumerates every external display (`DCPAVServiceProxy`, location `External`) **with its EDID**, channel or not (`MacBus::monitors`). The EDID is there; Tandem throws it away.
- Nothing maps a monitor id to the machine's screen id (`screen-N`, from `input::screens::detected`).

Hardware log, Mac, 2026-11-19, with the 34" on HDMI at start: `this machine is the owner: starts reading monitor=lc34g55t-…` (the Mac computed the same id as the PC). After the scene moved it to the PC: `no DDC channel: no valid reply to VCP 0xea`.

## Scope

1. A monitor seen with an EDID but without a channel is still reported, as **present without a channel**. It never becomes owner, it is never written to, and it does not enter the election. Protocol change in `Capabilities` or the monitor report, with the version bump that `scripts/ci/protocol.sh` asks for.
2. Each machine links each present monitor to its own screen id: macOS through CoreGraphics (`CGDisplayVendorNumber` / `CGDisplayModelNumber` / `CGDisplaySerialNumber` or the IOKit display registry, matched to the EDID's vendor, product and serial), Windows through the EDID of the display path of each monitor. Behind a trait with a test double.
3. The agent writes the learned screen into `[[cables]].<side>.screen` (one desk change, synced like any other), unless the user declared one by hand.
4. The UI shows **one** monitor with both connections (`<PC> · DP`, `Mac · HDMI`) and Live desktops draws it once, on the machine it shows.
5. With the 34" on the PC, the Mac's HDMI screen leaves the Mac's input geometry, and comes back when the scene gives the 34" to the Mac.

## Acceptance criteria

- [ ] `Local::scan` test: a monitor with an EDID and `NoChannel` is reported as present without a channel, and is never opened for writing nor elected owner.
- [ ] Two-agent test (`tandem-sim`): one machine with a channel (DP), the other present only (HDMI); the desk ends up with both `screen` ends filled and the geometry drops the screen of the machine the monitor does not show.
- [ ] A screen declared by hand in `[[cables]]` is never overwritten.
- [ ] UI (vitest + screenshot): one monitor card with both connections; Live desktops draws the 34" once.
- [ ] DESIGN §10 and §7 say a monitor is linked by EDID even without a channel.
- [ ] Quality gate and CI green.
