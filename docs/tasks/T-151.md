# T-151 — The setup's "Keyboard and mouse" step detects nothing

Found by the acceptance agent (part B), flow F1.

## What fails

1. `deviceRows()` (`apps/tandem-ui/src/lib/wizard.ts`) falls back to the input module when the machine does not list devices, and `live.ts` never fills `inputDevices`. Result measured with two real agents: a machine with **no keyboard or mouse connected at all** (`hub_here: false`) shows the green "Keyboard and mouse" mark all the same, and the one that does have it too; what was detected cannot be told apart from what was assumed. The agent already knows where the hub is (`input.hub_here`, `caps.here.hub`).
2. "Activity detected" from the **other** machine never appears: the UI only marks the activity of its own window (local `heard(...)`) and never sends `Action::HeardKey`, which is what makes the agent notify the other one (`agent/setup.rs::heard_key`). It was tested with a key pressed in B's window: A does not see it.

## Expected fix

- `inputDevices` comes from what the agent announces (hub, keyboard and mouse by name); with no device, the row says "No keyboard or mouse right now".
- The window sends `heard_key` on hearing a key or a movement during the probe; the other machine shows it as "Activity detected".
- Tests: vitest with the simulated bridge and a test with two agents (one with a double hub, the other without).

## Acceptance criteria

- [x] Each machine's row lists only what the agent detects.
- [x] Physical activity on one machine appears in the other's UI.
- [x] End-to-end test (F1) and CI green.

## Notes

- `inputDevices` comes from `caps.here.hub` (`devicesOfHub`); without a hub, "No keyboard or mouse right now". The window sends `heard_key` (`Store.reportHeardKey`) on the first activity; the other machine sees it through the `key_probe` notice. Tests: `wizard-ipc.test.ts` (simulated bridge) and `wizard.test.ts`.
- Two-agent test: `crates/tandemd/tests/input.rs` checks that the PC's hub is announced (here and on the other side) and that the Mac does not have it. The first key before the probe is armed is forwarded when it is armed (`StepInput.svelte`).
- The summary requires the tunnels module not to be off and at least one environment ready (`computeWorks`).
