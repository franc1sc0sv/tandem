# T-260 — Document the protocol version

## Context

Failure found by the acceptance agent, part C, round 4 (2026-11-19, `origin/develop` 8504769). See `docs/reports/acceptance-2026-11-19-c4.md`.

## Failure

Documents consistent with code. `crates/tandem-proto/src/lib.rs` has `PROTOCOL_VERSION: u16 = 41` (bumped by T-240, `KeyProbeMsg::Armed`), together with `CAPABILITIES_SINCE = 10` and `SIDES_SINCE = 16`. No file under `docs/` says what the current version is, that only the same version talks (the two agents and the UI ship together), when it must be bumped, or what the `*_SINCE` constants mean. `docs/DESIGN.md` §4 only says "typed messages ... versioned". The only mentions are `docs/DECISIONS.md` line 105 and `docs/dev/release.md` ("another protocol version"), which never give the number. The secure-desktop pipe has its own, separate `PROTOCOL_VERSION = 1` (`crates/tandemd/src/secure/protocol.rs`), also unmentioned as a distinct thing.

## Expected fix

- Add a short "Protocol versioning" subsection to `docs/DESIGN.md` §4: the current version (41), the rule (same version only; bump on any incompatible message change), the `CAPABILITIES_SINCE` / `SIDES_SINCE` hints, and that the secure-desktop pipe versions independently (link `docs/dev/secure-desktop.md`).
- Add a check to `scripts/ci/` (run in `ci.yml`) that the number in the docs equals `PROTOCOL_VERSION`, so the next bump cannot leave it stale. If a bump PR must touch the docs, say so in `CLAUDE.md` "Backlog protocol".

## Acceptance criteria

- [ ] `docs/DESIGN.md` states the current protocol version and the rule.
- [ ] A CI script fails when the documented number differs from `PROTOCOL_VERSION`.
- [ ] Quality gate and CI green.
