# T-223 — Relabelled candidates must not collide

Found by the acceptance agent (part B, round 3, `docs/reports/acceptance-2026-11-18-b3.md`) while checking T-196 on a machine with a real link-local interface.

## What fails

`relabel` (`crates/tandem-link/src/iface/classify.rs`) gives each configured peer the kind of the local interface that routes to it. Two configured peers that fall on the same kind end up as two candidates with the same `LinkKind`, and `spawn_manager` (`crates/tandemd/src/network.rs`) rejects the set with `ManagerError::DuplicateLink`. The only trace is a log line, and the agent runs with **no link at all**.

Reproduction (`docs/reports/acceptance/2026-11-18-b3/harness/t196.mjs`, run on a box whose `eth1` has `169.254.252.182` and an `fe80::` address; `tandemd links` lists it as Ethernet):

```
peers = [{ kind = "wifi", addr = "169.254.252.182:<port>" },
         { kind = "ethernet", addr = "[fe80::...%3]:<port>" }]
```

Both are classified Ethernet. The log says `could not start the link manager: the link Ethernet is configured twice`; the peer shows `paired` with `link: null`, and `tandemd links` shows every path as "no cable - no reply". Before T-196 the declared kinds (`wifi`, `ethernet`) were kept and it connected.

Each peer on its own works as T-196 intends: the IPv4 link-local peer declared as `wifi` is reported as Ethernet and connects, and the IPv6 link-local one with its scope id connects too (`t196.mjs v4` and `t196.mjs v6`).

By reading the code, the same collision should happen with two peers in the same `/24` declared with different kinds (not measured).

## Expected fix

- After relabelling, keep one candidate per kind (the declared peer wins over a discovered one, or the first in priority order) instead of failing, and log a warning that names the two addresses.
- Surface "link manager not running" in the UI as a trouble state instead of only logging it.
- Tests with simulated interface tables: two configured peers on the same interface and on different interfaces.

## Acceptance criteria

- [ ] Two configured peers that classify to the same kind no longer stop the link manager; one connects and a warning explains the other.
- [ ] A test for the case above that fails before the fix.
- [ ] If the link manager cannot start for any reason, the UI shows a trouble state with the reason.
- [ ] Quality gate and CI green.
