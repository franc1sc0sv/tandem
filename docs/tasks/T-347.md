# T-347 — A channel from the Mac at all times

## Context

The task was blocked on a firmware patch so that the 34" would answer DDC/CI on its inactive HDMI input. The read-only experiment of 2026-11-20 (`monitor-firmware` PR #2, `docs/targets/lc34g55t/inactive-hdmi-ddc.md`, section "Result of the experiment") showed that **no patch is needed**: with the monitor showing DP (the PC) and the Mac's HDMI cable plugged in, the Mac's raw IOAVService requests `Get 0x10`, `0xEA` and `0x60` all got valid replies on the first try (`0x60` = `0x09`, the DP input actually shown). The 2026-11-15 failure was a test artefact; the first attempt on 2026-11-20 found the HDMI cable unplugged, and then macOS lists no external IOAVService at all.

So the assumption written in DESIGN §10 "Present without a channel (T-340)", "the 34" only answers DDC on the input it shows", is wrong for this monitor. The shared request buffer and the global event cursor still hold, so T-346's one-talker rule stays.

## Scope

1. DESIGN §10 (T-340, T-341, T-346 paragraphs) and DECISIONS: the 34" answers DDC/CI on both inputs while each source is connected; `NoChannel` now means the probe really failed (DDC/CI off in the OSD, a cable or adapter without DDC, macOS without the IOAVService), not "the monitor shows the other input".
2. The Mac's probe on macOS (`monitor-ddc`, IOAVService) must get the channel on the inactive input as reliably as the experiment's tool did: one retry when the DCP drops the first write, a short wait before the read. If the pinned `monitor-ddc` lacks that, fix it there (repo `monitor-firmware`, crate `monitor-ddc`) and pin the new commit.
3. With both machines holding a channel, the election and T-346 work unchanged: the owner talks, the other one only probes on scans and reads directly while the owner is unreachable. Add a `tandem-sim` test with both machines having a channel while the monitor shows A, and the same with B.
4. Remove the "waiting for the firmware" wording from the UI and docs, if any.

## Acceptance criteria

- [ ] DESIGN and DECISIONS updated as in item 1.
- [ ] The macOS probe retries a dropped first write (test with the simulated bus dropping the first write).
- [ ] `tandem-sim` test: both machines with a channel, monitor on A and then on B; one owner, the other never reads events.
- [ ] Quality gate and CI green.
