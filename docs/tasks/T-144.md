# T-144 — Measure the interactive states that `shots-spec.ts` does not cover

## Context

Finding of the acceptance agent (part A). `docs/mockups-png/` has screenshots of states that no app screenshot compares: `V3-Puesto--escena-solo-macbook`, `V3-Puesto--escena-juego` (apply a scene from the Desk), `F-Paleta--filtro`, `F-Paleta--sin-resultados` and `F-Avisos--cerrado` (close the first notice). They were measured in this run with temporary screenshots: Desk (click on "MacBook only" and on "Game") 99.99 % / 98.4 %, `F-Avisos--cerrado` 99.98 % / 99.4 % and `F-Paleta--sin-resultados` ("zzz") 99.96 % / 97.1 %: they pass, but nothing requires it. `F-Paleta--filtro` came out 99.37 % / 86.0 %: the mockup, when the field is filled with `fill`, does not filter the list (it keeps all the rows and "esc" typed), so the state does not represent a filter; it has to be regenerated by typing key by key in `tools/mockup-render/src/states.ts`.

`docs/ACCEPTANCE.md` also contradicts the mockups in P6: it says the mockup does not draw the crossing test "timed out" and lists "wrong edge" as comparable; in reality `F-PruebaCruce--no-cruza` draws "Did not cross in 20 s" (timed out) and it is "Crossed through another edge" that does not exist (`cruce-otro-borde` already goes without a threshold).

## Scope

1. Add to `shots-spec.ts` the screenshots with a threshold of the four states that pass, and change the mockup's `filtro` state so that it filters (typing), with its app screenshot.
2. Correct in `docs/ACCEPTANCE.md` (P6 and the note "States the mockup does not draw") which crossing-test state the mockup draws.
3. Regenerate `docs/mockups-png/` and `docs/screenshots/v03/`.

## Acceptance criteria

- [x] Each state in `docs/mockups-png/` with a counterpart in the app has a screenshot with a threshold ≥ 0.99 / ≥ 0.97 (or a documented exception in the README).
- [x] `ACCEPTANCE.md` matches what the mockups draw.
- [x] Quality gate and CI green.
