# T-141 — Short Tunnels labels with two machines of the same system

## Context

Finding of the acceptance agent (part A), rule G2/D2. `shortLabels` (`apps/tandem-ui/src/lib/tunnels.ts`) uses "Mac"/"PC" if the systems differ, and otherwise the first word of the name split by space or hyphen. With `?demo=win-win` (`PC-Desktop` and `PC-Workshop`) the first word is "PC" on both and each tunnel says "PC → PC"; with `?demo=mac-mac` (`MacBook Pro`, `Mac mini`) it comes out as "MacBook → Mac", which cannot be told apart at a glance either. The tunnel list, the selected tunnel and the tray do not say which one is the origin. Screenshot: `docs/reports/acceptance/2026-11-18-a/tunnels-win-win/app.png`.

## Scope

1. `shortLabels` must return two different labels whenever the machines are different: with different systems, as today (same as the mockup); with the same system, the part of the name that tells them apart (for example `Desktop`/`Workshop`, `Pro`/`mini`) or the full name if there is no other way.
2. Tests, including a property test (`proptest`/`fast-check` equivalent in vitest) that two different names never give the same label, and the `win-win` and `mac-mac` cases.
3. Review the other places that use short labels (tray, palette) with the three demo pairs.

## Acceptance criteria

- [x] `?demo=win-win` and `?demo=mac-mac` show different labels in the list, the tube and the tray.
- [x] The `mac-win` pair stays identical (similarity of `tunnels*` unchanged).
- [x] Quality gate and CI green.

## Notes

`shortLabels` uses, with the same system, the first word if it tells them apart; if not, what follows ("Desktop"/"Workshop", "Pro"/"mini"); and the full name as a last resort. Property test with `fast-check` (new dependency, exact). Only `Tunnels.svelte` uses short labels; the tray and the tube use the full names, already different.
