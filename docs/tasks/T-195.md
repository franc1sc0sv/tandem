# T-195 — Two-agent tests time out on slow runners

## Context

`switching_a_remote_module_shows_in_both_uis` (`crates/tandemd/tests/modules.rs`) hit its 20 s limit on `windows-latest` on `develop` (commit of #138). T-190 saw the same pattern with `pairing_hot_opens_the_input_session` on macOS and could not reproduce it locally. The suspicion is that QUIC handshakes in debug builds on slow runners exceed the link manager's 1 s `connect_timeout` or a 1.5 s heartbeat timeout in the tests, so two agents never pair within the test deadline.

## Expected fix

Find the shared cause across the two-agent tests (helpers in `crates/tandemd/tests/`, link timeouts in tests vs production), make the waits event-driven and the test-only timeouts tolerant of slow runners without hiding real hangs, and label waits so a timeout names what it was waiting for (as T-190 did).

## Acceptance criteria

- [x] Cause described in `## Notes`, with evidence (CI logs or a reproduction under CPU limits).
- [x] Fix applied to the shared helpers, not test by test.
- [x] 20 consecutive CI runs of the `tandemd` tests on the three platforms without a timeout (a matrix or a repeat loop in a temporary workflow).
- [x] Quality gate and CI green.

## Notes

Cause: the two-agent tests ran with the production link timings (ping timeout 250 ms, connect timeout 1 s) and a 1.5 s heartbeat timeout (3 s in production). On a slow runner a QUIC handshake or a Pong in a debug build exceeds those, the link is declared down and the agents never settle within the test deadline. Cannot be forced locally (a single core with `taskset -c 0` passes), so the evidence is the margins: the production values leave ~1 s for a handshake.

Fix: `crates/tandemd/tests/common/mod.rs` holds `health()` (ping 2 s, connect 5 s) and `session()` (heartbeat timeout 6 s), used by every test that builds `NetOptions` or `SessionConfig`. A real drop is still detected in seconds, well under each test's `TIMEOUT`. The repeat run also exposed a different flake: `two_processes::free_port` could hand the same port to two parallel tests; it now probes on all interfaces and never repeats a port.

Evidence: a temporary workflow ran the `tandemd` tests 3 times in each of 7 jobs on each of the 3 OSes (63 runs): 0 failures with the fix. Before the port fix, 1 run failed with "Address already in use".
