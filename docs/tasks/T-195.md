# T-195 — Two-agent tests time out on slow runners

## Context

`switching_a_remote_module_shows_in_both_uis` (`crates/tandemd/tests/modules.rs`) hit its 20 s limit on `windows-latest` on `develop` (commit of #138). T-190 saw the same pattern with `pairing_hot_opens_the_input_session` on macOS and could not reproduce it locally. The suspicion is that QUIC handshakes in debug builds on slow runners exceed the link manager's 1 s `connect_timeout` or a 1.5 s heartbeat timeout in the tests, so two agents never pair within the test deadline.

## Expected fix

Find the shared cause across the two-agent tests (helpers in `crates/tandemd/tests/`, link timeouts in tests vs production), make the waits event-driven and the test-only timeouts tolerant of slow runners without hiding real hangs, and label waits so a timeout names what it was waiting for (as T-190 did).

## Acceptance criteria

- [ ] Cause described in `## Notes`, with evidence (CI logs or a reproduction under CPU limits).
- [ ] Fix applied to the shared helpers, not test by test.
- [ ] 20 consecutive CI runs of the `tandemd` tests on the three platforms without a timeout (a matrix or a repeat loop in a temporary workflow).
- [ ] Quality gate and CI green.
