# T-343 — One agent per data directory

Found on real hardware on 2026-11-19. While diagnosing the Mac agent that died (fixed by T-331…T-334: kickstart a loaded job that is not running, `KeepAlive = true`, ignore a plain Quit Apple event, log why the process ends), `pkill -f …/tandemd` did not stop a running agent within a second, and a second `tandemd` started next to it from a terminal with the same identity. The PC logged `the peer closed the control stream` several times while the two Mac agents took turns on the link, and the IPC socket of the first one was replaced.

## Scope

1. At start-up, before the IPC socket or pipe and the QUIC endpoint, the agent takes an exclusive lock on its data directory (a lock file held for the life of the process; released by the OS on any exit, including `kill -9`).
2. If the lock is held, the agent logs which PID holds it and exits with an error code, without touching the socket, the state or the trust file of the running one.
3. `--check-config` and the other one-shot CLI commands that do not serve do not take the lock.

## Acceptance criteria

- [ ] Test: a second agent on the same data directory exits with an error, and the first keeps serving IPC (Linux CI, real processes).
- [ ] Test: after the first agent is killed with SIGKILL, a new one starts.
- [ ] Windows and macOS CI green with the same tests.
- [ ] Quality gate and CI green.
