# T-343 — The Mac agent dies and stays dead

Found on real hardware on 2026-11-19, during setup step 3 (permissions).

## What happens

- `tandemd` started (`IPC listening`, QUIC on 52000) and about 30 s later was gone, **with no line in its log** (no `shutting down`). `launchctl print`: `state = not running`, `last exit code = 0`, `job state = exited`. The socket stayed on disk.
- It happened while the user was turning on Accessibility and Input Monitoring for Tandem. Likely, not confirmed: macOS's "Quit & Reopen" after granting a privacy permission kills every process of the `Tandem.app` bundle, `tandemd` included, and reopens only the app.
- The LaunchAgent (`apps/tandem-ui/src-tauri/src/launch_agent.rs`) has `KeepAlive = { SuccessfulExit = false }`: an exit with code 0 is not restarted. The app sees the plist loaded and does nothing. The UI showed "tandemd is not running: nobody is listening on the local IPC" until the user ran `launchctl kickstart -k` by hand.
- In the same session `pkill -f …/tandemd` did not stop a running agent within a second, and a second agent started next to it with the same identity; the PC saw `the peer closed the control stream` several times.

## Scope

1. The agent logs why it ends: the signal it got (SIGTERM, SIGHUP, SIGINT), a normal shutdown, or a panic, before it exits.
2. Whatever kills it, launchd brings it back: `KeepAlive = true` (with the existing `ThrottleInterval`), unless DESIGN says why not. An explicit "Quit Tandem" from the app stops it on purpose with `launchctl bootout` and is the only way to keep it stopped.
3. The app, when the plist is loaded but the job is not running, kickstarts it and says so, instead of waiting.
4. A second `tandemd` for the same user and data directory refuses to start (lock on the data directory), logs which PID holds it and exits with an error code.

## Acceptance criteria

- [ ] Tests: the plist generator gives `KeepAlive` true; the app's reconcile logic kickstarts a loaded job that is not running (with a launchctl double).
- [ ] Test: a second agent on the same data directory exits with an error and does not touch the socket of the first.
- [ ] The agent's log has a final line with the reason on SIGTERM, SIGINT and a panic (test with the signal sent to a child process on Linux/macOS CI).
- [ ] `docs/dev/install-macos.md` describes the new behaviour.
- [ ] Quality gate and CI green.

## Pending hardware verification
