# T-077 — DDC calibration engine

## Scope

Portable engine in `tandem-display::calibrate` that finds the input codes of an unknown monitor, based on what was learned in T-050 (`docs/research/ddc-34-LC34G55T.md`, `ddc-32-odyssey-g5.md`):
- **Candidates ordered by probability:** (1) what the monitor reports at `0x60` while on each input (the user puts the monitor on that input from its menu and the engine reads); (2) standard MCCS (`0x0F`/`0x10` DP, `0x11`/`0x12` HDMI); (3) the values declared in the capabilities string; (4) codes from the same brand in the profile database; (5) sweep `0x01`–`0x1F` as a last resort. No duplicates.
- **Testing each candidate** with a `Confirmer` trait (is the target machine visible on that monitor?), with a timeout (8 s by default) and **always automatic return** to the starting input with an already verified code (the starting one is verified first).
- State machine with observable progress (events), cancelable at any moment leaving the monitor on the starting input.
- Result: a profile (`InputCodes` + metadata) ready to save or export.
- Simulated monitors in the tests that reproduce the two real Samsungs (they lie in the list, report the code of the current input, one code goes to black).

## Acceptance criteria

- [x] With the 34" and 32" doubles the engine finds exactly their real profiles, and the candidate order makes the 32" resolve on the first HDMI attempt (reported reading).
- [x] If no candidate works, it returns `NoWorkingCode` and the monitor stays on the starting input (test).
- [x] Cancelling midway leaves the monitor on the starting input (test).
- [x] Property test: for any simulated monitor with a valid code in the range, the engine finds it and never ends up off the starting input.

## Notes

- `tandem-display::calibrate`: `calibrate(bus, &CalibrationRequest, &dyn Confirmer, &CancelToken, on_event)` (async). Returns `CalibratedProfile` (`InputCodes` with one code per input, PnP id, EDID name, `0x60` readings per input, declared values, MCCS version, attempts) and `ddc_profile()` for `[[monitors]].ddc`.
- **How the return is verified first:** without a return code, no code that could take the monitor off the starting input is sent. So the walk is: read capabilities and `0x60` on the starting input → ask the user to switch the monitor to the other input from its menu (`ProbeKind::UserSwitch`, 120 s) and read `0x60` there → from the other input, try candidates for the starting one until its machine is seen (return code verified) → try those for the other input, returning with the verified code after each one, whether seen or not.
- Candidates (`calibrate::candidates::ordered`): reading for that input, MCCS (`0x0F`/`0x10` DP, `0x11`/`0x12` HDMI), those declared in `60(...)`, those for that input in profiles of the same manufacturer (`BrandProfile`, provided by the caller; T-079 will take them from the database) and the `0x01`–`0x1F` sweep. No duplicates, no `0x00` and without the return code (a code does not select two inputs; the 34" reads `0x09` on HDMI too).
- `Confirmer` (`confirm(&Probe) -> Result<bool, ConfirmError>`): the `Probe` carries the `MonitorInfo`, the input that should be visible, the kind (candidate or manual switch) and the timeout (8 s by default). The engine cuts at the timeout and counts it as not seen, so the real confirmer may never answer; when the future is dropped it must remove the probe (T-078).
- If something fails or is cancelled off the starting input: with a return code, it returns with it (with retries, not cancelable); without it, or if the return fails, the user is asked to go back by hand. If they do not confirm either, `NotReturned`.
- Events: `CalibrationEvent::{State, Declared, Reported, Trying, Seen, Returned, Found}`; `State` = `Reading`, `UserSwitch`, `Testing`, `Done`, `Cancelled`, `Failed`.
- The bus is used directly from the future (each DDC operation takes tens of ms); T-078/T-080 should run the calibration on its own thread.
- Simulated monitors in `calibrate::sim` (public, for T-078/T-080 and demo mode): `samsung_34()` (obeys `0x03`/`0x06` HDMI and `0x09` DP, always reads `0x09`) and `samsung_32()` (`0x05` HDMI, `0x0F` DP, `0x06` to black, reads the code of the current input), both with their real capabilities. `SimMonitor` is bus and user at the same time; `silent_when_unseen` imitates nobody clicking.
- With the Samsung profile database the 34" comes out `HDMI 0x06 / DP 0x09` on the fifth HDMI attempt (0x06 comes from the brand). Without the database, the sweep gives `0x03`, which also works (separate test).
- Tests: 20 unit tests (the two Samsungs, black, timeouts, `NoWorkingCode` on each input, user who does not switch or does not return, cancellation with and without a return code, retries, failed return, confirmer error) and properties (candidate order; for arbitrary monitors with one valid code per input: it finds them, never leaves two consecutive candidates without a return and ends on the starting input, also without a code for the other input and cancelling after any event).
