# T-130 — The other machine never receives credentials

## Context

The user's real use (2026-11-17): one machine with the credentials (GitHub, tokens, SSH) and another that only runs commands through a tunnel and returns results, over the USB4 cable. The one that executes may be a company-managed machine (antivirus/MDM) to which no access to anything is meant to be given. The code is sent with the workspace (T-107), run with processes (T-104) and comes back as a branch; the `push` is done from the machine with credentials.

Already today: processes do not inherit the source's environment (only an explicit `launch.env`) and the workspace travels with git, so what is in `.gitignore` is not copied. What is missing is for the rule to be guaranteed, not implicit.

## Scope

1. Decision in DECISIONS: "the destination machine of a tunnel never receives credentials from the source".
2. **Secrets filter** in workspace (T-107) and files (T-106): reject by default, even if they are not in `.gitignore`, `.env*`, `*.pem`, `*.key`, `id_rsa*`/`id_ed25519*`, `.ssh/`, `.aws/`, `.config/gh/`, `.git-credentials`, `.npmrc`/`.pypirc` with a token, etc. List in a single place, with an explicit option to include a specific file.
3. **Process environment** (T-104): reject or warn about variables that look like secrets (`*_TOKEN`, `*_SECRET`, `*_KEY`, `GH_*`, `AWS_*`…) unless explicitly allowed per call; never forward `SSH_AUTH_SOCK` nor agents.
4. The destination's git has no remotes with credentials: the workspace arrives without `origin` (or with a fake remote) and without `credential.helper`.
5. MCP/CLI (T-108): the tool warns when a file was skipped by the filter.

## Acceptance criteria

- [x] Tests: a workspace with a non-ignored `.env`, an SSH key and an `.npmrc` with a token → none of that reaches the destination; the report says so.
- [x] Test: an `exec` with `GH_TOKEN` in `env` is rejected without explicit permission.
- [x] Test: the destination's repo has no remotes nor credential helper.
- [x] Quality gate and CI green.

## Notes

Done (protocol v37):

- `tandem_files::secrets`: the single list (`SecretFilter`, `looks_secret`) with `include` by exact path; `Source::scan_with` applies it in `put` and in `get` (the destination filters what it sends) and `FilesReport.skipped` reports it. `Files::put_with` receives the `include`.
- Workspace: after `add -A` in the temporary index the changes are listed, the credentials go back to `HEAD` in that index (`reset`) and are noted in `Opened.skipped`; copied submodules go through the same filter. `Reply::Tunnel { tunnel, skipped }`.

- MCP/CLI: `include_secrets`, `allow_secret_env`, and `skipped` + `warning` in the responses (the CLI, through stderr). Tests: unit and property tests of the two lists, `tandem-workspace/tests/roundtrip.rs` (real git) and `tandem-cli/tests/e2e.rs::la_otra_maquina_nunca_recibe_credenciales` with two agents (`start_pair!`).
