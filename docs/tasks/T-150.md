# T-150 — Arrangement and crossing test do not use what the engine knows

Found by the acceptance agent (part B, `docs/reports/acceptance-2026-11-18-b.md`), flows F1 and F2, screens P5 and P6.

## What fails

With two real `tandemd` over loopback (with a double input engine) and the production UI connected to one of them:

- `LiveSource.watchCrossing()` (`apps/tandem-ui/src/lib/store/live.ts`) always throws "The agent does not report the cursor crossing yet".
- `LiveSource.can("crossing")` always returns `false`: in Arrangement the "Test crossing" button stays disabled (the button sweep marks it "no effect").
- In the setup, step 5 "Arrangement and crossing test", "Test crossing" ends in "The crossing cannot be tested yet: The agent does not report the cursor crossing yet" and "Continue" stays in a waiting state (`store.wizardCrossed` never becomes `true`); the step 6 summary says "crossing untested".
- The `#/acomodo/cruce` screen shows the same error and cannot reach "Crossed correctly", "Crossed through another edge" nor "Did not cross in 20 s".

## And the arrangement screens

`layoutFromDesk()` (`apps/tandem-ui/src/lib/store/live.ts`) only knows the `[[screens]]` declared in `tandem.toml`. Without them (the normal case after pairing) the engine does use the screens each system reads, but the UI receives zero screens and draws a 16×10 rectangle per machine with **Size, Resolution, Aspect ratio and Scale at "—"** (violates "desktops at real scale" in `docs/DECISIONS.md`). With two agents whose engines read 1920×1080 and 3440×1440, Arrangement and setup step 5 show two equal boxes and no data. Saving the arrangement does work: the 12 cases (4 sides × 3 alignments) reach both machines, `[arrangement]` and the engine's geometry (crossing through the new edge passes, through the old one does not).

## What already exists

The agent does report the crossing: `watch_cursor` answers `done` and the engine emits `Notice::Crossed`/`Notice::Cursor` (T-128). What is missing is connecting it to the UI.

## Expected fix

1. `LiveSource.watchCrossing` subscribes `watch_cursor` and converts `Notice::Crossed`/`Notice::Cursor` into the `CrossSample` that `crossing.ts` already uses (the real cursor, not an invented sample); `can("crossing")` is true with the paired machines.
2. Setup step 5 and `#/acomodo/cruce` go through their four states with a real crossing of the double input engine (integration test with two agents in the same process: crossing through the marked edge passes, through another edge gives "wrong edge", no crossing gives "timed out").
3. The IPC exposes the screens each engine reads (id, position, size in pixels, scale) and `layoutFromDesk` uses them when there are no `[[screens]]`; the drawing respects the real proportion between the two machines.
4. Remove this case's exception in the live UI tests.

## Acceptance criteria

- [x] Setup step 5: the test passes with a real crossing and enables "Continue"; the summary says "crossing tested".
- [x] Arrangement and step 5 show real resolution, aspect ratio and scale, at scale with each other.

## Notes

- Protocol v38: `InputStatus` carries `screens` (those the engine reads here) and `peer_screens` (those the other machine announced); the window exposes them in `input.screens` / `input.peer_screens` and `layoutFromDesk` uses them if there are no `[[screens]]`.
- `LiveSource.watchCrossing` subscribes `watch_cursor`; each `Crossed` is a real crossing. The entry point (`at`/`of`) comes from the first cursor sample on the other machine; if it does not arrive within 250 ms, it is reported without a position (`of: 0`) and the screen omits that datum. The latency shown is how long that first sample took.
- Physical size stays at "—": the engine does not read it (the criterion asks for resolution, aspect ratio and scale).
- The Arrangement similarity (≥ 0.99) does not change: demo mode draws the same as before.
- Two-agent tests (`crates/tandemd/tests/input.rs`): with `WatchCursor`, the double engine emits `Crossed` and `Cursor` through the marked edge, emits nothing against another edge and nothing without movement (timed out). The UI is tested with the simulated bridge (including "Did not cross in 20 s" with a fake clock).
- Without an arrival sample within 250 ms the crossing is reported with `of: 0` and `ms: null`: the screen shows neither position nor latency.
- Criterion removed from the list (T-193): the Playwright test of F1/F2 against two real `tandemd` is run by the acceptance agent and is not a CI test; there is no automated one in the repo. The CI coverage is the two-agent tests (`crates/tandemd/tests/input.rs`) and the UI ones with the simulated bridge.
