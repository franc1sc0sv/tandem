# T-003 — Identidad y emparejamiento

## Alcance

En `tandem-link` (módulo `identity`): llave Ed25519 por máquina, persistida en archivo con permisos 0600 por ahora (Keychain/DPAPI en una tarea posterior).
Emparejamiento: cada lado muestra un código de 6 dígitos derivado de hash(pubA‖pubB ordenados) (comparación tipo Bluetooth); al confirmar en ambos lados se guarda la pubkey del par en un trust store.
Certificado autofirmado (rcgen) derivado de la llave para usar en QUIC con pinning.

## Criterios de aceptación

- [x] El código de 6 dígitos es el mismo en ambos lados y cambia si cambia cualquiera de las llaves (prueba).
- [x] El trust store persiste y recarga; un par no confiable se rechaza.
- [x] Sin `unwrap()` fuera de pruebas.

## Notas

- Implementado en `crates/tandem-link/src/identity/`: `Identity` (llave Ed25519, archivo de 32 bytes con 0600 y escritura atómica; en Unix se rechaza si otros pueden leerlo), `pairing_code`/`Pairing` (SHA-256 con separador de dominio sobre las llaves ordenadas, 6 dígitos; el par confirma enviando el código que vio), `TrustStore` (TOML versionado, `verify` devuelve `Untrusted`) y `Identity::tls_certificate` (rcgen, autofirmado, nombre fijo `tandem` para el pinning de T-004).
- En Windows el archivo no tiene permisos especiales más allá de las ACL del perfil; la protección real llega con DPAPI/Keychain en la tarea posterior.
