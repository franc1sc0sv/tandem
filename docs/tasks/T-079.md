# T-079 — Shared DDC profile database

## Scope

Replace the profiles written in code (`known_profile` in `crates/tandem-display/src/ddc/switch.rs`) with a profile database in files: `profiles/ddc/<PNP>.toml` (for example `SAM711A.toml`, `SAM7489.toml`) with: PnP id, known EDID names, codes per input (`hdmi`, `display_port`, and optional `hdmi2`/`display_port2`), the reading each input reports (T-050's hint), notes, who verified it and date.
- The repo's profiles are embedded in the binary (`include_str!`); the user can add their own in `<data>/profiles/ddc/`, which take priority.
- Lookup by PnP id first; by EDID name only if the name is not generic.
- Migrate the two verified profiles from `docs/research/` (34" SAM711A: HDMI 0x06 / DP 0x09; 32" SAM7489: HDMI 0x05 / DP 0x0F).
- `tandem-ddc profile <monitor>` shows the profile that would be applied and where it comes from; `tandem-ddc profile export <monitor>` prints the TOML to share it.

## Acceptance criteria

- [x] The two verified profiles live in `profiles/ddc/` and the `known_profile` tests keep passing with the new database.
- [x] A user profile with the same PnP id wins over the repo's (test).
- [x] An invalid profile file gives a clear error with the file name, without breaking the lookup of the others.
- [x] docs/dev/ddc-profiles.md: format and how to contribute a profile.

## Notes

- `crates/tandem-display/src/ddc/profiles.rs`: `DdcProfile` (parse, validation, `to_toml`), `ProfileDb` (embedded repo + `<data>/profiles/ddc/`, lookup by PnP id and by non-generic name, `by_manufacturer` for T-077). `known_profile` remains as a wrapper over the repo's database.
- `tandem-ddc switch` uses the full database (repo + user) and says where the profile comes from; invalid files are reported on stderr.
- The daemon still uses the codes from the monitor's configuration; using the database there is part of T-080.
