# T-127 — Component style parity

## Context

T-112 left the visual system in `apps/tandem-ui/src/ui` (Button, Segmented, Switch, Chip, Card, Kbd, Bar, Ring, Sparkline) copied from the v0.3 mockups, and a gallery (`gallery.html`, only in `pnpm build:demo`) with each component. The pixel comparison of `pnpm shots` measures whole screens; a component with a different border or curve can pass if it takes up few pixels.

## Scope

1. In the harness (`scripts/`), open the gallery and the mockups with `@tandem/mockup-render/harness` and compare the computed styles (height, padding, font, radius, border, background, shadow, `transition` and `animation`: duration and curve) of each component with the same element in the mockup: 38 px button of `V3-Arrangement`, `sm`/`pri`/`ghost ic` of `V3-Monitors`, `danger` of `F-Settings`, segmented controls of `V3-Arrangement` and `V3-Monitors`, switch of `F-Settings`, chip and card of `V3-Desk`.
2. `pnpm shots --check` fails if a property differs; the report says which one and where.

## Acceptance criteria

- [x] Tests of the style comparator (unit, with sample styles).
- [x] All the pairs in the list match; the `ui (screenshots)` job checks it.

## Notes

- Pairs, property groups and comparator: `apps/tandem-ui/scripts/style-parity-spec.ts` (tests in `style-parity-spec.test.ts`); the browser part, `scripts/style-parity.ts`, is called by `pnpm shots` (`--only estilos` runs only this one). In addition to what was asked, the primary's glow (`::after`), the segmented controls' indicator and options, the switches' knob and the link card (`.mcard`) are compared.
- The gallery now goes into the demo build (`vite.config.ts`); its screenshot is left in `docs/screenshots/v03/galeria.png`.
- Normalization: times to ms, named curves to `cubic-bezier`, numbers rounded to 0.01, only the first family of the font; transitions are compared per property (`all 0s` does not count); of the animations, duration, curve, repetitions and fill (not the name, which Svelte prefixes, nor the delay, which the cards stagger). The color of a border that is not drawn is not compared.
- The width of the segmented indicator depends on the width of the group (different in the gallery): `box-sizing` is compared, which with the same formula gives the same width.
- Fixes to the components (the mockup rules): the button no longer animates `opacity` (only `F-Asis3` and `F-Asis5` have it, the rest do not); the segmented indicator uses a content box (measures 2 px more than an option, as in the mockups) and only the `lg` animates `border-color`; the segmented options without `border-radius`; the chip without a transition; the switch with the button's default padding (does not change what is seen).
