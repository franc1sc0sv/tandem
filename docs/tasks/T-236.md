# T-236 — Consistent snapshot in `Agent::desk_sync`

## Context

Found while fixing T-235. `Agent::desk_sync()` read the stamp (under the `sync` lock) and the desk (the `watch` value) separately, and writers updated them separately. A concurrent reader could see a new stamp with the old desk, or the reverse, so remote sync or the UI could act on an inconsistent snapshot.

## Expected fix

Writers (`commit_local`, `receive_desk`, `adopt_side`) update stamp and desk inside the same `sync` lock; `desk_sync` reads both while holding it.

## Criteria

- [x] A stress test (concurrent commits and readers) fails before the fix and passes after: the stamp always matches the desk content.
- [x] `desk_sync` returns stamp and desk from one snapshot.
- [x] Quality gate passes.
