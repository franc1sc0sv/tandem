# T-146 — Mockup regions that nobody measures or explains

## Context

Finding of the acceptance agent (part A), review of masks. The `avisos` screenshot crops only the stack of notices (390 × 681 px from the first notice: 24 % of `F-Notices`). The rest of the mockup is not compared and the README does not say so: the "Notices" header with its text and the "Add notice" button (demo controls) and the whole right column **"System notifications"** ("Only for what happens while you are not looking at Tandem: jobs that finish or fail, resources at the limit and machines that join or leave"), with three system notifications, one of them "MacBook Air joined 'My desk'" (third machine, D1). The app has no system notifications (no `notification` code in `apps/tandem-ui`), and DECISIONS D14 says "no audio nor notifications for now". It is an uncompared zone without the reason written down.

In addition, `mockups/README.md` describes masks that `shots-spec.ts` no longer has: in Settings → Shortcuts it says the first row's combination and the "Reset · Save" strip are covered (the `settings-shortcuts` screenshot covers nothing and measures 100 %, with six shortcuts in the app).

## Scope

1. Document in the README, under "What the mockups say and DECISIONS corrects", that the "System notifications" column is not implemented (D14) and why the Notices screenshot crops the stack; or implement the notifications and measure them, if the user decides so (then it is a new decision in DECISIONS, not part of this task).
2. Leave the Settings → Shortcuts README the same as `shots-spec.ts` (without masks that do not exist).
3. Check that no other region of the mockup is left outside every comparison without being documented (`F-ClaudeMCP` is Claude's view: it is tested in part B).

## Acceptance criteria

- [x] Every region of a mockup that is not compared, or is covered, is in the README with its reason.
- [x] The README does not mention nonexistent masks.
