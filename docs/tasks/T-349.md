# T-349 — Know the monitor's real link state and act on it

## Context

On 2026-11-20 the Mac's HDMI cable to the 34" was unplugged and nothing in Tandem said so: the Mac simply had no monitor. The user wants one reliable system that tells, at every moment, for each shared monitor:

- which machine it is showing,
- whether each machine's cable is connected,
- whether the monitor is on, in standby or off,

and that Tandem (UI, scenes, input engine and cursor) acts on it.

Most raw signals exist already, but are not combined into one state:

- the owner's live state (`MonitorReport`: input, `power_on`, `signal`);
- each machine's EDID listing (T-340);
- `[[cables]]`;
- `shows` (`crates/tandemd/src/monitors.rs`).

Changes of cable or power are only noticed by the 5 s scan, and there is no hot-plug trigger.

## Scope

1. **Cable state per machine and monitor:** `connected` (the system lists the monitor's EDID), `disconnected` (the machine is reachable and does not list it) or `unknown` (machine unreachable). Each agent fills its own end and sends it in its report. It is kept separate from the DDC channel: a connected cable without a channel is still `connected`.

   `disconnected` only comes from a positive "not listed" report by a reachable machine that has just rescanned. Only the Mac side has been shown to keep listing the monitor while it shows the other input; Windows has not been checked yet. Until hardware confirms both sides, a machine that stops listing a monitor which is showing the other machine reports `unknown`, not `disconnected`, so item 6 never refuses a switch because of it.
2. **Hot-plug:** a display change on the system triggers a rescan within 1 s instead of waiting for the next scan. On macOS that is `CGDisplayRegisterReconfigurationCallback`; on Windows, `WM_DISPLAYCHANGE` or `RegisterDeviceNotification` for monitors. Both go behind a trait with a test double.
3. **Power state:**
   - `on` (live state `power_on` and signal);
   - `standby` (`power_on` false, or no signal on the active input);
   - `off` (at least one machine has a probed channel to the monitor, and that channel stops replying past a timeout, while a connected cable still lists the EDID);
   - `unknown`.

   Debounced, so a single failed read is not "off". A monitor whose ends are all `NoChannel` (DDC/CI off in the OSD, an adapter without DDC) stays `unknown`, never `off`.
4. **One derived state per monitor** in `tandem-core`, pure and tested with `proptest`: `ShowsMachine(m)`, `Standby`, `Off`, `ActiveInputUnplugged(m)` (the input shown leads to a machine whose cable is disconnected), `Unknown`, plus the cable state of each end. It is computed from cables, the owner's (or the direct T-346) reading and each end's cable state.
5. **UI:** Desk, Monitors and the tray/menu bar show this state with plain words and the machine's colour, for example "Showing PC", "Mac cable unplugged", "Monitor in standby" or "Monitor off". The live desktops draw a monitor that is off or in standby as dimmed, not as a screen of either machine.
6. **Acting on it:**
   - **Geometry and cursor.** A screen whose monitor is not showing this machine (off, standby, unplugged, or showing the other machine) is out of the input engine's geometry. The cursor never crosses into it, and a cursor already inside is moved back to the nearest live screen. This extends DESIGN §7 and T-341: the Mac turns off its display of a monitor that is off or showing the PC, with the same rules and limits.
   - **Scenes and selector.** Switching a monitor to an input whose machine has its cable `disconnected` is refused before any DDC write, with a clear message, because it would leave a black screen. A scene with such a step fails its preflight; nothing is rolled back because nothing was done.
   - **Notices.** A notice on transitions such as "Mac cable unplugged", "Mac cable connected", "34\" turned off" and "34\" back on". The same state is never repeated.
7. **Contract and docs:** protocol bump (next free version), DESIGN §7 and §10, DECISIONS line, CLI/MCP read of the state (`tandem monitors`).

## Acceptance criteria

- [x] Pure state derivation in `tandem-core` with unit and `proptest` tests: every combination of cable states, power and input maps to exactly one state, and an unknown input never yields `ShowsMachine`.
- [x] Hot-plug trait with test doubles on both platforms. A simulated display change triggers the local rescan in under 1 s, and the new cable state reaches the other agent's UI state in under 1.5 s (`tandem-sim`, simulated clock where available).
- [x] Debounce: a single failed DDC read does not change the state to `off`; it takes the timeout (simulated clock).
- [x] A monitor with only `NoChannel` ends is `unknown`, never `off`.
- [x] Cable safety: a simulated machine that stops listing the monitor while it shows the other machine gives `unknown`, and switching to that machine's input is **not** refused.
- [x] Geometry test: a monitor going to standby or off removes its screen from the geometry, and a cursor inside is moved to a live screen.
- [x] Scene and selector test: switching to an input whose cable is disconnected is refused without any DDC write.
- [x] UI (vitest): each state renders its text and the dimmed live desktop on Desk and Monitors; the tray/menu bar shows the state text; notices are not repeated.
- [x] `tandem monitors` (CLI and MCP) returns the derived state and each end's cable state (test on the API layer).
- [x] DESIGN, DECISIONS, protocol version and STATUS updated.
- [x] Quality gate and CI green.

- [ ] Each machine keeps listing the monitor (cable `connected`) while the monitor shows the other machine, checked in both directions (the PC while it shows the Mac, the Mac while it shows the PC). If Windows stops listing it, record it in DECISIONS and keep the `unknown` rule.
- [ ] Unplugging the Mac's HDMI cable shows "Mac cable unplugged" on both machines within 2 s, and plugging it back clears it.
- [ ] Turning the 34" off with its button shows "Monitor off" on both machines, the cursor stays on the live screens, and turning it on restores the previous state.
- [ ] Monitor in standby (PC asleep, DP without signal): "Monitor in standby", and the Mac's cursor never enters it.
- [ ] With the Mac's cable unplugged, "Only Mac" is refused with the message, and the monitor stays on the PC.
