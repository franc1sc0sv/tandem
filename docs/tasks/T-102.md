# T-102 — Per-path metrics

## Context

DESIGN §6; mockup `V3-Network` (path map, latency and bandwidth rings, 60 s graph with the peak marked, per-path cards with state Primary / Backup / No cable).

## Scope

1. Per path: state (`primary`, `backup`, `no cable`, `down`), RTT and input latency p50/p99, last measured bandwidth, 60 s history (1 sample/s).
2. `UiCommand::MeasureLink { path }`: 3 s bandwidth test over a data stream (T-101), on any path.
3. Path-change events with duration ("switched to Wi-Fi in 0.6 s"), stored (last 50).
4. IPC `UiEvent::Network` at 1 Hz only with the screen visible (explicit subscription).
5. UI demo mode with equivalent simulated data (for T-118).

## Acceptance criteria

- [x] Tests with `tandem-sim`: cutting a path generates the event with its duration and changes the states; the bandwidth measurement returns a value with the simulated link limited (`tandem-sim/tests/network.rs`: the test that cuts a path and checks the event, its duration and the state changes, and the test where the measurement gives what the simulated Wi-Fi gives and sets the cap).
- [x] IPC test: without a subscription there are no events (`tandemd/src/ipc/mod.rs::network_flows_only_while_the_connection_watches`).
- [x] Quality gate and CI green (gate in WSL; CI in the PR).

## Notes

Done:

- `tandem-proto` (v28; T-122, T-100 and T-103 took v22, v23 and v25, and T-093 v26): `net` module with `NetworkStatus` (the three paths with `PathState` primary/backup/no cable/down, RTT, input p50/p99, the path's target, last `Bandwidth`, 60 one-second `LatencySample`s), `PathSwitch` (last 50, with `took_ms`) and `MeasureReport`. `UiCommand::WatchNetwork { on }`, `UiCommand::MeasureLink { path }`, `AgentToUi::Network`, `Reply::Bandwidth` and `Channel::Measure`.
- `tandem-link`:
  - `LinkEvent::took`: from the last response of the path that dropped until the switch (upper bound of the outage: it is not known when it really dropped). `None` on a rise with no outage. `Snapshot::handles`: the connection of each healthy path, to measure one that is not the active one.
  - `qos`: `percentiles` (p50 and p99) in the guardian's window, `Qos::input_latency`, `measured` and `input_target`.
  - `metrics`: `NetMetrics` (pure, with a property test), shared `Metrics` (one measurement at a time; what is measured also goes to the path's `Qos`, so T-101's cap comes from the measurement), `follow` (feeds the metrics from a running manager, 1 sample/s) and `probe` (the test: sends for 3 s without a cap over a data-priority stream, but is cut if the path's `Qos` pauses data; whoever receives measures; test in `tandem-sim/tests/network.rs` where the measurement is cut if the input exceeds its target). `ControlStream::measure`/`answer_measure` over QUIC (loopback test in `tests/transport.rs`).
- `tandemd`: the metrics live in the agent (`Agent::network_status`, `Agent::measure_link`) and survive the network rebuilding the manager; `network.rs` runs `follow` with each manager and leaves the connection of each healthy path. The IPC sends `AgentToUi::Network` at 1 Hz only to the subscribed connection and answers `MeasureLink` when finished without holding up the other notices. The other agent answers the test in `peer::serve_stream`. Two-agent test over real QUIC with ephemeral ports (`agent/net.rs`).
- `tandem-sim`: the `Desk` feeds the metrics like `tandemd`; `SimWifi::data_pipe` gives the receiving end.
- UI: types `NetworkView`/`PathView`/`PathSwitchView`, `network` theme (requested by the Network screen), demo mode with `V3-Network`'s numbers (primary USB-C 0.3 ms, p50 0.4 / p99 1.9 ms, 9.4 Gbps; Ethernet with no cable; backup Wi-Fi 3.8 ms, 410 Mbps; 60 s with the outage peak and "switched to Wi-Fi in 0.6 s"), which advances by itself only with the screen visible, and `measureLink(path)` per path. The Desk keeps `link` (summary).
