# T-154 — "No open tunnels" until something changes

Found by the acceptance agent (part B), flow F5 (the UI shows everything live).

## What fails

The session pushes the tunnels (`agent-tunnels`) only on connecting to the agent and when something changes (`Sink::tunnels`). The window does not ask for them at startup: `LiveSource.start()` only subscribes. If the window (main or tray) loads after the session connected — the normal case of an app that was already running, or of a reload — it receives nothing until the next change. Measured with an MCP client that opened a tunnel with 3 processes running:

- Freshly loaded Tunnels: "No open tunnels" (on both machines), until another `exec` generates an event.
- The tray's mini scene says "0 tunnels".
- The palette does not offer "Go to tunnel…".

## Expected fix

- An app command (`agent_tunnels`, or including the tunnels in `agent_snapshot`) that the window calls on startup, or the session forwards the last state to each new window.
- Test: open a tunnel, create a new `LiveSource` and see the tunnels without another event.

## Acceptance criteria

- [x] Tunnels, tray and palette show the open tunnels after reloading.
- [x] A session or bridge test that covers it.
- [x] Quality gate and CI green.
