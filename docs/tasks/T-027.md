# T-027 — Windows: SYSTEM service and secure desktop

## Scope

`--service` mode of tandemd: SYSTEM service that launches the helper in the active session with a winlogon token and TokenUIAccess, desktop tracking (OpenInputDesktop/SetThreadDesktop), Ctrl+Alt+Del with SendSAS. Installation in Program Files.

## Acceptance criteria

- [x] The mouse works in a UAC dialog (manual test). Code complete (the helper injects on the input desktop and the agent routes through it); the manual check is in "Pending hardware verification".
- [x] Document Authenticode signing requirements (the user decides the certificate): `docs/dev/secure-desktop.md`, "Authenticode signing".

## Notes

- Design and manual test: `docs/dev/secure-desktop.md`. Code: `crates/tandemd/src/secure/`.
- Three processes. The service (`tandemd --service`, `TandemSecureDesktop`, LocalSystem, auto start) only supervises: it launches the helper in the console session (`WTSGetActiveConsoleSessionId`) with a duplicate of that session's `winlogon.exe` token with `TokenUIAccess = 1` on `winsta0\default`, follows `SERVICE_CONTROL_SESSIONCHANGE` plus a 1 s poll, restarts a dead helper with a 1 s → 30 s backoff, and calls `SendSAS(FALSE)`. The helper (`tandemd --input-helper`) follows the input desktop (check every 100 ms and after any failed `SendInput`, one retry after a switch) and serves `\\.\pipe\tandem-secure-input-<session>`. The session agent's Windows injector is a `RoutedSink`: `INPUT` records go to the helper while it is reachable, otherwise to its own `SendInput`, reconnecting every 2 s.
- Portable logic tested on Linux: `Supervisor` over `SessionHost` (session switching, helper lifecycle and backoff, stop, SAS; property test: never more than one helper and always in the console session), `DesktopTracker` over `Desktops`, `Helper` (hello/version, desktop retry, SAS), the wire protocol (property test: records survive), `RoutedSink` and `SasChord` (fallback, reconnection, status, Ctrl+Alt+Delete → SAS), and the install plan (`install_plan`/`uninstall_plan`, `SoftwareSASGeneration` handling). Win32 is only in `secure::windows` (`cfg(windows)`), with Windows CI tests for the SCM query and a squatted pipe being refused.
- Security: the pipe's DACL is SYSTEM + Administrators with a high-integrity label (an unelevated process cannot open it, so the agent must run from T-104's elevated task), `FILE_FLAG_FIRST_PIPE_INSTANCE`, no remote clients; the agent opens it at identification level and only talks to a LocalSystem server; a hello with the protocol version comes first. The service runs its own copy in `%ProgramFiles%\Tandem Service`, copied only from an administrators-only source and checked after the copy; logs stay in that folder.
- Install: `tandemd --install-service` / `--uninstall-service`, and `--install --with-service` (what the app's setup runs with one UAC prompt; the "Administrator service" row is ok only with both the task and the service). An elevated `--install` refreshes an installed service and an elevated `--uninstall` removes it, so the NSIS hooks needed no new commands. Recovery actions: restart after 5 s, 10 s, 60 s, reset after a day, non-crash failures included.
- `SendSAS` policy: install turns on the services bit of `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System\SoftwareSASGeneration` (0/missing → 1, 2 → 3) and remembers the old value in `HKLM\SOFTWARE\Tandem\SecureDesktop`; uninstall restores it.
- The "Protected screens" module is active only while the agent reaches the helper; otherwise it says why (not installed, not running, agent not elevated, service from another version).
- Limits: the agent still runs in the user's session, so the secure desktop works inside that session (UAC, Ctrl+Alt+Del, lock screen). The sign-in screen after a boot and another account's session have no agent to receive input. Capture on the secure desktop (the PC's input driving the Mac while UAC is up) is not covered.

## Pending hardware verification

Steps in `docs/dev/secure-desktop.md`, "Manual test".

- [ ] Install with UAC from the app's setup (and `tandemd --install-service` from an elevated terminal): service `RUNNING`, three restart actions, copy in `C:\Program Files\Tandem Service`, "Protected screens" active.
- [ ] The Mac's mouse and keyboard work on a UAC prompt (No and Yes) and in an elevated window.
- [ ] Cmd+Option+Forward Delete from the Mac (the PC's Ctrl+Alt+Del with the default Cmd↔Ctrl swap) opens the Ctrl+Alt+Del screen and Cancel works with the Mac's mouse.
- [ ] Lock screen (Win+L): wake it and type the PIN or password from the Mac.
- [ ] Fast user switching: the helper moves to the other session and back; the Mac's input works again on returning.
- [ ] Killing the service: the SCM restarts it and it relaunches the helper.
- [ ] Uninstall with UAC (`tandemd --uninstall-service` or uninstalling Tandem as administrator): service gone, folder gone, `SoftwareSASGeneration` restored.
