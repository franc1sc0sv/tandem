# T-088 — Ignored monitors and automatic input-change detection

## Context

User's request (2026-10-17), after the first test with the two machines, in which four monitors appeared when there were two:

- Do not depend on ghost monitors: Tandem must only consider the monitors that are really connected.
- Of those detected, the user chooses which ones to use with Tandem; the rest stay **untouched by the program**. Applies to each of the two machines.
- Each monitor's state must update **by itself** when its input changes, without asking "what does it show now?".

T-087 covers the empty desk, the wizard's picker and the "connected only" rule. This task adds the concept of an ignored monitor and continuous detection. **Start from T-087 already integrated in `develop`**; if the code does not match what is described here, stop and report it.

Hardware constraint (see `docs/dev/HANDOFF.md`): the DDC reading of `0x60` is **not reliable** (the 34" always reads `0x09`; the 32" does not update after a change from the menu). Detection cannot depend on DDC.

## Scope

1. **States of a detected monitor:** `managed`, `ignored` or `new`.
   - `ignored` is saved by stable identity (EDID serial number if it exists; otherwise model and size), per machine. No plan, mode change, calibration or DDC command touches it, and it does not appear in the wiring.
   - `new` (detected with no prior decision) shows a discreet notice with "Use" / "Ignore". **It is never added by itself.**
   - The identity link between the two machines only exists for managed ones.
2. **UI:** ignored ones are shown **dimmed** with the "Use" action; they are not hidden. Going from managed to ignored reuses T-087's deletion (deletes everything about it, with confirmation). The wizard's picker (step 4) and "Add monitor" offer "Use" / "Ignore" per monitor.
3. **Change detection by presence, without asking:**
   - Each agent watches the system's screen connection events behind a trait (`DisplayWatcher`): Windows `WM_DISPLAYCHANGE` / `WM_DEVICECHANGE`; macOS `CGDisplayRegisterReconfigurationCallback`. With no events available, light polling every 2–3 s.
   - When the input changes, a monitor normally disappears from one machine and appears on the other. The two agents exchange the presence events over the encrypted link.
   - With T-087's identity links, the state is deduced: visible only on the Mac → shows the Mac; visible only on the PC → shows the PC.
   - 1–2 s debounce for the flicker of the input change.
   - Covers changes made with the monitor's physical button and monitors without DDC.
   - The DDC reading remains, at most, as a secondary hint; never the source of truth.
4. **Ambiguity:** visible on both machines at once, or on neither, leaves the monitor as "unknown" (`Doubt::Unknown`, T-085); a state is never assumed.
5. **Safety (T-087's rule F intact):** detecting a change **only updates the displayed state**. It does not deactivate outputs, nor send `SwitchInput` or `Detach` in reaction. An ignored monitor is never touched, not even in rollback.
6. **Persistence and protocol:** list of ignored monitors in each machine's config; presence events in the link protocol (bump the version if needed).
7. Document in `docs/DESIGN.md` (§5 and §8) the monitor state model and presence detection.

## Acceptance criteria

- [ ] With two detected monitors and one marked "ignored", no plan, mode change, calibration or DDC command touches it (agent test and property).
- [ ] A newly detected monitor shows the notice and is not added until the user chooses "Use" (agent and UI test).
- [ ] With `tandem-sim` (two agents on loopback and a simulated `DisplayWatcher`), moving a monitor from one machine to the other updates its state on both without asking and without any `SwitchInput` (test).
- [ ] A burst of presence events within the debounce window produces a single state update (test).
- [ ] Visible on both or on neither → "unknown" state (test).
- [ ] Property test: no sequence of presence events leaves an ignored monitor touched, nor an invented state, nor a monitor without an active output.
- [ ] Frontend tests: ignored monitor dimmed with "Use", new-monitor notice, and state that changes by itself; screenshots in the PR (demo mode).
- [ ] `docs/DESIGN.md` updated.
