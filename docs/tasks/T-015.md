# T-015 — Unified display topology (Windows + macOS)

## Scope

Today there are two parallel abstractions in `tandem-display`. Windows (T-011) has `topology::{DisplayTopology, Display, TargetId, TopologyError}`, with `displays()` and `set_active()`. macOS (T-012) has `quartz::{QuartzApi, MacTopology, Display, DisplayId, TopologyError}`, with `online()`, `set_enabled()` and `set_mirror()`. DESIGN §4.2 asks for **one** `DisplayTopology` trait with per-platform backends.

- A single portable `DisplayTopology` trait with:
  - an opaque identifier type per backend;
  - a common `Display` with name, EDID model, whether it is the built-in display, whether it is active and its bounds;
  - `displays()` and `set_active()`;
  - `set_mirror()` as an optional capability: it returns `Unsupported` on Windows.
- `MacTopology` and `WindowsTopology` implement it. The test doubles (`FakeTopology`, `FakeQuartz`) are unified or both implement the same trait.
- A single `TopologyError` and a single function to find a config monitor (`MonitorConfig`) among the displays.
- T-014's display step executor (`Attach`, `Detach`, `SetBuiltin`) uses only the portable trait, with no platform `cfg` in the logic.
- T-012's invariants (never leave the Mac without a display, always restorable) are kept as property tests over the unified trait.

## Acceptance criteria

- [x] A single `DisplayTopology` trait in `tandem-display`, implemented by the Windows and macOS backends (compiles on CI x3).
- [x] The display step executor has no platform-specific code; its tests run on Linux with the double.
- [x] The existing tests from T-011 and T-012 still pass, adapted to the unified trait.
- [x] The `lib.rs` documentation describes the final structure.

## Notes

- `tandem_display::topology::DisplayTopology` is the only trait: `type Id` (`TargetId` on Windows, `DisplayId` on macOS), `displays()`, `set_active()` and `set_mirror()` with a default `Unsupported` implementation (Windows does not redefine it). Common `Display<Id>`: name, interface path (empty on macOS), EDID, `builtin`, `main`, `active`, `mirror_of` and `bounds`. A single `TopologyError` (ids go as text).
- Search: `find_monitor(displays, &MonitorConfig)` is the only one for the configuration (full EDID model or system name, case-insensitive, never the built-in). On Windows it used to be a partial search: `G5` would have found `LC34G55T`. `find(displays, text)` remains for diagnostics.
- The operations of a mode change are written once over the trait: `attach`, `detach`, `set_builtin` (with the fallback to mirroring if the private API is missing) and the `Detached` guard. On the PC, `set_builtin` answers `NoBuiltin`.
- Backends: `WindowsTopology` (also fills `bounds` and `main` from the source mode and `builtin` from `outputTechnology`) and `MacTopology<A: QuartzApi>`, which keeps what is specific to macOS (remembering the deactivated ones, undoing mirrors before deactivating, `restore_all`, `RestoreGuard`). `QuartzApi` speaks `CgDisplay` (what CoreGraphics gives), which is converted to the common `Display` (the manufacturer comes from the EDID: `0x4C2D` = `SAM`).
- Doubles: `FakeTopology` implements the trait directly; `FakeQuartz` does it through `MacTopology`. The invariants (never without a display, always restorable) are property tests over the trait for both doubles (`topology/props.rs`), and T-012's one remains in `quartz/tests.rs`.
- Step executor: `TopologyDesktop<T: DisplayTopology>` without `cfg`; the choice of the real backend is only in `desktop::native(machine)`. With this the Mac already has a desktop in `tandemd` (`Attach`/`Detach`/`SetBuiltin` over Quartz) when the agent runs on macOS.
