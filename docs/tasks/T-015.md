# T-015 — Topología de pantallas unificada (Windows + macOS)

## Alcance

Hoy hay dos abstracciones paralelas en `tandem-display`. Windows (T-011) tiene `topology::{DisplayTopology, Display, TargetId, TopologyError}`, con `displays()` y `set_active()`. macOS (T-012) tiene `quartz::{QuartzApi, MacTopology, Display, DisplayId, TopologyError}`, con `online()`, `set_enabled()` y `set_mirror()`. DESIGN §4.2 pide **un** trait `DisplayTopology` con backends por plataforma.

- Un solo trait portable `DisplayTopology` con:
  - un tipo de identificador opaco por backend;
  - un `Display` común con nombre, modelo EDID, si es la pantalla integrada, si está activa y sus límites;
  - `displays()` y `set_active()`;
  - `set_mirror()` como capacidad opcional: devuelve `Unsupported` en Windows.
- `MacTopology` y `WindowsTopology` lo implementan. Los dobles de prueba (`FakeTopology`, `FakeQuartz`) se unifican o los dos implementan el mismo trait.
- Un solo `TopologyError` y una sola función para encontrar un monitor de la config (`MonitorConfig`) entre las pantallas.
- El ejecutor de pasos de pantalla de T-014 (`Attach`, `Detach`, `SetBuiltin`) usa solo el trait portable, sin `cfg` de plataforma en la lógica.
- Las invariantes de T-012 (nunca dejar a la Mac sin pantalla, siempre restaurable) se mantienen como pruebas de propiedades sobre el trait unificado.

## Criterios de aceptación

- [ ] Un único trait `DisplayTopology` en `tandem-display`, implementado por los backends de Windows y macOS (compila en CI x3).
- [ ] El ejecutor de pasos de pantalla no tiene código específico de plataforma; sus pruebas corren en Linux con el doble.
- [ ] Las pruebas existentes de T-011 y T-012 siguen pasando, adaptadas al trait unificado.
- [ ] La documentación de `lib.rs` describe la estructura final.
