# T-004 — QUIC transport with mutual authentication

## Scope

`tandem-link::transport`: quinn server+client endpoint with mutual TLS and verification by pinning the peer's pubkey (custom rustls verifiers).
API: open a connection to an address, bidirectional control stream (tandem-proto messages), datagram channel.

## Acceptance criteria

- [x] Loopback test: two endpoints with paired keys connect and exchange messages and datagrams.
- [x] An unpaired peer is rejected in the handshake (test).
- [x] Round-trip latency measured in the test and printed (informational).

## Notes

- Implemented in `crates/tandem-link/src/transport/`: `Endpoint` (quinn, server and client on the same socket), `Connection` (`peer()` with the already verified key, `open_control`/`accept_control`, `send_datagram`/`read_datagram`, `rtt()`), `ControlStream` (`tandem-proto` frames over a bidirectional stream) and the verifiers `PinnedServerVerifier`/`PinnedClientVerifier`.
- Pinning: the Ed25519 key is extracted from the certificate's SPKI and `PeerTrust` is queried (implemented by `TrustStore` and by `RwLock<TrustStore>`, so that a peer paired while the endpoint is already open counts for new connections). Name, validity and chain are ignored; possession of the private key is proven by the handshake signature (`verify_tls13_signature`). TLS 1.3 only and only the `ED25519` scheme. ALPN `tandem/1`.
- The control stream is opened by the side that connects and starts with a `Hello` in each direction; the accepting side sends its `Hello` even if the peer's is of another version, so that both see `IncompatibleVersion` and not a silent cut.
- With TLS 1.3 the client can consider the handshake finished before the server rejects its certificate: in that case `connect` returns the connection and the rejection arrives as an error on the first operation (the test covers it).
- Dependencies: `quinn` without `platform-verifier` and `rustls` without default features, both with `ring` (the same backend rcgen already used), so as not to pull in `aws-lc-rs` (cmake/nasm on Windows). `bytes` was added to the workspace.
- RTT measured on WSL2 (200 control pings, test build): mean ~0.6 ms, p50 ~0.55 ms, p99 ~1.1 ms. It is printed with `cargo test -p tandem-link --test transport -- --nocapture`.
- Out of scope, for a later task: T-003's notes left "the serialization of the pairing messages and their transport" for T-004, but this task's scope does not include it and it requires a design decision (pairing happens before there is a trusted key, so it needs a connection mode without pinning). It was not improvised.
