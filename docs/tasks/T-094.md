# T-094 — USB-C cable link detected automatically

## Context

The user has a USB-C cable from a 27" Samsung monitor (10 Gbps, with video) and wants to use it as a direct link between the Mac and the PC, without configuring anything. Design in `docs/DESIGN.md` §6.1. Today the `usb4` link only exists if its address is written by hand in `peers`.

## Scope

1. **`Interfaces` trait** (portable) that lists the network interfaces and reports additions and removals: name, type (`Usb4`, `Ethernet`, `Wifi`, `Other`), IPv4/IPv6 addresses, MAC and speed if the system gives it. Test double for Linux.
   - macOS: `getifaddrs` + `SCNetworkInterface` (Thunderbolt Bridge / `bridge0` with Thunderbolt `en*` members). Changes with `SCDynamicStore`.
   - Windows: `GetAdaptersAddresses` + `NotifyIpInterfaceChange`; `Usb4` type by adapter description (USB4 / Thunderbolt Networking) or by `IfType`.
2. **Addresses:** use the interface's *link-local* IPv6 (with its `scope_id`); if the system does not give it, each agent assigns itself `10.77.1.1` (Mac) or `10.77.1.2` (PC) in `10.77.1.0/30`. If assigning an IP requires permissions the agent does not have, the UI says so with the exact command and continues with link-local.
3. **Per-interface discovery:** mDNS on the cable's interface. Each end classifies the connection by its outgoing interface (not by the configuration) and announces it to the other in a new `ControlMsg::LinkClass { kind }` message when opening the connection (bumps the protocol version); **the link's label is the worse of the two** (`Wifi` < `Ethernet` < `Usb4`), so that a path with a Wi-Fi hop is not treated as a cable: it carries data only with Wi-Fi's cap (DECISIONS A2) and does not admit `MeasureLink`. Its own class and the other's are stored separately and the label is recalculated each time, so it recovers if the other announces a cable again.
4. **Measurement:** continuous RTT (already exists in the link health) and an on-demand bandwidth test (`UiCommand::MeasureLink`, 3 s over a QUIC stream), **only over cable links**: over Wi-Fi it is rejected with its reason. Result in the UI.
5. **Link switch:** when the interface goes down it is marked down immediately (without waiting for the health check); when it comes up, it enters with T-065's hysteresis.
6. **Diagnostics:** `tandemd links` (CLI) lists interfaces, detected type, address used and the state of each link, for spike S5.

## Acceptance criteria

- [x] With the `Interfaces` double, the appearance of a `Usb4` interface creates the link and it becomes the preferred one; its removal moves input to the next in < 1 s (test with `tandem-sim`).
- [x] The link's label comes from the interface (test with a configuration address that contradicts the type).
- [x] Different classifications at the two ends give the worse (test: PC `Ethernet`, Mac `Wifi` → `Wifi`, with Wi-Fi's data cap) and the label recovers when the other announces `Ethernet` again (test).
- [x] Per-interface discovery (`InterfaceDiscovery` trait with a double): with a cable with link-local the agent learns the other's address through that interface and the cable enters as a link (test).
- [x] Assignment of the fallback IP (`AddrAssigner` trait with a double; `netsh` on Windows, `ifconfig` on macOS); without permissions, the notice with the exact command reaches the Network screen (tests of both paths).
- [x] `MeasureLink` over Wi-Fi is rejected (test).
- [x] The construction of link-local addresses with `scope_id` has unit tests; the real connection over `fe80::` stays in hardware (the Linux and Windows loopback has no link-local address).
- [x] Quality gate and CI green on the three platforms.

## Notes

- 2026-11-16 (spike S5): with the 10 Gbps cable the two ends negotiate over PD (the PC, ITE controller, announces USB4 in its UFP VDO) but the USB4 link does not train (the Mac only activates CC); with a USB 2.0 cable it is impossible. Without updating the BIOS. Pending: try a 40 Gbps TB4/USB4 cable. See `docs/research/usb4-link.md`. The task is implemented and tested with simulators; the physical part stays in the hardware list.
- 2026-11-17 (implementation): `tandem-link::iface` (`Interfaces` trait, `FakeInterfaces`, `SystemInterfaces` through `if-addrs` reading every 0.5 s, classification by name, link-local addresses with `scope_id`, `10.77.1.0/30` fallback, worse-of-the-two label) and `LinkManager::control()` (add and remove links on the fly; removing the active one switches immediately; when one returns after being removed healthy it enters with the hysteresis). `ControlMsg::LinkClass` (protocol v34): each end sends it when opening the connection and the other applies the worse one to the path's `Qos`. `MeasureLink` is rejected over Wi-Fi (also if the effective label is Wi-Fi). `tandemd links` lists interfaces, type, addresses and the state of the paths.
- Decisions: the type comes from the name and what is not recognized (`en0` on macOS) counts as Wi-Fi, so that a Wi-Fi never carries data without a cap; the fallback IPs go per side of the desk (A = `.1`, B = `.2`, not by Mac/PC); what is configured by hand in `peers` takes precedence over what is detected of the same type.
- 2026-11-17 (review): per-interface mDNS and the assignment of the fallback IP were implemented behind traits with a double. `ScopedDiscovery` filters what the agent's mDNS announces by the interface's `scope_id` (mdns-sd already listens on all, also on cable ones); link-local ones with an interface are removed from the LAN list so that a cable is not taken for Wi-Fi. `WiredResolver` decides the other's address and assigns the fallback with `SystemAssigner` (`netsh` / `ifconfig`); without permissions a notice with the exact command is left in `NetworkStatus.notices`, which the Network screen shows. Detection latency: polling is every 0.5 s, so the real margin of the removal is 0.5 s (the < 1 s test uses `FakeInterfaces`, with immediate notice, and does not measure it).
- Pending hardware: the native `SCDynamicStore` / `NotifyIpInterfaceChange` notifications (improvement over polling), and MAC, negotiated speed and type through `IfType` / `SCNetworkInterface`.
