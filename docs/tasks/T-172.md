# T-172 — `docs/screenshots/v03` up to date

## Context

Finding of the acceptance agent (part A, round 2). On a clean `develop`, `pnpm shots --check` ends with 0 but leaves 10 PNGs modified (`setup-desk`, `setup-desk-new`, `setup-arrangement-crossed`, `setup-arrangement-waiting`, `setup-arrangement-other-edge`, `setup-machine-amber`, `setup-machine-teal`, `setup-machine-violet`, `setup-permissions-all`, `setup-permissions-one`) and `similarity.json` (the worst tile of several setup screens goes from 0.9993 / 1.0 / 0.9976 to 0.9961). The difference is minor and meets the thresholds, but the committed screenshots are the evidence of the screens and they are no longer those of the `develop` app: a setup change (T-151, T-156) did not regenerate them.

## Scope

1. Regenerate with `pnpm shots` and commit the PNGs and `similarity.json`.
2. Prevent it from happening again: a check (in `pnpm shots --check` or in CI) that fails if, after regenerating, `docs/screenshots/v03` changes.
3. Review why the worst tile dropped to 0.9961 on those screens (a text pixel or a border) and note it if it is a difference of the mockups.

## Acceptance criteria

- [x] `pnpm shots --check` on a clean copy leaves no changes in `git status`.
- [x] The scope 2 check exists and fails with an old screenshot.
- [x] Quality gate and CI green.

## Notes

Evidence: `docs/reports/acceptance-2026-11-18-a2.md`.
Cause: #124 (T-152) added the "leave desk" button (a 10x10 px X in the sidebar footer) without regenerating the screenshots; CI ran `shots --check` but never compared against what was versioned. The "Versioned screenshots up to date" step was added in `ci.yml` (screenshots job, Linux), which fails if `git status` of `docs/screenshots/v03` is not clean.
Visual review: the only difference is that X (expected, not a regression); that is why the worst tile drops to 0.9961 (a tile with 10x10 new px) and it is not a difference of the mockups, which do not have the X.
