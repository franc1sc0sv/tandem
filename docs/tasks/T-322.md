# T-322 — `a_local_setting_moved_to_the_desk_does_not_leave_the_machines_apart` still flakes (a different wait than T-235)

## Context

Failure found by the acceptance agent, part C, round 6 (2026-11-19, `origin/develop` 9fe53be). See `docs/reports/acceptance-2026-11-19-c6.md`. T-235 fixed a different step of the same test (`until_same_desk` already true before the merge); this is the wait before it.

## Failure

G11. `cargo test --workspace` failed on the first run on a clean checkout of `develop`:

```
test a_local_setting_moved_to_the_desk_does_not_leave_the_machines_apart ... FAILED
thread 'a_local_setting_moved_to_the_desk_does_not_leave_the_machines_apart' panicked at crates/tandemd/tests/network.rs:45:23:
the test exceeded the maximum time waiting at crates/tandemd/tests/network.rs:1003:5
test result: FAILED. 16 passed; 1 failed; ... finished in 21.77s
```

Line 1003 is `within(on_a.wait_for(off)).await.unwrap()`: agent A (the one with no legacy `[input] clipboard`) never sees `modules.b.clipboard == false` in its desk within `within`'s 20 s, although agent B (`clipboard = false` in the pre-T-099 `[input]`) has it off. Other tests of the binary finish in 1 to 2 s, so this is a lost update, not a slow one.

Reproduction: the machine was loaded (load average 17 to 23 on 8 CPUs, other acceptance builds running). Running the test alone 15 times with `cargo test -p tandemd --test network a_local_setting_moved` under that load failed 1 of 15, with the same panic. The unloaded rerun of the whole workspace (`--no-fail-fast`) passed: 1623 passed, 0 failed, 11 ignored. CI on `develop` has not shown it (14 of the last 15 runs green, the other one the Playwright download).

## Expected fix

- Find why B's desk, rewritten by the migration (`cfg.local_to_desk` makes `stamp = saved.next(me, ...)` in `Agent::with_local_steps`), does not reach A when the link comes up late or the two stamps are compared before B's change is registered. Suspects: the desk handshake compares `(rev, sum)` before the bumped stamp is in the `SyncClock`; the migrated desk is sent once, on a link that is replaced right after (T-237 adopts the other agent's connection); the update is lost when both dial at the same time and one connection is dropped.
- Force the ordering with a deterministic test that fails before the fix. Fix the cause in the daemon; do not raise the 20 s limit.
