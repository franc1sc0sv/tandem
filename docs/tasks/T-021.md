# T-021 — Display geometry and edge crossing

## Scope

`tandem-input::geometry`: per-machine display model (rectangles, scale), relative layout of the two machines from the `State` (DESIGN §7: only visible displays), crossing detection at the edge of the current display, proportional mapping to the destination edge, corner margin, DPI scaling.

## Acceptance criteria

- [x] Tests: crossing between monitors of different sizes; dead corners; layout recalculated when the state changes (the Mac with no external monitors uses its built-in display).

## Notes

- `tandem-input::geometry::Layout::compute(cfg, state, mac, pc, opts)` is pure: it is called again with every change of state or of reported displays, with nothing to invalidate.
- Native cursor coordinates of each machine; `Screen::scale` is native units per logical point (`dpi/96` on Windows Per-Monitor-V2, `1.0` on macOS, which already works in points). The corner margin is given in points and scaled per display; `to_logical`/`to_native` scale the speed.
- Displays that count: config monitors that the `State` assigns to that machine (a ghost that the system could not remove is excluded, plan C of DESIGN §8), the built-in only if its effective mode is `Extend` (in mirror it adds no space), and nothing from a machine that is not visible.
- Side of each machine: the order of the monitors in `Config`. When the Mac only has its built-in display, it has no place in that order: `LayoutOptions::builtin_side` (by default to the right of the PC).
- Locking the cursor on the current display (shortcut) is not in this task's scope.
