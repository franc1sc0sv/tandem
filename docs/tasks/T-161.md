# T-161 — Remove "Add machine" from the "First time" state (D1, G1, G5)

## Context

Failure found by the acceptance agent, part C (2026-11-18, `origin/develop` 04f2967). See `docs/reports/acceptance-2026-11-18-c.md`.

## Failure

G1 and G5: `apps/tandem-ui/src/lib/states.ts` (line ~114) draws in the "First time" state the title "Single-machine desk", the text "…appears off with 'Add another machine to use this'" and a primary button "Add machine" (`does: "add-machine"`, which opens the pairing step). D1: "There is no third machine nor 'add machine'; the other one can be changed (pair again)"; `mockups/README.md` leaves "Add machine" out. `src/screens/states.test.ts` (lines 82-90) also tests it and `src/lib/states.ts` defines `StateDo = "add-machine"`.

The `V3-States` mockup draws that text; the difference is not in the list of `mockups/README.md` nor in the screenshot harness, so it also has to be declared.

## Expected fix

- Change the button to "Pair the other machine" (link icon, same `pri` style) and the text to "…appears off until the other machine is paired".
- Rename `add-machine` to `pair` in `states.ts`, `States.svelte` and the tests.
- Add the difference to `mockups/README.md` and to `scripts/shots-spec.ts` with its reason (D1), and make `pnpm shots --check` stay ≥ 0.99 / ≥ 0.97.
- Vitest test: no visible text on any screen contains "Add machine" nor "Add another machine".

## Acceptance criteria

- [x] The app does not show "Add machine" nor "Add another machine" in any state.
- [x] The button still opens pairing and has a test.
- [x] `pnpm test`, `pnpm check`, `pnpm build` and CI green.
