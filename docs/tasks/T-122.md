# T-122 — Release y actualización automática

## Contexto

DECISIONS D19; DESIGN §13; mockup `F-Ajustes` (pestaña Actualizaciones).

## Alcance

1. `tauri-plugin-updater` con llave de firma del updater (minisign) guardada como secreto de GitHub (`TAURI_SIGNING_PRIVATE_KEY`); la pública en la config. Documentar en `docs/dev/release.md` cómo generarla (`pnpm tauri signer generate`) — si el secreto no existe, el workflow falla con un mensaje claro.
2. Workflow `release.yml`: con un tag `v*`, construye `.dmg` y NSIS, firma los paquetes del updater, publica el release (borrador → publicado) y el `latest.json`.
3. El agente `tandemd` se actualiza junto con la UI (va dentro del paquete); en Windows se reinicia la tarea programada; en macOS el LaunchAgent.
4. UI: buscar ahora, versión nueva, «Actualizar todas» (primero la otra máquina, luego esta, sin cortar el teclado), actualizar solo (interruptor).

## Criterios de aceptación

- [ ] Prueba del comparador de versiones y del plan de actualización de las dos máquinas (orden y vuelta atrás si la otra no vuelve).
- [ ] El workflow de release se valida en una corrida de prueba con un tag `v0.3.0-rc.N` en `develop` (borrador) o, si no hay secreto, queda documentado como paso del usuario en `## Notas`.
- [ ] CI en verde.
