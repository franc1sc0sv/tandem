# T-122 — Release y actualización automática

## Contexto

DECISIONS D19; DESIGN §13; mockup `F-Ajustes` (pestaña Actualizaciones).

## Alcance

1. `tauri-plugin-updater` con llave de firma del updater (minisign) guardada como secreto de GitHub (`TAURI_SIGNING_PRIVATE_KEY`); la pública en la config. Documentar en `docs/dev/release.md` cómo generarla (`pnpm tauri signer generate`) — si el secreto no existe, el workflow falla con un mensaje claro.
2. Workflow `release.yml`: con un tag `v*`, construye `.dmg` y NSIS, firma los paquetes del updater, publica el release (borrador → publicado) y el `latest.json`.
3. El agente `tandemd` se actualiza junto con la UI (va dentro del paquete); en Windows se reinicia la tarea programada; en macOS el LaunchAgent.
4. UI: buscar ahora, versión nueva, «Actualizar todas» (primero la otra máquina, luego esta, sin cortar el teclado), actualizar solo (interruptor).

## Criterios de aceptación

- [x] Prueba del comparador de versiones y del plan de actualización de las dos máquinas (orden y vuelta atrás si la otra no vuelve).
- [x] El workflow de release se valida en una corrida de prueba con un tag `v0.3.0-rc.N` en `develop` (borrador) o, si no hay secreto, queda documentado como paso del usuario en `## Notas`.
- [x] CI en verde.

## Notas

- **Comparador y plan:** `apps/tandem-ui/src-tauri/src/update.rs` (portable). `Version` con el orden de SemVer (pruebas de propiedades: orden total, ida y vuelta texto ↔ versión, prerelease antes de su final). `plan` + `run` con un doble de las dos máquinas (`FakeFleet`, tiempo pausado de tokio): la otra primero y esta al final (propiedad), la versión vieja que vuelve no basta, **vuelta atrás** si la otra no vuelve en el plazo (esta no se instala), otra versión del protocolo cuenta como «volvió», rechazo y sesión perdida paran antes de tocar esta.
- **Agente:** `tandemd` anuncia su versión al conectarse (`ControlMsg::Update(Version)`), recuerda la de la otra y si habló otro protocolo, y pasa el pedido «instala X» a su UI (`UiCommand::UpdatePeer`, `GetUpdate`, `AgentToUi::Update`). Protocolo v18.
- **Alcance 3:** el paquete de cada sistema ya trae `tandemd`. En macOS, al reiniciarse la app nueva el LaunchAgent cambia de versión y relanza `tandemd` (T-070). En Windows el arranque es la clave `Run` de `HKCU` con `tandemw` (T-071), **no una tarea programada** como dice la tarea; los ganchos NSIS ya detienen y vuelven a arrancar el agente en una actualización (`$UpdateMode`). No hizo falta código nuevo para esto.
- **«Sin cortar el teclado»:** no se mueve la declaración del teclado (ver DECISIONS, T-122); se garantiza que nunca se reinician las dos a la vez y que esta espera a la otra.
- **Llave del updater — pendiente del usuario:** el secreto `TAURI_SIGNING_PRIVATE_KEY` no existe en el repo. Se generó un par para estas pruebas **fuera del repo** (`~/.config/tandem-release/updater.key`, sin clave; la pública ya está en `tauri.conf.json`). Para sacar releases: `gh secret set TAURI_SIGNING_PRIVATE_KEY < ~/.config/tandem-release/updater.key` (o generar otro par y cambiar la pública; ver `docs/dev/release.md#llave-del-updater`). Sin el secreto, un release falla en `preparar` con ese mensaje.
- **Validación del workflow:** sin el secreto, la corrida con tag `v0.3.0-rc.N` en `develop` queda como paso del usuario (además, la versión del repo es `0.1.0` y el tag tiene que coincidir). En este PR el workflow corrió entero en **modo prueba** (lo dispara el PR al tocar `release.yml`): dmg + `.app.tar.gz` firmado, NSIS firmado y probado, checksums y `latest.json`, con una llave desechable.
