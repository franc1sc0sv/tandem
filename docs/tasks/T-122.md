# T-122 — Release and automatic update

## Context

DECISIONS D19; DESIGN §13; mockup `F-Ajustes` (Updates tab).

## Scope

1. `tauri-plugin-updater` with the updater signing key (minisign) stored as a GitHub secret (`TAURI_SIGNING_PRIVATE_KEY`); the public one in the config. Document in `docs/dev/release.md` how to generate it (`pnpm tauri signer generate`) — if the secret does not exist, the workflow fails with a clear message.
2. `release.yml` workflow: with a `v*` tag, build `.dmg` and NSIS, sign the updater packages, publish the release (draft → published) and the `latest.json`.
3. The `tandemd` agent is updated together with the UI (it ships inside the package); on Windows the scheduled task is restarted; on macOS the LaunchAgent.
4. UI: check now, new version, "Update all" (the other machine first, then this one, without cutting the keyboard), update automatically (switch).

## Acceptance criteria

- [x] Test of the version comparator and of the update plan for the two machines (order and rollback if the other does not come back).
- [x] The release workflow is validated in a test run with a `v0.3.0-rc.N` tag on `develop` (draft) or, if there is no secret, it is documented as a user step in `## Notes`.
- [x] CI green.

## Notes

- **Comparator and plan:** `apps/tandem-ui/src-tauri/src/update.rs` (portable). `Version` with SemVer ordering (property tests: total order, text ↔ version round trip, prerelease before its final). `plan` + `run` with a double of the two machines (`FakeFleet`, paused tokio time): the other first and this one last (property), the old version coming back is not enough, **rollback** if the other does not come back in time (this one is not installed), another protocol version counts as "came back", rejection and lost session stop before touching this one.
- **Agent:** `tandemd` announces its version on connecting (`ControlMsg::Update(Version)`), remembers the other's and whether it spoke another protocol, and passes the "install X" request to its UI (`UiCommand::UpdatePeer`, `GetUpdate`, `AgentToUi::Update`). Protocol v22 (T-099, T-110, T-105 and T-101 took v18 to v21).
- **Scope 3:** each system's package already ships `tandemd`. On macOS, when the new app restarts the LaunchAgent changes version and relaunches `tandemd` (T-070). On Windows startup is the `HKCU` `Run` key with `tandemw` (T-071), **not a scheduled task** as the task says; the NSIS hooks already stop and restart the agent on an update (`$UpdateMode`). No new code was needed for this.
- **"Without cutting the keyboard":** the keyboard declaration is not moved (see DECISIONS, T-122); it is guaranteed that the two are never restarted at the same time and that this one waits for the other.
- **Updater key — pending from the user:** the `TAURI_SIGNING_PRIVATE_KEY` secret does not exist in the repo. A pair was generated for these tests **outside the repo** (`~/.config/tandem-release/updater.key`, no password; the public one is already in `tauri.conf.json`). To publish releases: `gh secret set TAURI_SIGNING_PRIVATE_KEY < ~/.config/tandem-release/updater.key` (or generate another pair and change the public one; see `docs/dev/release.md#llave-del-updater`). Without the secret, a release fails in `preparar` with that message.
- **Workflow validation:** without the secret, the run with a `v0.3.0-rc.N` tag on `develop` stays as a user step (also, the repo version is `0.1.0` and the tag has to match). In this PR the workflow ran in full in **test mode** (the PR triggers it by touching `release.yml`): dmg + signed `.app.tar.gz`, signed and tested NSIS, checksums and `latest.json`, with a disposable key.
