# T-020 — Input event model and key tables

## Scope

`tandem-input::event`: event types (key by HID usage, buttons, relative and absolute movement, v120 and pixel scroll, modifiers), and HID ↔ Mac keycode ↔ Windows scancode tables (crate `keycode`). Modifier remapping policy configurable per direction (docs/research/input-engine.md). Set of pressed keys with `release_all()`.

## Acceptance criteria

- [x] HID↔Mac↔Windows round-trip tests for all the keys of a Spanish ISO keyboard.
- [x] Tests of the default Cmd→Ctrl remapping, etc.
- [x] No platform dependencies in this module.

## Notes

- The `keycode` crate's reverse lookups (`KeyMap::from_key_mapping`) do not distinguish the HID page and depend on the order of a `HashSet` in its macro; that is why `event::keymap` builds its own indexes by walking `KeyMap::from_usb_code`, which is exact. Chromium's Win and Mac tables are bijective (there is a test).
- Outbound-only aliases (when injecting): IntlHash (the ISO key labelled c-cedilla on a Spanish keyboard) → Backslash on both systems; consumer-page volume (0x0C 0xE2/0xE9/0xEA) → the keyboard-page one (0x7F–0x81); and only toward the Mac, PrintScreen/ScrollLock/Pause → F13/F14/F15, which is what macOS does with a PC keyboard.
