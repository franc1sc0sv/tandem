# T-194 — `large_output_is_read_in_pages_without_losing_or_repeating_bytes` sometimes fails on macOS

## Context

In the macOS CI (PR #137) the test failed on `assert_eq!(o["done"], true)` exactly when `more` was false. The `output` API (`crates/tandem-cli/src/api.rs`) returns `more: false, done: false` when it has already delivered everything read but the agent has not yet seen the process exit: it is a valid state. The test assumed that the last page always arrives with the process already finished.

## Fix

The test keeps requesting pages until `done: true` and then demands `more: false`. The API does not change.

## Acceptance criteria

- [x] The test does not assume that `more: false` implies `done: true`.
- [x] `cargo test -p tandem-cli` green, 20 consecutive runs of the test locally.
