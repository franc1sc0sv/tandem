# T-194 — `una_salida_grande_se_lee_por_paginas_sin_perder_ni_repetir_bytes` falla a veces en macOS

## Contexto

En el CI de macOS (PR #137) la prueba falló en `assert_eq!(o["done"], true)` justo cuando `more` era falso. La API de `output` (`crates/tandem-cli/src/api.rs`) devuelve `more: false, done: false` cuando ya entregó todo lo leído pero el agente todavía no vio salir al proceso: es un estado válido. La prueba suponía que la última página siempre llega con el proceso ya terminado.

## Corrección

La prueba sigue pidiendo páginas hasta `done: true` y entonces exige `more: false`. La API no cambia.

## Criterios de aceptación

- [x] La prueba no supone que `more: false` implica `done: true`.
- [x] `cargo test -p tandem-cli` en verde, 20 corridas seguidas de la prueba en local.
- [x] Puerta de calidad y CI en verde.
