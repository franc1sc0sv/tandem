# T-007 — tandemd: agent skeleton

## Scope

`tandemd` binary: tokio runtime, logging with tracing (file + stdout), loading `tandem.toml` (`tandem_core::Config` config + network + local machine), persistence of `State` as JSON in the app's data directory, orderly shutdown.
Local IPC for the UI: Unix socket on macOS / named pipe on Windows, accessible only to the current user, speaking tandem-proto's UI↔agent messages.

## Acceptance criteria

- [x] `tandemd --check-config <file>` validates a config and exits with a code ≠ 0 if it is invalid.
- [x] Test: the state is saved and reloaded identically.
- [x] Integration test: an IPC client requests the state and receives it (on Linux with a Unix socket).

## Notes

- `tandem.toml` = `machine` + `[network]` (`port`, default 47770; optional `peers`) + the `[[monitors]]` of `tandem_core::Config`. Both `--check-config` and startup read it.
- Default paths: `dirs::data_dir()/Tandem` (state `state.json`, `logs/tandemd.log`, socket `tandemd.sock`) and `dirs::config_dir()/Tandem/tandem.toml`; `--config` and `--data-dir` change them. The log level comes from `TANDEM_LOG`.
- The saved state is adjusted to the config at startup (new monitors on the Mac, the ones no longer present are forgotten); a damaged `state.json` is set aside as `state.json.corrupt` and the initial state is used.
- IPC: the agent greets first, the UI answers with its `Hello` and then asks with `UiRequest`; state changes are pushed as `AgentToUi::State`. `SetMode`, `MoveMonitor` and `SetBuiltin` answer `Rejected("not implemented yet")` until the orchestrator (T-008).
- Current user only: on Unix, directory 0700, socket 0600 and a check of the client's uid (`peer_cred`); on Windows, pipe `\\.\pipe\tandemd-<SID>` with a protected DACL that admits only the process's SID and no remote clients. The case of the SYSTEM service with the UI in the user's session is left for T-027.
- A second `tandemd` on the same socket or pipe exits with an error; an old socket from a dead agent is replaced.
