# T-002 — tandem-proto: messages and framing

## Scope

Serde message types for: agent↔agent (control: Hello/version, Ping/Pong, execute a plan step + result, state; input: defined by T-026) and UI↔agent (query state, change mode, move monitor, built-in display preference, transaction progress events).
Reuse `tandem_core::{Step, Mode, State, BuiltinDisplay}`. `postcard` encoding with length framing (u32 LE) and protocol version in the Hello.

## Acceptance criteria

- [x] Round-trip tests for all messages.
- [x] A message with an incompatible version is rejected with a typed error.
- [x] Framing: decode streams split into arbitrary chunks (test with deterministic random partitions).

## Notes

- `postcard` is not self-describing and cannot read the serde tagged enums used by `tandem_core::Step` (`tag = "step"`) and `Mode` (`tag`/`content`): it fails with `WontImplement`. The messages keep the core types and are serialized with mirrors in `tandem-proto/src/wire.rs` (`#[serde(with = ...)]`), with exhaustive conversions so that a change in the core does not compile until they are updated. `tandem-core` was not touched.
- Version policy: we only talk with the same `PROTOCOL_VERSION`. `decode_hello` first reads the `version` field (which must remain the first one in `Hello`) and rejects with `ProtoError::IncompatibleVersion` before interpreting the rest.
- Frame cap `MAX_FRAME_LEN` = 1 MiB; a larger length gives `ProtoError::FrameTooLarge` without reserving memory.
- `proptest` was added to `[workspace.dependencies]`; the property tests use a fixed seed.
