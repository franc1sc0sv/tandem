# T-098 — Módulos y capacidades

## Contexto

DECISIONS D3, DESIGN §4.3. La UI muestra los módulos de cada máquina con estado y razón (mockups `V3-Maquina`, `F-MaquinaMac`).

## Alcance

1. Trait `Module` en `tandemd`: `id`, `nombre`, `estado() -> ModuleState { Active, Off, Unavailable { reason } }`, encender/apagar si aplica. Registro de módulos por sistema con `#[cfg]`: teclado y mouse, portapapeles, archivos, túneles, monitores, energía, pantallas protegidas (escritorio seguro de Windows, T-027).
2. `ControlMsg::Capabilities` ampliado: `MachineInfo`, módulos con estado, entornos (placeholder hasta T-105), monitores con canal (placeholder hasta T-110). Se manda al conectar y con cada cambio (debounce 250 ms).
3. IPC: `UiEvent::Machines { local, remote }` con todo lo anterior; `UiCommand::SetModule { machine, module, on }` (el agente remoto lo aplica por el plano de control).
4. Las razones de «no disponible» son concretas y accionables («Falta el permiso de Accesibilidad», «Sin canal DDC en esta máquina»).

## Criterios de aceptación

- [ ] Pruebas unitarias del registro por sistema (con dobles) y de la serialización del anuncio.
- [ ] Prueba de integración (`tandem-sim` o dos agentes por loopback): apagar un módulo remoto desde la IPC local cambia su estado en las dos UIs.
- [ ] Puerta de calidad y CI en verde.
