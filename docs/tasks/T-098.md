# T-098 — Modules and capabilities

## Context

DECISIONS D3, DESIGN §4.3. The UI shows each machine's modules with state and reason (mockups `V3-Machine`, `F-MachineMac`).

## Scope

1. `Module` trait in `tandemd`: `id`, `name`, `state() -> ModuleState { Active, Off, Unavailable { reason } }`, turn on/off if applicable. Module registry per system with `#[cfg]`: keyboard and mouse, clipboard, files, tunnels, monitors, power, protected screens (Windows secure desktop, T-027).
2. `ControlMsg::Capabilities` extended: `MachineInfo`, modules with state, environments (placeholder until T-105), monitors with channel (placeholder until T-110). It is sent on connecting and on each change (250 ms debounce).
3. IPC: `UiEvent::Machines { local, remote }` with all of the above; `UiCommand::SetModule { machine, module, on }` (the remote agent applies it over the control plane).
4. The "unavailable" reasons are concrete and actionable ("Accessibility permission is missing", "No DDC channel on this machine").

## Acceptance criteria

- [x] Unit tests of the per-system registry (with doubles) and of the announcement's serialization.
- [x] Integration test (`tandem-sim` or two agents over loopback): turning off a remote module from the local IPC changes its state in both UIs.
- [x] Quality gate and CI green (all 11 jobs at ba9b4a3, the last commit with code).

## Notes

- `crates/tandemd/src/modules.rs`: `Module` trait, `Registry::for_os` and the seven modules. Protected screens only exists on Windows. The design decisions (registry by `Os`, what can be turned off, `AgentToUi::Machines` notice, 250 ms window) are in DECISIONS, section "Decided by agents".
- Turning off "Keyboard and mouse" stops the whole input engine (capture, session and clipboard); turning off "Clipboard" stops it without cutting the input session. If the system clipboard does not open, the module stays "unavailable" with the error.
- What is turned off lives in memory; persisting and syncing it is left for the "modules on" section of the `Desk` (T-099).
- Files, tunnels, monitors and protected screens say "unavailable" until their tasks (T-103…, T-110, T-027); `environments` and `monitors` are empty until T-105 and T-110.
- Protocol v17.
- Tests: `modules.rs` (registry with doubles, reasons, switch properties), `agent/modules.rs` (local and remote, 250 ms window with paused clock), `capabilities.rs` (announcement serialization), `tests/modules.rs` (two agents over loopback: turning off one of B's modules from A's UI is seen in both UIs) and `tests/input.rs` (turning off clipboard and input really stops them).
