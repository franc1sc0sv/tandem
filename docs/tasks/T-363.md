# T-363 — An elevated window on the PC is explained, not logged 9,700 times

## Context

Real desk, 2026-11-26, Tandem 1.0.1. Keyboard and mouse on the Mac, cursor on the PC, Task Manager (elevated) in the foreground: from 15:29:40 every injected movement failed with `SetCursorPos failed: The handle is invalid. (0x80070006)`, 9,700 log lines in 13 minutes, and the user saw "Windows died". UIPI: the medium-integrity agent cannot move the cursor or inject while an elevated window has the foreground. The T-027 service would have handled it but was not installed; installing it by hand, its first start failed with SCM 7000 "Access is denied" (the antivirus scanning the new file) and a manual start a minute later worked. Even running, the service refused the agent (`NoAccess`): the helper pipe only admits administrators, and an agent under `%LOCALAPPDATA%` runs unelevated by design (A7). The fix on the desk was the per-machine install: Tandem under `C:\Program Files\Tandem` with `tandemd --install` from an administrator, which registers the elevated startup task; the agent then injects over elevated windows itself. At 19:44 UTC the agent restarted that way and no injection error followed.

## Scope

- `secure::uipi`: UIPI failures without a helper are grouped into episodes (one line when it starts naming the foreground process, a counter, one line when injection works again), published for the module. The foreground is asked again at most once a second.
- `RoutedSink::with_foreground`: the local `SendInput`/`SetCursorPos` failures go through the episode accounting; the first failure of an episode tries the helper at once (not at the next 2 s mark), without a second attempt in the same instant. An episode ends only on a real success.
- `secure::windows::WinForeground`: `GetForegroundWindow` → process name and token elevation; a process whose token cannot be opened counts as elevated. Wired into the Windows injector.
- "Protected screens" module: while an episode lasts it names the process before the usual reason.
- `--install-service`: the start is tried up to 5 times, 2 s apart, on access denied / request timeout / a wait that ran out.
- DESIGN (secure desktop), DECISIONS.

Not done here (follow-up): keeping the service in step when the per-user agent updates (today a new agent finds an older service, reports `Outdated` and injects locally), and a one-click "Install" in the UI.
