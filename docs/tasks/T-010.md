# T-010 — DDC/CI on Windows (dxva2) + tandem-ddc CLI

## Scope

`tandem-display::windows::ddc`: enumerate physical monitors (EnumDisplayMonitors + GetPhysicalMonitorsFromHMONITOR), model from EDID (WmiMonitorID or SetupAPI), read the capabilities string, read/write VCP. All under `cfg(windows)`.
`tandem-ddc` binary (in the crate): `list`, `caps <monitor>`, `get <monitor> <vcp>`, `set <monitor> <vcp> <value>`, `switch <monitor> hdmi|dp --return-after <s>` (always with automatic return; see docs/research/ddc-34-LC34G55T.md).

## Acceptance criteria

- [x] Compiles for `x86_64-pc-windows-gnu` and on windows CI.
- [x] Capabilities string parser with tests (use the real LC34G55T string from docs/research).
- [x] Verification on the real monitor is done by T-050, not this task.

## Notes

- Portable logic in `tandem-display::ddc` (trait `DdcBus`, capabilities parser, EDID, switch with return) and `tandem-display::cli`; it is tested on Linux with `ddc::fake::FakeDdc`. The real backend is `tandem-display::windows::ddc::WindowsDdc`.
- The model comes from the EDID in the registry (`HKLM\SYSTEM\CurrentControlSet\Enum\DISPLAY\...\Device Parameters\EDID`), found with the interface path from `EnumDisplayDevicesW`; neither WMI nor SetupAPI is needed.
- `switch` always returns: the return is sent even if the outbound switch fails, with 3 retries per code; Ctrl+C brings it forward and when the console is closed the handler waits for it to be sent. `--return-after` is mandatory (1–300 s). The return goes to the other input by default and cannot be the same as the outbound one (usage error, nothing written).
- Included profile for the 34" (`LC34G55T` in the EDID name): HDMI `0x06`, return to DP with `0x0F` and then `0x09` (until we isolate which one is enough, T-050). Other monitors use standard MCCS or `--code`/`--return-code`.
- `set` rejects `0x60` and `0xD6` because they do not carry an automatic return.
