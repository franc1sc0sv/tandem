# T-101 — Data over any path

## Context

DECISIONS A2; DESIGN §6. Today Wi-Fi never carries data; tunnels and files must work over Wi-Fi without adding latency to keyboard and mouse.

## Scope

1. Remove the "no data over Wi-Fi" policy from `tandem-link` (and its texts in the UI: "requires cable").
2. QUIC stream priorities: input (highest) > control > clipboard > data (lowest). Motion datagrams without pacing wait (coordinate with T-093).
3. Bandwidth cap for data on Wi-Fi (by default 50% of the last measured; configurable in the `Desk`), with a rate limiter per connection.
4. If the input's p99 latency exceeds its target for 2 s, data is paused until it drops (with hysteresis) and an event is logged.
5. API for the data modules: open a data stream with priority and receive pause/resume events.

## Acceptance criteria

- [x] Test with `tandem-sim`: transfer data at full speed over simulated Wi-Fi while there is input at 1000 events/s; the input latency stays within its simulated target and the data is paused/resumed when appropriate (`tandem-sim/tests/qos.rs::datos_a_tope_por_wifi_con_entrada_a_1000_eventos_por_segundo`; counter-test without cap: `sin_tope_los_datos_le_meten_latencia_a_la_entrada`).
- [x] Rate limiter test (properties: it never exceeds the cap in a 1 s window) (`tandem-link/src/qos/limiter.rs`: `nunca_supera_el_tope_en_una_ventana_de_1_s` and `quien_espera_lo_justo_no_lo_supera_y_lo_aprovecha`).
- [x] Quality gate and CI green (gate in WSL; CI in the PR).

## Notes

Done:

- `tandem-link`: without the "Wi-Fi does not carry data" rule (`Plane`, `PlaneError::RequiresCable`, `data_plane*` and `LinkEvent::data_plane` are gone). New `qos` module:
  - `StreamClass` (input 10 > control 0 > clipboard −10 > data −20, quinn priorities) and `ControlStream::set_class`.
  - `RateLimiter` (token bucket as integer nanobytes: burst + refill ≤ cap, so no 1 s window exceeds it).
  - `LatencyGuard`: p99 in a 1 s window; pauses after 2 s above the target (4 ms cable, 20 ms Wi-Fi, DESIGN §7.1); resumes after 1 s below 75% of the target or with no input.
  - `Qos` per path (`LinkQos`, in the agent: `Agent::link_qos()`), shared by the connection each agent opens and those it accepts (`Connection::with_qos`): path, the desk's `[data]`, measured bandwidth (`set_measured`, for T-102), `record_input_latency` (for T-093, on both machines), `gate()`/`watch_gate()`/`events()` (pause, resume, cap change; also logged).
  - Cap that adjusts by latency: it drops if the input's p99 approaches the target, rises slowly with margin, a pause leaves it at half. With a Wi-Fi that worsens and stays bad, the input stays within the target without cycling pauses (`tandem-sim/tests/qos.rs::con_un_wifi_que_no_vuelve_la_entrada_queda_dentro_del_objetivo`: p99 17 ms from 15 to 30 s, data at ~1.4 MB/s out of 2 MB/s).
  - Data API: `ControlStream::into_data(&qos)` → `DataStream` (data priority, waits for pause and cap; `write_all` and frame `send`). T-103 uses it with its tunnel channel.
- `tandem-core`: `DataPrefs` (`[data]`) inside the desk; it travels with `ControlMsg::Desk` and is written to `tandem.toml` (`config_edit::with_desk`). `[data]` enters T-099's `Desk` with its `DeskPatch::Data` patch and the change notice ("Data over Wi-Fi"). Protocol v21 (after T-098, T-099, T-110 and T-105).
- `tandemd`: each own channel opens/accepts with its priority (`peer::open_channel` and `serve_stream`); each connection (the one the link manager opens and the incoming ones) takes its path's `Qos` (`kind_of_remote` for incoming ones: IP of a fixed address or, failing that, Wi-Fi), and `network::follow_desk` carries each `[data]` change to all of them (test: `tests/network.rs::the_wifi_data_cap_reaches_the_connections_already_open`).
- `tandem-sim`: `SimWifi` (capacity, propagation and the access point's FIFO queue, with changeable capacity).

Pending outside this task:

- Datagrams without *pacing* wait belong to T-093 (transport adjustment with its test). quinn already puts datagrams before streams in each packet, and the cap prevents data from filling the congestion window.
- In the agent, the pause is activated when T-093 delivers the measured input latency (`conn.qos().record_input_latency`). The ping RTT is not used as a substitute (see DECISIONS).
- The "requires cable" text was removed by T-112 (#71) when replacing the UI, so scope item 1 is covered.
