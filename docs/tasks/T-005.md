# T-005 — Multi-link manager and plane policy

## Scope

`tandem-link::manager`: keeps candidate connections per link (USB4, Ethernet, Wi-Fi) according to configuration, health ping every 1 s, priority USB4 > Ethernet > Wi-Fi, immediate switch of the active link and a change event.
Plane policy (DESIGN §6): the data plane is only enabled over wired links; API `data_plane_available()` and explicit rejection if it is requested over Wi-Fi. No switch to force it.

## Acceptance criteria

- [x] Tests with simulated links (loopback sockets on different ports): preferred link goes down → switch < 1.5 s; preferred link comes back → it returns.
- [x] Test: requesting the data plane with only Wi-Fi active returns an error.
- [x] Link change events emitted in order.

## Notes

- Implemented in `crates/tandem-link/src/manager/`: `LinkKind` (order = priority USB4 > Ethernet > Wi-Fi), `Plane`/`PlaneError`/`check_plane`, `LinkTable` (pure state), `LinkManager` (one ping per link, a single task that applies the results and emits the events), trait `Prober` with `QuicProber` (`ControlMsg::Ping`/`Pong` pings over the control stream of one QUIC connection per link) and `answer_pings` for the accepting side.
- Timings (`HealthConfig::default()`): ping every 1 s, Pong within 250 ms at most, connection within 1 s. A single failed ping is enough to consider the link down and switch; worst-case detection 1.25 s. After a failure the session is discarded and the next tick connects again; the return to the preferred link happens with the first good ping of the new connection.
- Data plane: `data_plane_available()` is true if and only if the active link is wired; `data_plane()` returns `PlaneError::RequiresCable` with Wi-Fi active and `NoLink` with no links. The rule lives in `LinkKind::allows` and has no configuration.
- Events: `LinkEvent { seq, from, to, data_plane }` through an unbounded queue (none are lost or reordered); the snapshot (`Snapshot`, with each link's RTT) is updated before the event is emitted.
- Tests: unit and property tests of the table; the manager with a double and a paused clock (cable cut at different phases of the ping, always < 1.5 s); integration with real QUIC over loopback, with a UDP relay per link on its own port that simulates unplugging the cable (USB4 → Ethernet measured at ~1.25 s, return at ~0.75 s on WSL2).
- Pending for the integration in `tandemd` (out of scope): the control stream that `QuicProber` opens on each connection only carries pings, so the orchestrator's messages will need their own stream or to share this one; `tandemd`'s config (`network.peers`) does not yet say the type of each address (`LinkCandidate` already deserializes with `kind = "usb4" | "ethernet" | "wifi"`), and the addresses that arrive via mDNS (T-006) will need to update the running candidates.
