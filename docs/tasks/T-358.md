# T-358 — The mouse works and feels the same in every scene

## Context

Reported on 2026-11-24 with 1.0.0:

1. With the keyboard and mouse on the Mac and part of the desk on the PC, the cursor was invisible on the PC.
   The hub is on the Mac, so Windows has no mouse and does not draw the cursor; `SendInput` does not change that.
2. With the keyboard and mouse on the PC, going to the Mac worked for a while with a strange speed and then died.
   - Speed: with input swallowed, Windows capture sent Raw Input counts, without the pointer speed or
     acceleration the user has on the PC.
   - Dying: with every monitor showing the Mac (scene "only Mac") the PC has no screen and the geometry
     no crossing edge. Any moment without Mac screens (a scene change, macOS reconfiguring its displays)
     made the server `leave` to the PC: the cursor stayed on an invisible PC with no way back. The PC's
     log shows the Mac's latency reports stopping at 20:14:28 without the session ending.

## Scope

- `ServerSession`: never leaves to a machine with no visible screen; if every screen of the server shows
  the other machine (`Layout::shown_elsewhere`, set by the agent in `input::screens::layout`), the cursor
  goes there by itself at session start or when the scene changes.
- Windows capture: with input swallowed, `MotionRelative` is the hook's point minus where the cursor is
  (`HookFilter::origin`), and Raw Input does not count; on grabbing, the cursor moves to `anchor`, in the
  middle half of its monitor.
- Windows injection: `Injector::set_focus` (Enter/Leave and end of session) and `InputSink::force_cursor`
  (MouseKeys, restored afterwards, also through `RoutedSink`).
- DESIGN §7.

## Acceptance criteria

- [x] Unit tests: the focus does not come back to nothing; the cursor goes to the other machine only with
  `shown_elsewhere`; the hook's delta and the anchor; MouseKeys only while the focus is here and without a mouse.
- [x] Integration (`tandem-input/tests/session.rs`): the injector learns when the cursor arrives and leaves;
  with every monitor on the Mac the cursor goes there when the session starts.
- [x] `cargo clippy` for Linux and `x86_64-pc-windows-gnu`, `cargo test --workspace`.

## Pending hardware verification

- [ ] Hub on the Mac, cursor on the PC's monitor: the cursor is seen; on leaving, MouseKeys is back as it was
  (`mousekeys_draws_the_cursor_and_is_put_back`, `#[ignore = "hardware"]`).
- [ ] Hub on the PC, focus on the Mac: the mouse moves at the same speed as on the PC, with acceleration.
- [ ] Scene "only Mac" with the keyboard on the PC: the cursor appears on the Mac by itself and keeps working

## Notes
