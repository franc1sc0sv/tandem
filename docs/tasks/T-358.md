# T-358 — The mouse works and feels the same in every scene

## Context

Reported on 2026-11-24 with 1.0.0:

1. With the keyboard and mouse on the Mac and part of the desk on the PC, the cursor was invisible on the PC.
   The hub is on the Mac, so Windows has no mouse and does not draw the cursor; `SendInput` does not change that.
2. With the keyboard and mouse on the PC, going to the Mac worked for a while with a strange speed and then died.
   - Speed: with input swallowed, Windows capture sent Raw Input counts, without the pointer speed or
     acceleration the user has on the PC.
   - Dying: with every monitor showing the Mac (scene "only Mac") the PC has no screen and the geometry
     no crossing edge. Any moment without Mac screens (a scene change, macOS reconfiguring its displays)
     made the server `leave` to the PC: the cursor stayed on an invisible PC with no way back. The PC's
     log shows the Mac's latency reports stopping at 20:14:28 without the session ending.

3. Mac→PC the cursor lagged and "followed" the hand (reported after the first fixes). Measured per stage
   (`send_*` on the server, `recv_*`/`inject_*` on the client): the Mac handed each movement to QUIC in
   21 µs and the network delivered it in 0.24–0.48 ms, but the PC injected every datagram with `SendInput`
   from the network loop at 0.4–1.5 ms each. A fast Mac mouse (~1000 movements/s) built a queue:
   capture → datagram read p50 40 ms, p99 180–680 ms, and the input QoS paused the data for it.

## Scope

- `ServerSession`: never leaves to a machine with no visible screen; if every screen of the server shows
  the other machine (`Layout::shown_elsewhere`, set by the agent in `input::screens::layout`), the cursor
  goes there by itself at session start or when the scene changes.
- Windows capture: with input swallowed, `MotionRelative` is the hook's point minus where the cursor is
  (`HookFilter::origin`), and Raw Input does not count; on grabbing, the cursor moves to `anchor`, in the
  middle half of its monitor.
- Windows injection: `Injector::set_focus` (Enter/Leave and end of session) and `InputSink::force_cursor`
  (MouseKeys, restored afterwards, also through `RoutedSink`).
- Latency per stage in the 5 s reports: capture → handed to QUIC (server), capture → datagram read and
  enqueue time (client), queued → injected (`ThreadedInjector`).
- `ThreadedInjector`: injection on its own high-priority thread; the newest position replaces the one
  waiting (relative deltas add up), keys and buttons keep their order. The agent wraps its injector in it.
- Windows: plain movement with `SetCursorPos` (8 µs p50, 41 µs p99 measured on the PC, against 0.4–0.8 ms
  for `SendInput`); with a button held, and one every 500 ms, with `SendInput`; through the secure desktop
  helper, always as input.
- DESIGN §7.

## Results on the desk (2026-11-25)

| Mac → PC | p50 | p99 | max |
|---|---|---|---|
| Before (1.0.0) | 30–270 ms | 180–680 ms | 680 ms |
| Own injection thread | 0.8–2.8 ms (thread) | 5–8 ms | 17 ms |
| + `SetCursorPos` (capture → injection) | 0.46 ms | 0.58 ms | 0.63 ms |
| + `SetCursorPos` (queued → injected) | 36 µs | 0.82 ms | 8.3 ms (one `SendInput`) |

## Acceptance criteria

- [x] Unit tests: the focus does not come back to nothing; the cursor goes to the other machine only with
  `shown_elsewhere`; the hook's delta and the anchor; MouseKeys only while the focus is here and without a mouse.
- [x] Integration (`tandem-input/tests/session.rs`): the injector learns when the cursor arrives and leaves;
  with every monitor on the Mac the cursor goes there when the session starts.
- [x] Mailbox: only the newest position waits, keys and buttons keep order, a slow injection never builds a
  queue, dropping it injects what was waiting. Windows: plain moves with `SetCursorPos`, drags and the
  keepalive as input, without `SetCursorPos` as before; `RoutedSink` only moves the cursor without the helper.
- [x] Mac → PC on the real desk: capture → injection p99 ≤ 2 ms (0.58 ms measured).
- [x] `cargo clippy` for Linux and `x86_64-pc-windows-gnu`, `cargo test --workspace`.

## Notes

- With the focus on the Mac, the PC's cursor stays visible (frozen) in the middle half of its monitor if that
  monitor shows the PC; before it was frozen at the edge.
- The Mac→PC latency that looked like a link problem (QoS pausing tunnel data) was the injection queue: with
  it gone, the data pauses stopped with tunnels running.
- With `SetCursorPos`, apps that read Raw Input (some games) do not see plain movement; clicks and drags
  go as input.
