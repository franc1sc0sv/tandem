# T-346 — The Mac reads the monitor directly

## Context

Confirmed on real hardware on 2026-11-19: with the 34" on HDMI, the Mac's `monitor-ddc` (`IOAVService`) gets a DDC channel, the firmware answers the probe (`0xEA`), and the Mac computes the same monitor id as the PC. The election then makes the PC the owner (lower latency, or `A` on a tie, DECISIONS T-110), and the Mac only learns the monitor's state through the PC. The user wants the Mac to know the monitor's real state by itself whenever it can.

## Scope

1. A machine that has a channel but is not the owner reads the live state itself (read-only `Get 0x60` and `0xEE`, never the event cursor, which stays with the owner): the UI on that machine uses its own reading when it is fresher than the owner's report.
2. When the owner leaves (PC off, link lost), the other machine with a channel takes over at once, without waiting for the next scan, and the event cursor carries on from the last event the old owner reported.
3. The Mac can switch the 34" itself (Set `0x60` with the firmware verdict) while it has a channel and the PC is unreachable.
4. DESIGN §10 and DECISIONS (refines T-110) describe it.

## Acceptance criteria

- [ ] Tests: the non-owner with a channel reads live state and never reads events; owner loss hands over to it within one poll; switch from the Mac with the PC off.
- [ ] DESIGN §10 and DECISIONS (refining T-110) describe it.
- [ ] Quality gate and CI green.
