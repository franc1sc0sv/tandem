# T-103 — Túneles: protocolo y sesiones

## Contexto

DECISIONS D8, D9, A7; DESIGN §8. Base de T-104…T-108.

## Alcance

1. Crate nuevo `tandem-tunnel` (portable, sin código de plataforma). `Tunnel { id, title, project: Option<Project { name, root }>, origin: Machine, target: Machine, opened_by: Client { kind: Mcp|Cli, session }, state: Open|Closed, created }`.
2. Mensajes nuevos en `tandem-proto`: abrir y cerrar túnel, listar, y un canal de datos por túnel (stream de prioridad de datos, T-101). Versión del protocolo sube.
3. **Sobrevivir al enlace:** el estado vive en el agente destino; cada flujo de salida lleva un número de secuencia por byte; al reconectar (por el mismo u otro camino) el origen pide «desde el byte N» y no se pierde ni se duplica nada. Búfer circular de salida por proceso (por omisión 8 MiB) con aviso si se descartó algo.
4. IPC local para clientes (`tandem` CLI / `tandem mcp`): autenticación por el canal IPC del usuario (DESIGN §11).
5. Estado de túneles para la UI (`UiEvent::Tunnels`), agrupado por proyecto, solo lectura.

## Criterios de aceptación

- [ ] Escenarios de dos agentes: abrir túnel, cortar el camino a mitad de un flujo, reconectar por otro camino y verificar que la salida llega completa y en orden (prueba de propiedades sobre puntos de corte).
- [ ] Cerrar túnel desde el origen cierra sus recursos en el destino.
- [ ] Puerta de calidad y CI en verde.
