# T-198 — Run the Mac half of the hardware suite locally

## Context

The company's SOC2 policy disables ssh to the Mac. `scripts/hw/run.sh` drives the Mac over ssh, so on 2026-11-18 the Mac half was run by hand from a local session (`docs/reports/hw-2026-11-18-cable.md`). Doing that by hand is error-prone: zsh does not split `$H`, `pkill -f` missed a process started with a relative path, and the two halves had to be timed manually.

## Expected fix

- `scripts/hw/mac-side.sh` (bash, runs on the Mac): clone or update the source at a given commit, build, provision, start the agent with absolute paths, run the Mac checks in the same order and windows as `run.sh`, print the results, always clean up (trap), and remind the user to remove the privacy permissions.
- `scripts/hw/run.sh --mac-manual`: runs only the PC half with long windows and prints the exact one-line command to run on the Mac (commit, IPs, PC paths).
- Merge both result files into the usual report.

## Acceptance criteria

- [ ] `mac-side.sh` and `run.sh --mac-manual`, both with `--plan`.
- [ ] `run.sh --sim` still passes; a simulated run of the manual mode on Linux (both halves local).
- [ ] `docs/dev/hardware.md` explains the no-ssh flow.
