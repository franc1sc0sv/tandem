# T-231 — `docs/STATUS.md` does not match the backlog

## Context

Failure found by the acceptance agent, part C, round 3 (2026-11-19, `origin/develop` bbdc245). See `docs/reports/acceptance-2026-11-18-c3.md`.

## Failure

G11 / documents. `scripts/ci/status.sh` exits 1 on `develop`:

```
STATUS.md: the header must say: **138 done of 145** (`T-001`…`T-209`
```

`docs/STATUS.md` says "127 done of 141 (`T-001`…`T-208`)", lists T-201…T-208 as "todo / in progress" although all but T-205 are `done`, and its header says CI passes "except for known flaky tests (T-160, T-190)". The script only runs in `release.yml`, so nothing catches this between releases.

## Expected fix

- Update the counts, the open-task table and the CI sentence of `docs/STATUS.md` to the state of `develop` when the task is taken (rerun `scripts/ci/status.sh` right before the PR, since other PRs move the counts).
- Decide whether `status.sh` should also run in `ci.yml` (it would force every task PR to touch `STATUS.md` and conflict with parallel PRs); if not, document in the task notes why it is release-only.

## Acceptance criteria

- [x] `scripts/ci/status.sh` prints `status: no findings`.
- [x] The decision about running it in `ci.yml` is written in `## Notes`.
- [x] Quality gate and CI green.

## Notes
Updated 2026-11-19 against `develop` at 8504769 (after T-241): header counts, test counts (re-measured: 1608 Rust, 682 vitest), open-task table, CI sentence and hardware state (`reports/hw-2026-11-18-cable.md`, T-237…T-241). T-160 and T-195 are closed, but T-190 is still `blocked`, so the CI sentence now names it as the one unexplained flake instead of being removed.

Decision: `status.sh` stays release-only (`release.yml`, job `prepare`, as decided in T-192) and does not run in `ci.yml`. Running it per PR would force every task PR to edit `STATUS.md` (each PR changes the done count and the open table), so any two parallel PRs would conflict on the same lines and every merge would force a rebase of the others. Release-only still catches drift before it ships, and `scripts/ci/status.sh` can be run by hand at any time. The cost is that `develop` can drift between releases, as it did here; the acceptance agent's G11 check covers that by running the script on `develop`, and a fix like this one is the remedy.
