# T-081 — Calibration: fixes from the first test on real hardware

## Facts from the real test

2026-10-16, `tandem-ddc calibrate 1 --from hdmi --no-save` on the 32" (SAM7489), whose verified real profile is **HDMI 0x05 / DP 0x0F**. The result came out wrong: **HDMI 0x0F, DP 0x10**.

1. The question said "Is the HDMI machine visible?": the user saw Windows and confirmed.
2. Codes that do nothing were accepted: when testing DP the monitor was already on DP; 0x10 was sent, the monitor ignored it, stayed on the PC and it counted as a success.
3. An 8 s timeout with an automatic "no": too short (HDMI resync takes several seconds and the terminal has to be read); it discarded the correct code 0x05 without the user answering.
4. No final verification: it gave HDMI = 0x0F when 0x0F was the verified return code to DP.
5. The `0x60` reading after changing the input from the menu does not update (on DP it read 0x05): it is only a candidate, not evidence.

## Scope

Same fix in the engine (T-077), in the CLI and in the UI wizard (T-078/T-080):
- **(1) Multiple-choice question** by machine name according to the wiring: "What do you see on <monitor>? [m] Mac / [p] PC / [n] black or no signal" (and cancel); in the UI, with buttons. If the answer is the machine of the opposite input, the code is no good for the input being tested.
- **(2) Precondition:** before each candidate, the monitor is on the opposite input with an already verified code and the user confirmed that they see the opposite machine.
- **(3) Deadline:** 20 s by default (configurable). With no answer the same code is repeated once and then the user is asked whether to continue; it is never discarded silently.
- **(4) Verification:** candidates for one input that are the other's verified code are rejected, and it ends with a round trip (start → other → start) confirming each time which machine is seen.
- The `0x60` reading after a change from the menu is only a candidate.

## Acceptance criteria

- [x] Tests that reproduce the real session (simulated monitor that ignores what it does not know, reads the old code after the change from the menu, and simulated user who answers what they see, late): with the previous engine they give the wrong profile (HDMI 0x0F / DP 0x10, checked before the fix) and after it the correct 0x05 / 0x0F.
- [x] Same fix in the engine, in the CLI and in the UI wizard.
- [x] Clear texts in English.

## Notes

- **Engine** (`tandem-display::calibrate`): the `Confirmer` answers `Option<Answer>` (`Answer::Saw(Sight::Input(..) | Sight::Black)` or `Answer::Stop`; `None` = no answer). `ProbeKind` adds `Back { code }` (confirmed return), `Verify { code }` (final verification) and `Stalled { code }` ("continue?", with a 120 s deadline; with no answer, `CalibrationError::NoAnswer`). `CONFIRM_TIMEOUT` = 20 s. Walk: manual switch to the other input (its machine has to be seen) → candidates for the starting one until its machine is seen (if the other is seen, it continues; if black, the user is asked to go back from the menu) → candidates for the other, excluding the return (if the starting one is seen, return without asking; if black, return confirmed with `Back`) → `State::Verifying` with three `Verify` (start, other, start). New events: `Seen { sight }`, `NoAnswer { again }`, `Verified`. New errors: `NoAnswer`, `ReturnNotSeen`, `VerificationFailed` (in the last two the return is not sent blindly: the user is asked to go back by hand).
- **Simulated monitor:** `Reports::LastSet` (what the real 32" does: it reads the code of the last change over DDC; a change from the menu does not update it) and `samsung_32()` uses it; `SimState::answer_delay`. That is why from DisplayPort the 32"'s HDMI no longer comes out on the first attempt (it finds it after MCCS, the declared ones and the black of 0x06); from HDMI, as in the real test, each input comes out on the first attempt.
- **Reproduction:** `calibrate::tests::the_first_real_calibration_of_the_32_finds_its_verified_profile` and `cli::tests::the_first_real_calibration_now_finds_the_verified_profile` (`calibrate 0 --from hdmi --no-save` with the database, a user who takes 10 s and types the letter of what they see). Before the fix, the same session against T-077's engine (a user who only answers, with Enter, when they see the PC where their terminal is) gave `hdmi [0F] dp [10]`. Also: "the opposite machine is seen" rejects the code, black while looking for the return asks for the menu, with no answer it repeats and asks, nobody answers → stops, "stop" cancels with rollback, verification or return not seen fail without a profile. New property in the engine's proptests: every time a candidate is sent, the simulated monitor shows the opposite input.
- **CLI:** `console::LineConfirmer` with `Wiring` (the PC's input; the Mac on the other): `m`/`p`/`n`/`c`, Enter alone does not answer; instructions at the start (including "if this terminal is on the monitor you are calibrating, type the letter anyway"). `tandem-ddc calibrate` accepts `--pc hdmi|dp` and `--wait <s>` (5–300); without `--pc`, the wiring comes from the `[[monitors]]` in `tandem.toml` (`%APPDATA%\Tandem\tandem.toml`) that matches that monitor by `edid_model`, or from the default desk (PC on DisplayPort). `CalibrateEnv.confirmer` is now a factory that receives the wiring.
- **Protocol v8:** `ProbeAsk::{Back, Verify, Stalled}`, `CalibrationProbe.machine` (the machine that should be seen), `ProbeAnswer::{Seen, Machine(Machine), Black, Stop}`, `ProbeOutcome::{Answered(ProbeAnswer), NoAnswer, Failed}`, `UiCommand::AnswerProbe { id, answer }`, `CalibrationStep::{Verifying, Verified}`.
- **Agent** (`AgentConfirmer`): each probe is shown full screen on the machine that should be seen (as in T-078) and, at the same time, the PC's UI asks "What do you see?" (`ProbePlace::Question`) with "I see the Mac", "I see the PC", "Black or no signal" and "Stop"; whichever arrives first wins. "Continue?" only goes as a question. With no UI on either, a clear error.
- **UI:** `probe.ts` (`questionText` with `choices`, texts per probe kind, deadline "N s left"), buttons in the notice and in the "Add monitor" dialog, "Verifying: round trip…" in the wizard; demo updated. Screenshots: `docs/screenshots/T-081-what-you-see.png` (question in the wizard) and `docs/screenshots/T-081-probe.png` (full-screen probe).
- `docs/dev/ddc-profiles.md` explains how the calibration tests now and how to answer in the terminal.
