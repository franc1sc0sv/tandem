# T-074 — tandemd: assemble keyboard/mouse, clipboard and roles

## Scope

Connect in the real binary: the `tandem-input` session (server/client) with the platform capture and injection backends (T-022..T-025) behind their traits, geometry from the `State` (visible screens), `tandem-clipboard`, and `tandem-peripherals` (HubWatcher + RoleArbiter) which decides who is the server. Default modifier policy (Cmd↔Ctrl) from the config. Shortcut to lock the cursor on the current screen. On macOS, the permissions state (Accessibility / Input Monitoring) is reported to the UI.

## Acceptance criteria

- [x] Integration test with two agents on loopback and simulated input backends: the cursor crosses the edge and the events reach the other side; when the hub changes the roles swap; the clipboard syncs.
- [x] On real platforms, the code compiles in CI x3 and the backends are chosen by `cfg`.
- [x] Missing macOS permissions reach the UI as a notice.

## Notes

- What is assembled lives in `tandemd::input` and starts in `daemon::start` (`Backends::Platform` uses `InputSetup::platform`; `Backends::Custom { input, .. }` receives simulated backends or `None`). The backends sit behind `InputBackends` (`input/backends.rs`): `PlatformInput` chooses by `cfg` CGEventTap/CGEventPost on macOS, hooks/`SendInput` on Windows, `arboard` for the clipboard, IOKit/SetupAPI for the hub and `tandem-display`'s topology for the screens; on Linux it reports that there is no capture or injection. `input/fake.rs` has the doubles.
- Channels (protocol v5, on top of T-073's v4): over the active link's connection, input and clipboard open their own stream with `ControlMsg::Open(Channel)` as the first message; `peer::accept_streams` hands them to the engine (`PeerInbox`). The input stream is opened by the server; the clipboard's, by the Mac. The `tandem-input` drivers gained `run_with` to use an already-open stream.
- Roles: `RoleArbiter` with the local `HubWatcher` (`[input.hub]`) and the other agent's `ControlMsg::Hub`, which repeats every 2 s and on link change. With no link, the Mac with `pc_on = false` calls `set_peer_off()` (what T-066 asked for). Without `[input.hub]` the server is `input.server`.
- Geometry: each agent reads its screens (at startup, every 5 s and with each `UpdateInputGeometry`, which on the real platform is now `GeometrySteps` instead of "not implemented") and sends them with `ControlMsg::Screens`; the `Layout` is recalculated with the `State` and applied live to the server and the client.
- Cmd↔Ctrl: `[input.remap]` (by default `RemapPolicy::default()`), applied on the server when capturing (`CaptureSink`).
- Lock shortcut: `[input] lock_shortcut` (names from `KeyboardEvent.code`, by default `["ScrollLock"]`; F14 on the Mac works the same). When locked, the cursor does not cross in either direction (`ServerSession::with_lock_shortcut`, `Layout::step_within`). The shortcut's keys go through the same remapping as what is captured (`CaptureSink::remap_key`): `["ControlLeft", "KeyL"]` on the PC is satisfied even if Ctrl reaches the session as Cmd.
- Hot pairing: the active link that the input engine follows lives in the network (`Shared`), not in each `supervise`; each `follow()` feeds it and unpairing leaves it as `None`. A generation prevents an already-aborted `supervise` from restoring the link of a forgotten peer.
- UI: `UiCommand::GetInput`, `Reply::Input` and `AgentToUi::Input` with `InputStatus` (server, hub here, session, lock, missing permissions, problem). The window shows the "Server"/"Client" chip of each machine and, on its own, "missing permissions" or the engine's problem (`roleChip` in `scene.ts`); `?demo&perms=missing` and `?demo&hub=pc` in demo mode.
- Tests: `crates/tandemd/tests/input.rs` (two agents over QUIC on loopback with simulated backends: mode change, PC→Mac edge crossing, keys with Ctrl→Cmd, clipboard in both directions, moving the hub swaps the roles and the cursor crosses Mac→PC, missing permissions to the UI; the capture that fails is reported and retried, and Ctrl+L on the PC locks the cursor), `crates/tandemd/tests/pairing.rs` (hot pairing with the input engine running opens the session and unpairing closes it), plus unit tests in `tandem-input` (lock, `from_code_name`, `Injector` over the emulators), `tandem-display` (`placed_screens`), `tandem-proto` (v5 samples) and `tandemd` (config, channels, IPC, conversions with proptest).
- Known limitation: a monitor without `edid_model` (the 32" for now) is not found on the desktop and is left out of the geometry; the example configs say so.
