# T-159 — Powering on the other machine requires editing `tandem.toml` by hand

Found by the acceptance agent (part B), flows F10 and G10 ("everything editable is edited from the UI", D4).

## What fails

With two real agents, after pairing, powering off the other from the palette works (`power_off` step, "off" state), but **"Power on PC"** (button on the Desk, the tray and the palette) answers "machine B is off and the other cannot power it on": the agent can only wake the other if `tandem.toml` has `[power.wol]` with the MAC, and the UI has nowhere to put it nor does it learn it when pairing (`autoconfig.rs` leaves it as a comment: "add [power.wol] with the MAC"). The machine page says "Wake-on-LAN needs to be configured ([power.wol] with the other machine's MAC)", that is, it asks to edit a file. With `[power.wol]` set by hand, powering off and on work (`power_off` and `power_on` steps, `on` state on both).

Also: the rejection message does not say what is missing nor how to fix it, and the "Power on" button is shown just as enabled.

Another edit that cannot be done from the UI: the desk name ("My desk") is only displayed.

## Expected fix

- Each machine announces the MAC of its Ethernet card (capabilities) and whoever pairs it stores it in `[power.wol]` by itself (editable on the machine page); if no MAC is known, the button explains what is missing and leads to where it is completed.
- The desk name is edited from Settings and travels to the other machine (D4).
- Two-agent tests: after pairing, "Power on" works without editing files.

## Acceptance criteria

- [x] Powering on the other works after pairing without editing `tandem.toml`.
- [x] Without a known MAC, the message says what to do.
- [x] The desk name is edited from the UI and reaches the other machine.
- [x] Quality gate and CI green.
