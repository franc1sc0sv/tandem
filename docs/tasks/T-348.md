# T-348 — One-click updates

## Context

The user wants every new release to be one click: "Update" in the app, on both machines, with nothing else to do (2026-11-19). The updater exists (T-122, `docs/dev/release.md`), but on macOS the app is signed ad hoc: macOS ties Accessibility and Input Monitoring to the exact signature, so **every update asks for both permissions again** (`docs/dev/install-macos.md`, "every new version of the app asks for the permissions again"), and the agent cannot capture or inject until the user grants them by hand. Gatekeeper may also quarantine the new bundle.

## Scope

1. Sign the macOS app and `tandemd` with a **stable self-signed code-signing identity** instead of ad hoc: a certificate generated once, kept as a repo secret (like the updater key), imported into a temporary keychain in the release job. With a stable identity the designated requirement stays the same across versions (identifier + certificate leaf), so TCC keeps the grants. No Apple Developer account. Document how to generate and rotate it in `docs/dev/release.md`.
2. Check that an update through `tauri-plugin-updater` does not leave the new bundle quarantined, and that the app restarts the LaunchAgent with the new `tandemd` (already in `launch_agent.rs`).
3. Windows: the update runs the NSIS installer in passive mode with no UAC prompt for the per-user install; when Tandem is under Program Files (T-027 service), say in the app that the update asks for administrator once, and refresh the service.
4. The app shows "Update available: vX.Y.Z" with one button that runs "Update all" (the other machine first, then this one), and the result.
5. A release checklist in `docs/dev/release.md`: bump, tag from `develop`, CI, publish, and the hardware check below.

## Acceptance criteria

- [x] The release job signs with the stable identity when its secret exists and fails with a clear reason when it is missing (test mode keeps a disposable identity).
- [x] `codesign -d -r-` of two builds of different versions gives the same designated requirement (CI check on macOS).
- [x] UI tests (vitest) for the update notice and the one-button flow.
- [x] DESIGN §13 says macOS builds are signed with a stable self-signed identity; DECISIONS has the T-348 line.
- [x] Quality gate and CI green.

## Pending hardware verification

- [ ] From v0.3.x to the next release on the real desk: one click on "Update" in either app updates both machines, keyboard and mouse keep working throughout, and the Mac keeps Accessibility, Input Monitoring and Local Network with no prompt. The update from the last ad-hoc release to the first self-signed one asks once (its grants stored a `cdhash` requirement); the no-prompt check applies from the first self-signed release to the next.
- [ ] After that update, `xattr -l /Applications/Tandem.app` shows no `com.apple.quarantine`, the app opens without a Gatekeeper dialog, and `launchctl print gui/$(id -u)/com.franc1sc0sv.tandem.tandemd` shows the new `tandemd` running (`TANDEM_APP_VERSION` = the new version).
- [ ] `codesign -d -r- /Applications/Tandem.app/Contents/MacOS/tandemd` on the real Mac shows `identifier tandemd and certificate leaf = H"<SHA-1>"` with the SHA-1 printed by `make-macos-identity.sh`, and the System Settings entries for `tandemd` do not duplicate after the update.
- [ ] Windows per-user install: the passive NSIS update shows no UAC prompt and `tandemd`/`tandemw` come back by themselves.
- [ ] Windows with Tandem under Program Files and the T-027 service: the notice says the update asks for administrator once, there is exactly one UAC prompt, and afterwards the service in `%ProgramFiles%\Tandem Service` runs the new `tandemd` version.
- [ ] After the restart, the main window shows "Updated to vX.Y.Z" once, with the other machine's version.

## Notes

- The one-time secret setup is the user's (agents do not create secrets): `scripts/release/make-macos-identity.sh`, then the two `gh secret set` commands it prints (`MACOS_SIGNING_CERTIFICATE`, `MACOS_SIGNING_CERTIFICATE_PASSWORD`). Until then a real release fails in `prepare` with that reason; PR CI and test mode use a disposable identity.
- The DR form, the TN2206/TN3127/TN3179 references and the caveats (Gatekeeper's first install, the first signed release, Local Network and the Mach-O UUID, expiry, rotation) are in `docs/dev/release.md#macos-signing-identity`.
- `tauri-plugin-updater` 2.14 on macOS downloads in the process and unpacks the `.tar.gz` with the `tar` crate, so nothing is quarantined unless the package carries the attribute; the release checks the package (`dr-check.sh package`).
- Windows: the elevated `tandemd --install` run by the installer's post-install hook already refreshes the T-027 service; the app only had to say beforehand that the update asks for administrator (`UpdateView.admin`, from `admin_service::update_asks_admin`).
