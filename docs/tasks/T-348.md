# T-348 — One-click updates

## Context

The user wants every new release to be one click: "Update" in the app, on both machines, with nothing else to do (2026-11-19). The updater exists (T-122, `docs/dev/release.md`), but on macOS the app is signed ad hoc: macOS ties Accessibility and Input Monitoring to the exact signature, so **every update asks for both permissions again** (`docs/dev/install-macos.md`, "every new version of the app asks for the permissions again"), and the agent cannot capture or inject until the user grants them by hand. Gatekeeper may also quarantine the new bundle.

## Scope

1. Sign the macOS app and `tandemd` with a **stable self-signed code-signing identity** instead of ad hoc: a certificate generated once, kept as a repo secret (like the updater key), imported into a temporary keychain in the release job. With a stable identity the designated requirement stays the same across versions (identifier + certificate leaf), so TCC keeps the grants. No Apple Developer account. Document how to generate and rotate it in `docs/dev/release.md`.
2. Check that an update through `tauri-plugin-updater` does not leave the new bundle quarantined, and that the app restarts the LaunchAgent with the new `tandemd` (already in `launch_agent.rs`).
3. Windows: the update runs the NSIS installer in passive mode with no UAC prompt for the per-user install; when Tandem is under Program Files (T-027 service), say in the app that the update asks for administrator once, and refresh the service.
4. The app shows "Update available: vX.Y.Z" with one button that runs "Update all" (the other machine first, then this one), and the result.
5. A release checklist in `docs/dev/release.md`: bump, tag from `develop`, CI, publish, and the hardware check below.

## Acceptance criteria

- [ ] The release job signs with the stable identity when its secret exists and fails with a clear reason when it is missing (test mode keeps a disposable identity).
- [ ] `codesign -d -r-` of two builds of different versions gives the same designated requirement (CI check on macOS).
- [ ] UI tests (vitest) for the update notice and the one-button flow.
- [ ] DESIGN §13 says macOS builds are signed with a stable self-signed identity; DECISIONS has the T-348 line.
- [ ] Quality gate and CI green.

## Pending hardware verification

- [ ] From v0.3.x to the next release on the real desk: one click on "Update" in either app updates both machines, keyboard and mouse keep working throughout, and the Mac keeps Accessibility, Input Monitoring and Local Network with no prompt.
