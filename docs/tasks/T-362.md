# T-362 — The mouse is never a phantom on the Mac

## Context

Real desk, 2026-11-26, Tandem 1.0.1. Keyboard and mouse on the PC (A), scene "Only FJ-MAC": both monitors
show the Mac (B). The keyboard typed on the Mac but the mouse was a phantom (no visible cursor). Moving the
USB to the Mac fixed it. In the logs:

- 14:00–14:01: the role went A↔B eight times; each time B became sender it logged `no screen of this machine
  is visible: the cursor goes to the other one` followed by `capture: a password field is active (Secure
  Event Input); the screen is not crossed`.
- 14:59:19: macOS re-enabled the 34" (a display configuration change) during the session.
- 15:00:24: the USB moved to the Mac; `no screen of this machine is visible` again, although the monitors
  showed the Mac.
- 15:43:25: the same on the PC: the USB went back to the PC in scene "Work" (the 34" showing the PC) and the
  PC sent its cursor to the Mac.

## Root causes (proved with tests)

1. **Stale geometry on a new server session.** `ServerDriver::idle` does not read the geometry; only `serve`
   does, and only after `session.start()`. `start()` runs `settle` with the layout the session had when it
   stopped serving (scene "only A": every Mac screen elsewhere), so it entered the other machine, grabbed (hid
   and froze the cursor) and only then received the real layout. Test:
   `a_server_starting_after_a_scene_change_uses_the_current_geometry`.
2. **A refused grab left the session "remote".** `apply_local` only logged the Secure Event Input refusal:
   the session believed the focus was on the other machine, sent `Enter`, and the local cursor and keyboard
   kept working at the same time. Tests: `a_refused_grab_returns_the_focus_to_this_machine`,
   `ServerSession::grab_refused` unit tests.
3. **The injector did not follow display changes.** `Injector::refresh` ran only when the geometry
   (`sh.visible`) changed; with declared screens it does not change when macOS reconfigures its displays, so
   the Mac injector kept clamping to the old screens. Test: `the_client_rereads_the_displays_when_the_system_changes_them`.

Discarded: the grab's hide counter and freeze are balanced on every path, including a Secure Event Input
refusal followed by a release (`a_refused_grab_then_a_release_leaves_the_cursor_visible_and_free`);
`link_lost` already releases the grab. A server never settles without an input session (`start()` runs after
the stream is open).

## Scope

- `ServerDriver` applies the pending geometry before `start()`.
- `ServerSession::grab_refused` + `apply` loop: a refused `Grab(true)` returns to local and sends `Leave`.
- `ClientDriver::with_display_changes`, wired by the agent to the screens the system reports.
- Safety net: a focus that went to the other machine because this one had no visible screen (a settle, not a
  crossing) comes back as soon as a screen of this machine is visible again, so a settle made on a view that
  did not last never strands the cursor. A cursor that crossed by an edge is not moved. Tests:
  `a_settled_cursor_comes_back_when_a_own_screen_is_visible_again`, `a_crossed_cursor_stays_when_the_layout_changes`.
- DESIGN §7, DECISIONS. Not done: preventing the Mac from becoming sender under Secure Event Input (the
  crossing is refused and it stays local; see DECISIONS).

## Notes

The 15:00:24 `no screen of this machine is visible` is explained by cause 1 (the layout of 14:01 was the last
one the idle driver had seen); the Mac's own monitor links were not found wrong in the code. If it happens
again with a fresh layout, capture the Mac's `monitors` state at that moment.
