# T-241 — macOS echo guard: tag what `CgSink` posts

## Context

The macOS capture (`crates/tandem-input/src/macos/capture`, an active CGEventTap) skips events whose `kCGEventSourceUserData` is `INJECTED_MARKER`, but the injector (`CgSink`, `CGEventPost`) never wrote that tag. When the Mac is the receiving side, everything Tandem injects reached its own tap as local input: injected motion pushed against an edge could cross back, keys could echo, and injected input could be mistaken for local activity and make ownership flap. Found while investigating T-239.

The Windows side already has the equivalent guard: the hooks drop `LLMHF_INJECTED`/`LLKHF_INJECTED` and Raw Input with `hDevice == 0`, and the injector tags `dwExtraInfo` (T-024, T-025).

## Fix

- `INJECTED_MARKER` moves to `tandem_input::macos` (still re-exported from `macos::capture`), shared by both halves.
- `MacSink::post` takes the source user data. `MacEmulator` always passes `INJECTED_MARKER`, and `CgSink` writes it into `kCGEventSourceUserData` at its single exit (`post_cg`), so every event is tagged, including media keys built through `NSEvent`.
- The tap's decision is portable: `Translator::tap` lets a tagged event through (not forwarded, not swallowed, translator state untouched) and translates everything else; tap notices (`TapDisabled*`) are always handled. `sys.rs` only reads the field and calls it.
- `RecordingSink` records the user data of each event (`take_tagged`).

## Criteria

- [x] Failing tests first: with the emulator posting user data 0 (the old behaviour), `every_injected_event_carries_the_marker`, `injected_events_are_not_captured_again`, `injected_motion_does_not_reach_the_edge_logic` and `nothing_injected_echoes` fail; with the tag they pass.
- [x] Loopback on Linux (`crates/tandem-input/src/macos/tests.rs`): what the emulator posts, fed to a tap on the same Mac, is never forwarded nor swallowed, grabbed or not (property test over random event sequences).
- [x] Real input is still captured: the same events without the tag, or with another app's tag, are forwarded.
- [x] An injected press does not count as a local press (its release is not let through while grabbed).
- [x] The Windows guard is unchanged and equivalent (`LLMHF_INJECTED`, Raw Input without a device).
- [x] Quality gate passes; macOS CI compiles and tests the `cfg(target_os = "macos")` code.

## Pending hardware verification

- [ ] With the Mac receiving input from the PC, run `tandem-capture` (or the agent with debug logs) on the Mac and check that nothing injected is reported as captured, while the trackpad and keyboard still are.
- [ ] Push the cursor against the Mac's edge from the PC: it does not bounce back on its own, and ownership does not flap.
- [ ] Media keys injected on the Mac (play/pause, volume) are not reported by the tap.
- [ ] `input-cross` from the Mac still crosses (it must push through the agent, see Notes).

## Notes

- `tandem-hw`'s `input-cross` on macOS pushes with `CgSink` (system injection) and relies on the tap seeing that motion. With this fix it no longer does, by design, like Windows. T-239 (PR #167) adds `UiCommand::SyntheticMotion` and drives Windows through the agent; once it is on `develop`, macOS has to use that path too.
